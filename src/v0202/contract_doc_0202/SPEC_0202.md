## 5. 통신 및 API 사양

- **REST**: `/api/v001/*`
  - 인증: `X-API-Key` 헤더 (비어있으면 개방, **A-3 null 방어**)
  - 주요 경로: `/state`, `/control/*`, `/motion/*`, `/system`, `/wifi/*`, `/reload`, `/config/*`, `/ai/gemini`
  - 주요 신규: `/control/ack` (이벤트 래치 해제), `/control/mode` (모드 전환), `/wifi/state` (Wi-Fi 상태 조회), `/fwUpdate` (OTA)
- **WebSocket**: `/ws/{log|state|chart|metrics|summary}` (`?apiKey=...`)
- **OTA**: `/api/v001/fwUpdate` (multipart, `Update.h` 스트리밍)
- **파일 업로드**: `/api/v001/fileUpload` (최대 2MB, **N-4 safeAbort**)
- **정적 웹 호스팅**:
  - `Accept-Encoding` 검사 후 gzip/raw 분기 (RFC 7231)
  - `^/html_v0202/.+` regex 라우트로 `.gz` 우선 서빙
  - 단일 정적 경로: `/html_v0202` (레거시 URL 호환 기능 제거)
  - `P010_bundle_0202.js` 단일 번들, `W10_guessMime` MIME 자동 판별
  - Root fallback 시 메인 HTML(`index.html`) 부재 → 404 진단 메시지
  - **D-2/D-3**: `.gz` 경로 사전 계산 + regex 시 스택 버퍼(128B) → 요청당 힙 0회

### 5.1 API 응답 필드 (Batch N-1, F-2, F-3)

- `/api/v001/version`: `fw="FW_Ver_2.0.0"`, `control="CT10_Ctl_0202"` 등 (B-1)

  - `{ "security": { "geminiApiKey": "new" } }` / `{ "clearGeminiApiKey": true }` 동일 정책

  - `gzip;q=0` → raw 파일 + `Vary: Accept-Encoding`

### 5.2 설정 재적용(Reload) 정책 (I-2, F-05)

**핵심 원칙**: `POST /api/v001/reload`는 **디스크 저장 상태로 메모리 전면 재로드**. 디스크에 저장되지 않은 in-flight patch는 **소실**.

**동작 흐름**:

```text
[T-async]
  POST /api/v001/reload → requestReload() atomic CAS
  → 202 Accepted 즉시 반환 (< 1ms)

[T-loop]
  consumePendingReload() 확인 (≤ 10ms)
  → true → reloadAll():
      1. C10::loadAll(디스크 → v_new_root)
      2. s_rootSwapMux 하 원자 스왑
      3. CT10 상태 리셋 (_pendingMotionSimApply=false)
      4. queuePendingFree(v_old) 3초 grace
      5. applySystemRuntimeFromConfig()
```

**클라이언트 필수 원칙**:
1. `POST /motion`, `/system`, `/wifi/config`는 메모리 patch만.
2. reload 이전에 반드시 `POST /config/save` 호출.
3. reload 완료 폴링: `control.pendingReload` true→false, 성공 여부는 `control.lastReloadOk`.
4. 이미 pending 상태 시 재요청 → **409 Conflict**.

**금지 패턴**: `POST /motion` → (save 없이) `POST /reload` → 패치 유실.


### 5.3 시간 필드 단위 규격 (v2.3 신규)

모든 API 응답의 시간 필드는 다음 5가지 단위 중 하나로 명확히 구분된다. 프론트엔드는 필드별 단위를 반드시 준수해야 한다.

#### 5.3.1 필드 유형 분류

| 필드 유형 | 단위 | 기준점 | 예시 필드 | 프론트엔드 사용 규칙 |
|---|---|---|---|---|
| **epochms** | ms | 1970-01-01 UTC | `sim.chart[].t` | `new Date(t)` 직접 사용. SNTP sync 전엔 차트 버퍼 push 스킵 → 항상 유효 |
| **uptimeMs** | ms | **기기 부팅 시점 0** | `control.lastDecisionMs`, `control.lastStateChangeMs`, `control.event.holdUntilMs`, `control.autoOffRt.timerStartMs`, `control.schedule.segment.scheduleRt.phaseStartMs`, `control.schedule.segment.profileRt.phaseStartMs`, `time.lastSyncMs`, `time.lastRequestMs`, `logs[].ts`, WS 메시지 `ts`, `metrics.holdUntilMs`, `control.system.uptimeMs` | **절대 시각 표시 금지**. 상대 시간(경과/남은) 계산만 허용 |
| **durationMs** | ms | - | `time.syncIntervalMs`, `control.event.holdRemainMs`, `metrics.holdRemainMs` | 그대로 표시 (지속시간) |
| **durationSec** | 초 | - | `control.override.remainSec`, `metrics.overrideRemain` | `* 1000` 후 사용 |
| **시각 분해** | 정수 | 로컬 TZ | `control.time.hour`, `control.time.min`, `control.time.wday` | 헤더 시계 표시 (wday: 0=Sun) |

#### 5.3.2 절대 시각 변환 규칙 (v0202 필드 활용)

`sim.chart[].t`를 제외한 모든 `*Ms` 필드는 부팅 후 경과 시간(millis)이므로, 절대 시각으로 변환하려면 v0202 신규 필드를 활용한다.

```text
serverBootEpochMs = control.system.epochNowMs - control.system.uptimeMs
fieldEpochMs      = serverBootEpochMs + fieldMs
```

- `fieldMs`: uptimeMs 유형 필드 값
- `control.system.uptimeMs`: `millis()` — 부팅 후 경과
- `control.system.epochNowMs`: SNTP sync 후 `time(nullptr)*1000`, 미동기 시 `0`

#### 5.3.3 SNTP 미동기 정책

- `control.system.epochNowMs == 0` (SNTP 미동기) → **절대 시각 표시 금지**, 상대 시간만 사용
- `sim.chart[].t`는 이미 epochms이므로 위 변환 불필요 (직접 사용)
- `control.time.{hour,min,wday}`는 `localtime_r` 실패 시 `-1` 반환 → 프론트엔드는 "시간 미동기" 표시

#### 5.3.4 금지 패턴

| 금지 패턴 | 문제 | 대안 |
|---|---|---|
| `new Date(control.lastDecisionMs)` | millis를 epochms로 오해 → 1970년 표시 | 상대 시간만 사용 또는 `uptimeMs` 변환 |
| `Date.now() - control.event.holdUntilMs` | 클라이언트 epochms와 서버 millis 기준점 혼합 | `control.event.holdRemainMs` (백엔드 계산값) 그대로 사용 |
| `Date.now() - logs[].ts` | millis를 epochms로 오해 | WS 수신 시각과 `logs[].ts`의 차이만 상대 계산 |
| `new Date(time.syncIntervalMs)` | durationMs를 절대 시각으로 오해 | 그대로 표시 (지속시간) |

#### 5.4.2 소스 디렉토리 구조

```text
src/v0202/
├── data_v0202_src/html_v0202/       [개발 원본]
│   ├── index.html                   (SPA Shell)
│   ├── _*.css (10파일)              (CSS 소스)
│   └── *.js (31파일)                (JS 소스, 000~999 넘버링)

    │   ├── P000_common_0202.css     (concat raw + .gz)
    │   └── P010_bundle_0202.js      (concat raw + .gz)
    └── json/*.json                  (10개)
```

> **에셋 저장 정책**: `.gz` 압축 파일은 실제 ESP32 LittleFS 플래시 이미지 대상인 배포 스테이징(`data_v0202/`)에만 생성됩니다. 개발 소스 폴더(`data_v0202_src/`)에는 개발 원본과 로컬 Live Server 검증용 raw 번들(`P010_bundle_0202.js`, `P000_common_0202.css`)만 유지됩니다.

**JS 넘버링 (Layer별)**:

| 범위 | Layer | 파일 수 | 역할 |
|:---:|:---:|:---:|---|
| `000~029` | L0 (기반) | 3 | const / config / i18n |
| `030~099` | L1 (유틸) | 6 | level / time / dom / log / tpl / toast |
| `100~199` | L2 (서비스) | 4 | api / ws / store / router |
| `200~299` | L3 (UI) | 6 | badge / toggle / gauge / slider / chart / form |
| `300~399` | L4 (페이지) | 11 | dashboard / chart / schedule / profiles / settings / diagnostics / firmware / network / logs / ai / info |
| `999` | L5 (부트) | 1 | app |
| **합계** | - | **31** | - |

> **정렬 규칙**: `pio_gzip_0202.py`는 `glob("*.js")` 후 **파일명 정렬**로 concat. 넘버링이 로드 순서를 자동 보장.

#### 5.4.3 정적 라우팅 규약 (W10)

`W10_Web_Static_0202.cpp::W10_registerGzipServe()`가 서빙하는 경로:

| 경로 패턴 | 대상 | Gzip |
|---|---|:---:|
| `^/html_v0202/.+` | 정적 자산 | ✅ (Accept-Encoding 검사 후 `.gz` 우선) |
| `/json/*` (W10 routeStaticAssets 경유) | 설정 JSON | ❌ (무압축) |

**W10 정적 서빙 흐름**:
1. `Accept-Encoding` 헤더에 `gzip` 포함 여부 검사
2. `gzip` 지원 시: `LittleFS.exists(url + ".gz")` → `.gz` 파일 응답 + `Content-Encoding: gzip`
3. `gzip` 미지원 또는 `.gz` 없음: raw 파일 응답
4. 둘 다 없음: `404 not found`

#### 5.4.5 시간 필드 규격 (`§5.3` 연계)

프론트엔드는 `§5.3 시간 필드 규격`을 엄수한다. `sim.chart[].t`만 epochms이며, 나머지 `*Ms`는 `uptimeMs`(부팅 후 경과).

**v0202 신규 필드 (프론트엔드 절대시각 변환용)**:
- `control.system.uptimeMs`: `millis()` — 부팅 후 경과
- `control.system.epochNowMs`: SNTP sync 후 `time(nullptr)*1000`, 미동기 시 `0`

**변환 규칙**:
```text
serverBootEpochMs = control.system.epochNowMs - control.system.uptimeMs
fieldEpochMs      = serverBootEpochMs + fieldMs
```

## 6. 코딩 및 품질 컨벤션

- **JSON**: ArduinoJson v7 (`JsonDocument` 단일, `containsKey`/`createNested*` 금지)
- **문자열**: `memset` + `strlcpy` / `A40_Com_Utils_0202` 안전 복사
- **네이밍**:
  - 상수 `G_`, 전역변수 `g_`, 클래스 `CL_`, 구조체 `ST_..._t`, Enum `EN_`
  - 지역변수 `v_`, 인자 `p_`, 정적멤버 `s_`, private `_`
- **로깅**: `CL_D10_Logger::log(EN_L10_LOG_*, "[모듈] ...")`
- **매크로 정책 (E-2)**: 다중 .cpp 참조 매크로는 `*_Internal_0202.h`로 승격
  - 예: `G_C10_SCH_ID_START` → `C10_Config_Sch_Internal_0202.h`
- **Include 원칙 (E-2)**: 각 분할 .cpp는 참조 심볼의 헤더를 **직접 include**
  - 예: `C10_Config_Sch_JSON_0202.cpp`가 `A22_Com_Lookup_0202.h` 직접 include
- **A40 자립성**: `ST_A20_AutoOff_t`/`ST_A20_Motion_t` 참조 → `A20_Const_Sch_0202.h` 자체 include
- **JS nullish 폴백 (**NEW-C1**)**: 폼 필드 렌더 시 `||` 금지, `nz(v, fallback)` 사용
  - 이유: `0`, `''`, `false`가 유효값 (pin=0, brightness=0, holdSec=0)
  - `nz` = `(v === null || v === undefined) ? fallback : v`
- **JS bool 판정 (**NEW-U4**)**: `asBool(v)` 명시 사용
  - 이유: 문자열 `"false"`는 `Boolean("false")===true`
  - `asBool` = `v === true || v === 1 || v === '1' || v === 'true'`
- **HTML 이스케이프 (**B-3/NEW-C2**)**: 사용자 제어 문자열은 반드시 `SNW.DomUtil.escape()`
  - 대상: `meta.deviceName`, `security.apiKey`, `wifi.ssid`, `wifi.hostname`, `hw.tempHum.type`
- **NVS 쓰기 (**B-1/B-7**)**: `nvs_set_*` × N + `nvs_commit` × 1 (개별 `Preferences::put*` 금지)
  - 반환값 `ESP_OK` 검사, 실패 시 dirty 유지 재시도 (float은 `nvs_set_blob` 4B 호환)
- **root 접근 (**B-2/B-9**)**: async_tcp 컨텍스트에서 `g_A20_config_root` 직접 참조 금지
  - 반드시 `getRootSnapshot(v_snap)` 경유 (화이트리스트 예외 없음)
- **부팅 복구 (**B-11**)**: config root null 시 in-memory defaults + 부팅 계속
  - 파일 쓰기 금지 (손상 파일 보존 → 사용자 복구)
- **OTA 세션 (**B-12**)**: 시작 시 `Update.isRunning()` → `abort()`, 각 write 반환 검사
- **HW 파라미터 검증 (**B-13**)**: LED pin `0~48`, numPixels `1~16` 범위 검증
- **웹 UI 모달/세그먼트 규격 (UI-1~UI-4)**: `.snw-modal-box` Flexbox 구조화(Header/Footer 고정, Body 단독 터치 스크롤), 세그먼트 2열 그리드(`.snw-seg-card`, `.snw-seg-grid`), 세그먼트 삭제 시 Undo 복원 보장
- **오프라인 어댑터 및 부트스트랩 규약 (LOAD-1~LOAD-3)**: `window.SNW_OFFLINE`은 번들 파싱 전 선행 결정(`document.write`로 `998.offline_0202.js` 동기 주입), `999.app.js`는 `SNW.Offline.ready` 완료 대기 가드(Wait Guard) 필수
