20년차 자연풍 선풍기 개발 및 UI/UX 전문가 관점에서, 일반 사용자 시나리오를 중심으로 대대적인 기능 통폐합 및 오퍼레이션 동선 재설계 방안을 제시함.
### 1. 바람 제어 및 쾌적 모드 개념 통폐합 (멘탈 모델 단순화)
현재 코드베이스상 바람의 형태와 제어 방식이 여러 레이어로 나뉘어 있어 사용자가 무엇을 눌러야 할지 혼란을 겪음. 이를 직관적인 2단계 구조(바람 테마 + 지능형 케어)로 통폐합해야 함.
 * **바람 형태 통폐합: [프로파일 + 플레이리스트 + 프리셋] \rightarrow '바람 테마(Wind Theme)'**
   * **현황 진단**: cfg_windDict_0203.json(프리셋/사전), cfg_userProfile_0203.json(프로파일), 292.playlist.js(플레이리스트), 300.page.windprofile.js가 각각 별도 메뉴와 데이터 구조로 노출됨. 일반 사용자는 '프리셋'과 '프로파일'의 차이를 구분하지 못함.
   * **개선 방향**:
     * 모든 바람의 단위(단일 자연풍 패턴 및 복합 시퀀스 바람)를 '바람 테마'라는 단일 개념으로 통합함.
     * **기본 테마(내장)**: 산들바람, 파도소리 바람, 숲속 산책, 집중 바람 등 검증된 자연풍 프리셋 제공.
     * **나만의 테마(사용자 생성)**: 기존 '플레이리스트(여러 바람 이어듣기)'와 '프로파일(세부 파형 커스텀)' 기능을 통합하여, 사용자가 원하는 바람을 조합하거나 세기/변동폭을 조절해 저장하는 단일 포맷으로 일원화함.
 * **자동화 모드 통폐합: [스마트 쾌적 + AI 스마트 쾌적 + 취향맞춤 오토] \rightarrow 'AI 맞춤 케어(AI Care)'**
   * **현황 진단**: CT10_Ctl_Comfort_0203.cpp, CT10_Ctl_Ctl_Mode_0203.cpp 등에 구현된 세 가지 자동 모드는 알고리즘의 차이(센서 기반 vs AI 추론 vs 사용자 피드백 학습)일 뿐, 사용자 목적("알아서 쾌적하게 해줘")은 동일함.
   * **개선 방향**:
     * 세 모드를 **'AI 맞춤 케어'** 버튼 하나로 통합하고, 내부 엔진이 상황과 데이터 누적도에 따라 자동 전환되도록 백그라운드 처리함.
     * **동작 메커니즘**: 초기에는 온습도(불쾌지수) 기반의 '스마트 쾌적' 알고리즘으로 즉시 동작하고, 사용자의 수동 조작(바람 세기 증감 등)이 누적되면 '취향맞춤 오토' 가중치를 자동 반영하며, 수면 시간대나 대화 맥락이 감지되면 'AI 수면/상황 케어'로 심리스하게 전환됨.
     * UI에는 복잡한 모드 선택 대신 "현재 26.5°C, 평소 선호하시는 약한 산들바람으로 자동 조절 중입니다"와 같이 상태 피드백만 직관적으로 표기함.
### 2. 유사 기능 화면 통폐합 및 오퍼레이션 동선 최적화
현재 js/app/ 하위에 20여 개의 페이지 모듈(200.page.dashboard.js ~ 310.page.rules.js)이 산재해 있음. 일반 사용자의 엄지손가락 동선(Thumb Zone) 기준 **3개의 핵심 탭 + 1개의 상시 플로팅 바** 구조로 압축함.
 * **하단 내비게이션 3탭 재편**
   * **1탭: 홈 (메인 리모컨 - 200.page.dashboard.js 고도화)**
     * 전원, 바람 세기, 회전, 타이머 등 80% 이상의 일상 조작을 한 화면에서 스크롤 없이 완료하도록 배치함.
     * 상단에 'AI 맞춤 케어' 원터치 토글 및 주요 '바람 테마' 가로 스크롤 칩(Chip) 배치.
   * **2탭: 바람 스튜디오 (탐색 및 개인화 - 291.studio.js + 292.playlist.js + 300.page.windprofile.js + 245.page.simulation.js 통합)**
     * 바람을 고르고, 조합하고, 미리 체험하는 모든 행위를 한 공간으로 모음.
   * **3탭: 자동화 & 기기 관리 (293.schedule_panel.js + 294.timer_panel.js + 310.page.rules.js + 240.page.settings.js 통합)**
     * 예약(스케줄), 조건부 규칙(온도 몇 도 이상 시 켜짐), 센서 상태 및 기기 환경설정을 통합함.
     * 엔지니어링 성격이 강한 진단(250), 펌웨어(260), 로그(280), raw 모니터(260.page.monitor.js)는 일반 메뉴에서 숨기고, '기기 정보 > 고급 진단(개발자 모드)' 하위로 격리함.
 * **상시 하단 미니 플레이어 (999a.nowplaying.js 개선)**
   * 음악 앱(Spotify, 멜론)의 UX를 차용하여, 어느 화면에 있든 현재 불고 있는 바람의 이름, 파형 애니메이션, 일시정지/세기 조절이 가능한 미니 바를 하단 탭 바로 위에 고정함.
### 3. 사용자 취향 기반 바람 형태 및 동작 조건 개별화
엔지니어링 파라미터(PWM 듀티비, 주기, 난류 계수 등)를 감성적·직관적 언어와 제스처로 치환하여 진입 장벽을 제거함.
 * **감성 슬라이더 기반 바람 커스터마이징**
   * 주파수나 파형 수치를 직접 입력하는 대신 3가지 직관적 슬라이더만 제공함.
     * **바람 결 (부드러움 \leftrightarrow 선명함)**: 파형의 상승/하강 기울기 조절.
     * **바람 변화 (잔잔함 \leftrightarrow 역동적)**: 세기 변동폭 및 돌풍 빈도 조절.
     * **바람 세기 (미풍 \leftrightarrow 강풍)**: 전체 출력 스케일 조절.
 * **상황별 동작 조건 개인화 (If-This-Then-That 카드화)**
   * 기존 150.ui.rule_editor.js의 복잡한 조건식을 레고 블록 형태의 문장 완성형 UI로 단순화함.
   * 예: [방 온도가 27°C 이상일 때] + [내가 집에 있으면] \rightarrow [숲속 산책 테마로 2시간 작동].
 * **수면 패턴 개별화**
   * 사용자가 취침 예정 시간만 설정하면, 입면기(시원한 바람) \rightarrow 숙면기(체온 저하 방지용 초미풍) \rightarrow 기상 전(쾌적한 산들바람)으로 이어지는 바람 세기 곡선을 사용자 체질(더위 많이 탐 / 추위 탐)에 맞춰 자동 생성하고 드래그로 미세 수정하게 함.
### 4. 자연풍의 시각화 및 사전 체험 경험 (시각 \rightarrow 체험 \rightarrow 적용)
눈에 보이지 않는 '바람'을 시각적 실체로 전환하여 구매 만족도와 사용 재미를 극대화함.
 * **실시간 비주얼라이저 (Live Wind Canvas)**
   * 120.ui.chart.js와 116.ui.sparkline.js의 딱딱한 꺾은선 그래프 대신, 바람의 세기와 주기에 따라 실시간으로 일렁이는 **유체(Fluid) 파티클 또는 오로라 웨이브 애니메이션**을 홈 화면 배경 및 스튜디오 상단에 적용함.
   * 바람이 강해지면 파도가 높아지고 색감이 시원한 블루/민트 톤으로 변하며, 미풍일 때는 잔잔한 물결처럼 움직여 직관적인 인지 가능.
 * **원터치 '미리 불어보기 (Try Wind)' 시뮬레이션**
   * 기존 245.page.simulation.js는 별도 페이지에 격리되어 활용도가 떨어짐.
   * 바람 테마 목록이나 커스터마이징 화면에서 **[30초 체험]** 버튼을 누르면, 실제 선풍기 모터가 해당 패턴의 하이라이트 구간(강-약 변화가 뚜렷한 핵심 30초)을 압축 재생함.
   * 화면에서는 현재 불어오는 바람의 파형 위를 재생 바(Playhead)가 지나가며 "지금 느껴지는 바람이 파도가 밀려오는 구간입니다"라고 안내하여 시각적 데이터와 촉각적 경험을 동기화함.
### 5. LLM(Gemini) 기술을 활용한 초간편 자연어 조작 및 맥락 제어
코드베이스에 이미 구축된 W10_Web_Gemini_0203.cpp, CT10_Ctl_AIAction_0203.cpp, 147.ai.live.js, 999b.ai-sheet.js의 강력한 파이프라인을 전면으로 내세워 복잡한 메뉴 탐색을 대체함.
 * **전역 AI 플로팅 버튼 및 자연어 액션 실행**
   * 화면 우측 하단(또는 미니 플레이어 우측)에 항상 접근 가능한 AI 버튼 배치.
   * 사용자가 메뉴를 찾아 헤맬 필요 없이 일상 언어로 지시하면 CT10_Ctl_AIAction이 즉시 JSON 제어 명령으로 변환하여 실행함.
   * *발화 예시*:
     * "오늘 좀 습하고 꿉꿉한데 안 춥게 바람 좀 틀어줘" \rightarrow 제습 느낌의 간헐적 중약풍 테마 생성 및 타이머 설정.
     * "아기 자니까 소리 안 나게 제일 약한 바람으로 3시간만 켜줘" \rightarrow 저소음 초미풍 모드 + 180분 타이머 + LED 화면 끄기 동시 실행.
     * "방금 불었던 그 바람 마음에 드는데 저장해 줘" \rightarrow 직전 5분간의 동적 파형 로그를 추출해 '나만의 바람 테마'로 자동 저장.
 * **대화형 바람 튜닝 (Conversational Refinement)**
   * 바람을 쐬다가 "좀 더 시원하게", "바람이 너무 자주 바뀌어 어지러워"라고 말하면, 현재 활성화된 바람 프로파일의 파라미터(세기 오프셋, 변동 주기)를 실시간으로 수정하고 변경된 파형을 시각적으로 보여줌.
 * **선제적 AI 브리핑 (Proactive Suggestion)**
   * 앱 실행 시 현재 실내 온습도, 시간대, 사용자 이력을 LLM이 분석하여 1줄 요약 제안 카드를 띄움.
   * 예: *"열대야가 예상되는 밤이에요. 어제 좋아하셨던 '새벽 숲길' 수면 모드로 시작할까요? [예, 실행하기]"*

### 1. 현재 v0203 코드베이스 기준 3가지 자동화 모드 정밀 비교
코드베이스 분석 결과, 세 모드는 내부 제어 변수와 동작 트리거가 명확히 분리되어 있으나 일반 사용자에게는 이름만으로 기능을 유추하기 어려운 구조임.
 * **스마트 쾌적 (Smart Comfort / MODE_COMFORT)**
   * **핵심 원리**: 물리 센서(온도, 습도) 기반의 결정론적(Deterministic) 불쾌지수(DI) 및 열적 쾌적성 수식 제어임.
   * **제어 특성**: 사전에 정의된 온습도 구간별 목표 풍속 곡선(LUT 또는 연속 함수)에 따라 팬 속도를 자동 조절하며, 사용자 개인의 조작 이력은 반영하지 않는 표준 환경 대응 모드임.
   * **강점 및 한계**: 별도 학습 기간 없이 전원 켜자마자 즉시 일관된 쾌적함을 제공하나, 추위/더위를 타는 개인별 체감 온도 편차를 맞추지 못함.
 * **AI 스마트 쾌적 (AI Smart Comfort / MODE_AI_COMFORT)**
   * **핵심 원리**: 센서 데이터(온습도, 조도/시간대, 재실 여부 등)와 LLM/추론 엔진(CT10_Ctl_AIAction, W10_Web_Gemini)의 상황 맥락(Context) 분석이 결합된 지능형 제어임.
   * **제어 특성**: 단순 온습도 수치뿐만 아니라 시간대별 생체 리듬(입면-숙면-기상), 날씨 예보(열대야, 장마 등), 사용자 자연어 피드백("좀 춥네", "조용히 해줘")을 종합하여 바람의 패턴(자연풍 파형)과 풍속, 회전 반경까지 동적으로 재구성함.
   * **강점 및 한계**: 상황 적응력이 가장 뛰어나나, 사용자가 수동으로 풍속을 미세 조정할 때의 즉각적인 오프셋(Bias) 학습 로직이 '취향맞춤 오토'와 이원화되어 있음.
 * **취향맞춤 오토 (Preference Auto / MODE_PREF_AUTO)**
   * **핵심 원리**: 사용자 행동 로그 기반의 강화학습/가중치 보정(Personalization Bias) 제어임.
   * **제어 특성**: 특정 온습도 조건에서 사용자가 수동으로 바람 세기를 높이거나 낮춘 횟수, 선호하는 자연풍 파형(변동폭, 주기) 데이터를 누적하여 기본 자동 제어 곡선에 개인별 오프셋(\Delta \text{Speed}, \Delta \text{Gust})을 영구 반영함.
   * **강점 및 한계**: 쓰면 쓸수록 사용자에게 최적화되나, 초기 사용 시(Cold Start) 데이터가 없어 일반 자동 모드와 차이를 느끼기 어렵고 별도 모드로 분리되어 있어 사용자가 직접 선택해야만 학습이 작동하는 구조적 한계가 있음.
### 2. 'AI 맞춤 케어(AI Care)' 통폐합 아키텍처 및 동작 설계
일반 사용자 시나리오에서 사용자는 **"환경에 맞추는 것(스마트 쾌적)"**, **"상황을 읽는 것(AI 쾌적)"**, "내 취향을 기억하는 것(취향맞춤)"을 별개의 버튼으로 누르고 싶어 하지 않음. 이 세 가지는 하나의 지능형 선풍기가 당연히 수행해야 할 **연속적인 진화 단계**임.
 * **통합 제어 파이프라인 (3-Layer 하이브리드 엔진)**
   * **1층 (베이스라인 - 스마트 쾌적 엔진)**: 실내 온습도(불쾌지수)를 실시간 측정하여 물리적으로 가장 쾌적한 기본 목표 풍속(V_{base})을 산출함.
   * **2층 (개인화 보정 - 취향맞춤 엔진)**: 사용자의 과거 조작 이력(특정 온도에서 항상 1단 낮췄던 패턴 등)에서 추출된 개인 선호 오프셋(\Delta V_{pref})과 선호 바람 결(부드러움/역동성)을 $V_{base}$에 상시 합산함.
   * **3층 (맥락 추론 - AI 스마트 엔진)**: 현재 시간대(수면 시간 진입 여부), Gemini 자연어 피드백, 급격한 환경 변화를 감지하여 최종 풍속과 자연풍 파형(V_{final})을 미세 튜닝함.
 * **사용자 경험(UX) 및 UI 단순화 방안**
   * **버튼 단일화**: 홈 화면 및 모드 선택창에서 기존 3개 버튼을 제거하고 **[AI 맞춤 케어]** 원버튼으로 통합함.
   * **투명한 상태 피드백 (Explainable UI)**: 통합으로 인해 "지금 얘가 무슨 기준으로 도는 거지?"라는 불안감이 생기지 않도록, AI 케어 활성화 시 한 줄 상태 배너를 제공함.
     * *초기 사용 시*: "실내 27.2°C · 표준 쾌적 바람으로 운전 중" (스마트 쾌적 동작)
     * *학습 누적 후*: "실내 27.2°C · 평소 선호하시는 은은한 미풍으로 자동 조절 중" (취향맞춤 반영)
     * *심야 시간대*: "취침 시간 감지 · 체온 유지를 위해 바람을 서서히 줄이는 중" (AI 쾌적 동작)
   * **원터치 피드백 학습**: AI 케어 동작 중 사용자가 물리 버튼이나 앱 슬라이더로 풍속을 조절하면, 모드가 해제되는 것이 아니라 **"취향이 반영되었습니다 (현재 온도에서 바람을 조금 약하게 기억함)"** 토스트 메시지와 함께 즉시 취향맞춤 가중치로 흡수됨.
### 3. 플레이리스트 내 '수면 모드' 포함 및 통합 검토
현재 코드베이스에서 수면 관련 기능은 292.playlist.js(시간대별 바람 시퀀스), 293.schedule_panel.js(타이머/스케줄), CT10_Ctl_Comfort_0203.cpp(야간 감속 로직)에 분산되어 있음. **수면 모드를 독립된 특수 모드가 아닌 '시간 흐름에 따른 바람 플레이리스트(시퀀스)'의 일종으로 통합**하는 것이 UX 및 아키텍처 측면에서 매우 타당함.
 * **수면 모드와 플레이리스트의 본질적 동일성**
   * **플레이리스트의 정의**: 시간 경과(예: 30분 단위 또는 비율)에 따라 서로 다른 바람 테마(강풍 \rightarrow 산들바람 \rightarrow 초미풍)를 순차적으로 재생하는 타임라인 시퀀스임.
   * **수면 모드의 본질**: 결국 [입면기(시원한 바람 30분) \rightarrow 숙면기(초미풍 4시간) \rightarrow 기상 전(산들바람 1시간) \rightarrow 자동 종료]로 구성된 가장 대표적인 시계열 플레이리스트임.
 * **플레이리스트 통합 시 구조적 이점**
   * **메뉴 깊이 축소**: 별도의 '수면 모드 설정' 페이지를 없애고, '바람 테마(플레이리스트)' 목록의 최상단에 **[꿀잠 수면 케어]**, **[열대야 숙면 코스]**, [낮잠 1시간 코스]를 기본 내장 시퀀스로 제공하여 즉시 실행 가능하게 함.
   * **직관적인 타임라인 편집**: 사용자가 수면 바람을 커스터마이징할 때 복잡한 수식을 건드리는 대신, 음악 플레이리스트처럼 블록 순서와 재생 시간만 드래그하여 수정할 수 있음.
     * 예: [1단계: 숲속 바람 (20분)] \rightarrow [2단계: 아기 숨결 초미풍 (5시간)] \rightarrow [3단계: 아침 산들바람 (30분)]
   * **AI 맞춤 케어와의 연동 (동적 플레이리스트)**: 수면 플레이리스트가 재생되는 동안에도 백그라운드에서 'AI 맞춤 케어'의 센서 감지가 병행 동작함. 새벽에 기온이 급격히 떨어지면 플레이리스트에 설정된 2단계 풍속보다 한 단계 더 낮추거나 일시 정지하는 안전장치(체온 저하 방지)가 자동 개입함.
### 4. 종합 정리 및 다음 단계 제안

### 1. 기존 3가지 자동화 기능 차이 비교 및 통폐합 방향
 * **기존 3가지 모드 특성 및 한계 비교**
   * **스마트 쾌적 (Smart Comfort)**
     * 실내 온습도 센서 기반 불쾌지수(DI)를 산출하여 고정된 제어 곡선에 따라 풍속을 자동 조절하는 방식임 (CT10_Ctl_Comfort_0203.cpp 기반).
     * 장점: 오프라인 환경에서 안정적이며 동작 원리가 명확함.
     * 한계: 사용자 개인의 더위/추위 민감도나 선호하는 바람결(자연풍 패턴)을 반영하지 못함.
   * **AI 스마트 쾌적 (AI Smart Comfort)**
     * 센서 데이터에 LLM/AI 추론을 결합하여 상황을 자율 판단하고 제어 파라미터를 동적으로 변경하는 방식임 (CT10_Ctl_AIAction_0203.cpp, W10_Web_Gemini_0203.cpp 연계).
     * 장점: 복합적인 맥락 해석 가능.
     * 한계: 주기적 API 호출에 따른 네트워크 의존성, 응답 지연, 토큰 비용 발생 및 사용자 의도와 다른 임의 동작(블랙박스화)으로 인한 신뢰도 저하 우려.
   * **취향맞춤 오토 (Preference-customized Auto)**
     * 기본 자동 제어 엔진 위에 사용자가 선호하는 바람 세기 오프셋이나 바람 형태를 가중치로 적용하는 방식임.
     * 장점: 자동화의 편의성과 개인화 만족도를 동시에 확보 가능.
     * 한계: 스마트 쾌적과 기능적 경계가 모호하여 사용자에게 중복 메뉴로 인식됨.
 * **통폐합 방향 설정**
   * 상시 자율 개입 방식의 **'AI 스마트 쾌적'은 자동화 모드에서 완전 배제**함.
   * [스마트 쾌적의 환경 감지 엔진] + [취향맞춤 오토의 사용자 선택권]을 결합하여 단일 자동화 모드(가칭: **스마트 오토**)로 통폐합함.
   * AI 기능은 상시 백그라운드 제어가 아닌, 사용자가 필요할 때만 호출하는 **'AI 대화창(999b.ai-sheet.js)' 기반 온디맨드(On-Demand) 설정 도우미**로 역할 재정의함.
### 2. 통합 자동화 모드(스마트 오토) 세부 기능 설계
 * **핵심 제어 원칙**
   * "언제, 얼마나 세게 불 것인가"의 기준은 온습도/불쾌지수(DI)가 자동 연산함.
   * "어떤 느낌의 바람으로, 어느 범위 안에서 불 것인가"의 주도권은 사용자에게 명시적으로 부여함.
 * **사용자 선택권(개별화) 세부 항목**
   * **적용 바람 스타일(프리셋) 선택**
     * 자동 제어 시 출력할 기본 바람 형태를 사용자가 직접 지정함 (예: 일반 고정풍, 산들바람, 숲속바람, 파도바람 등 cfg_windDict_0203.json 기반 프리셋 연동).
   * **체감 세기 오프셋 조절 (취향 보정)**
     * 표준 불쾌지수 곡선 대비 전체 풍속을 단계별로 보정하는 슬라이더 제공 (예: 약하게(-20%) / 조금 약하게(-10%) / 표준(0%) / 조금 강하게(+10%) / 강하게(+20%)).
   * **풍속 상·하한선(Min/Max) 제한**
     * 자동 운전 중에도 사용자가 원치 않는 과도한 소음이나 무풍 상태를 방지하기 위해 최소/최대 동작 단수(예: 최소 1단 ~ 최대 5단)를 직접 잠금 설정 가능.
   * **반응 민감도 설정**
     * 온습도 변화에 따른 풍속 전환 속도 선택 (빠른 반응 / 부드러운 전환).
   * **센서 연동 옵션 (선택 사항)**
     * 모션/재실 센서(M10_MotionLogic_0203.h 등) 연동 시, 일정 시간 부재 감지되면 자동 대기(절전) 전환 토글 제공.
 * **AI 대화창 연계 운영 방식**
   * 자동화 모드 내부 로직에 AI를 넣지 않고, 사용자가 대화창을 열어 자연어로 지시할 때만 통합 자동화 모드의 설정값을 즉시 변경함.
     * 예시: "자동 모드인데 소리가 좀 크네, 최대 3단까지만 나오게 해줘" \rightarrow 스마트 오토의 Max Limit = 3 파라미터 즉시 업데이트.
     * 예시: "지금 자동 바람을 좀 더 부드러운 산들바람으로 바꿔줘" \rightarrow 스마트 오토의 Base Preset = 산들바람 변경.
### 3. 수면 관련 기능의 플레이리스트(수면 모드) 통폐합
 * **자동화 모드에서 수면 기능 분리 사유**
   * 일반 주간 자동화는 '현재 온도/습도 쾌적 유지'가 목적이지만, 수면 제어는 '시간 경과에 따른 인체 체온 저하 방지, 저소음 유지, 시각적 방해(LED) 차단'이 핵심임.
   * 자동화 모드 안에 수면 분기를 두면 설정이 복잡해지고, 사용자가 취침 시 자동 모드를 켜야 할지 수면 모드를 켜야 할지 혼동함.
 * **플레이리스트 기반 '수면 모드' 통합 구조**
   * 기존 플레이리스트 엔진(292.playlist.js, CT10_Ctl_Ctl_Seg_0203.cpp)을 활용하여 수면 전 과정을 시간대별 세그먼트 시퀀스로 통합 관리함.
   * **기본 수면 플레이리스트 구조 (3단계 템플릿 제공)**
     * 1단계 (입면기, 예: 0~45분): 열기 해소를 위한 부드러운 중약풍 자연풍.
     * 2단계 (숙면기, 예: 45분~취침 5시간): 체온 저하 방지 및 무소음 유지를 위한 초미풍 간헐 바람.
     * 3단계 (기상 전, 예: 기상 1시간 전~종료): 쾌적한 기상을 돕는 미세 풍속 상승 또는 자동 정지.
   * **수면 플레이리스트 전용 옵션**
     * **온습도(DI) 미세 보정 토글**: 수면 플레이리스트 실행 중에도 새벽 열대야 등으로 실내 온도가 급상승할 경우, 설정된 수면 곡선 내에서 풍속을 소폭 자동 상향하는 안전장치 연동.
     * **수면 환경 일괄 제어**: 수면 플레이리스트 시작 시 기기 본체 LED 자동 소등, 조작 비프음 음소거, 최대 RPM(소음) 제한을 별도 설정 없이 일괄 적용함.
     * **사용자 커스터마이징**: 일반 플레이리스트와 동일한 UI에서 각 수면 구간의 지속 시간과 바람 프리셋을 사용자가 직접 편집 및 저장(예: '열대야 수면', '환절기 수면') 가능.
### 4. 각 통폐합 기능별 보완 사항 검토
 * **통합 자동화 모드(스마트 오토) 보완 사항**
   * **수동 조작 개입(Override) 정책 명확화**
     * 자동 운전 중 사용자가 물리 버튼이나 앱에서 풍속을 직접 변경할 경우의 동작 정의 필요 (CT10_Ctl_Ctl_Ovr_0203.cpp 연계).
     * 권장 방식: 수동 조작 시 자동 모드를 무조건 강제 종료하기보다, "현재 세기 오프셋으로 임시 반영됨 (자동 유지)" 또는 "수동 모드로 전환됨" 중 명확한 규칙을 정하고 화면에 토스트 메시지로 즉각 안내함.
   * **센서 헌팅(Hunting) 방지 로직 강화**
     * 온습도 경계값(예: 26.9°C \leftrightarrow 27.0°C)에서 풍속이 빈번하게 오르내리는 현상을 막기 위해 히스테리시스(Hysteresis) 구간 및 최소 유지 시간(예: 3~5분) 적용 필수.
   * **동작 근거의 시각적 투명성 확보**
     * 사용자가 자동화 동작을 신뢰할 수 있도록 홈 화면 상태 영역에 1줄 요약 제공 (예: 27.4°C · 습도 62% (불쾌지수 77) → '산들바람' 3단 자동 운전 중).
 * **수면 플레이리스트 보완 사항**
   * **원터치 진입 동선 확보**
     * 수면 기능이 플레이리스트 탭 하위로 들어가더라도, 취침 전 어두운 환경에서 메뉴를 탐색하지 않도록 **홈 화면 최상단에 [수면 모드 시작] 원터치 퀵 버튼** 배치 필수.
   * **상대 시간(타이머형) 및 절대 시각(알람형) 병행 지원**
     * 고정된 기상 시각(예: 오전 7시 종료) 외에, 주말 등 불규칙한 취침을 고려하여 "지금부터 6시간/7시간/8시간 수면" 선택 시 전체 세그먼트 비율이 자동 스케일링되는 기능 보완 필요.
### 5. 현실적인 구현 및 사용자 운영 가능성 검토
 * **펌웨어 및 시스템 구현 관점 (v0203 코드베이스 기준)**
   * **구현 난이도 하락 및 코드 경량화**
     * CT10_Ctl_Comfort_0203.cpp의 기존 불쾌지수 연산 로직을 그대로 활용하되, 출력단에 사용자 선택 파라미터(프리셋 ID, 오프셋, Min/Max 클램핑)만 매핑하면 되므로 펌웨어 수정 범위가 명확하고 안정적임.
     * 별도의 수면 전용 제어 상태머신을 유지할 필요 없이 기존 세그먼트 플레이어(CT10_Ctl_Ctl_Seg_0203.cpp)에 수면 속성(LED 소등, DI 보정 플래그)만 추가하면 되어 유지보수성이 대폭 향상됨.
   * **네트워크 및 리소스 안정성 확보**
     * 상시 AI 추론 루프를 제거함으로써 ESP32-S3의 힙 메모리 단편화 위험, Wi-Fi 단절 시 제어 불능 상태, 외부 LLM API 장애로 인한 기기 오작동 리스크를 원천 차단함.
 * **사용자 운영(UX) 관점**
   * **학습 곡선 최소화 및 예측 가능성 향상**
     * 일반 가전 사용자는 "AI가 알아서 한다"는 모호한 기능보다, "온도에 맞춰 자동으로 조절되되 내가 고른 바람결과 세기 범위 안에서 움직인다"는 명확한 통제감을 선호함.
     * 주간(스마트 오토)과 야간(수면 플레이리스트)의 역할이 뚜렷하게 분리되어 일상적인 사용 패턴에 자연스럽게 안착 가능.
   * **오프라인 자립 운영 가능**
     * 인터넷 연결이나 API 키 설정이 없는 환경에서도 핵심 기능(스마트 오토 + 수면 플레이리스트)이 100% 독립 동작하며, AI 대화창은 부가적인 편의 기능으로 작동하므로 실사용 환경에서의 제품 완성도가 매우 높음.
