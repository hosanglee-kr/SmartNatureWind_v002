## 1. 개요

### 1.1 목적
본 문서는 Smart Nature Wind v0203의 **AI 자연어 제어** 및 **음성 인터페이스** 기능 요구사항을 정의한다. Stage 1~7의 물리 제어(Studio/Playlist/Schedule/Normal Fan) 위에 AI 계층을 추가하여, 사용자가 자연어 또는 음성으로 선풍기를 제어할 수 있도록 한다.

### 1.2 배경 및 현재 소스 기준 현황
- **현재 소스 상태 (v0203 베이스라인)**:
  - 백엔드 `W10_Web_Gemini_0203.cpp`: `POST /api/v001/ai/gemini` 엔드포인트 제공. Gemini 2.5 Flash 기반 단방향 텍스트 완성 프록시(`generateContent`), 레이트 리밋 3초, 응답 상한 4KB(요청 8KB).
  - 프론트엔드 `290.page.ai.js` (SNW.Page.AI): 단일 텍스트 챗 UI (단순 질문/답변형 대화).
  - 물리/세션 엔진: Stage 1~7에서 구축된 Session FSM (`CL_CT10_ControlManager`), NVS 런타임 영속성 (`CL_N10_NvsManager`), 모니터 링버퍼 (`CL_MON_Monitor`) 가동 중.
- **Stage 8 (0203_011) 확장 도입 이유**:
  - 기존의 단순 텍스트 대화에서 탈피하여 **"실제 선풍기를 제어하고 프로필을 생성하는 AI"** 구축.
  - 12대 Function Calling 도구 체계 도입: 자연어 명령 ➔ 세션 FSM 제어 (바람 세기, 타이머, 프로필 실행/생성, 스케줄 연동).
  - REST (기본/무료, 2-turn Function Calling) + Live API (선택/실시간 음성/유료) 이중 모드 지원.
  - 비용 상한 가드레일(일일 30분 초과 시 강제 REST 복귀) 및 백엔드 위험 명령 원천 차단.

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| **REST 모드** | HTTP POST `/ai/gemini` + 2-turn Function Calling (기본, 무료) |
| **Live 모드** | Gemini Live API WebSocket (실시간 음성, 유료) |
| **Function Calling** | Gemini가 도구(함수)를 호출하도록 지시하는 JSON 스키마 방식 |
| **2-turn** | Turn1(FunctionCall) → 실행 → Turn2(FunctionResponse + 자연어 응답) |
| **Barge-in** | 사용자가 말하기 시작하면 모델 응답을 즉시 중단 |
| **AEC** | Acoustic Echo Cancellation (스피커 출력 → 마이크 재유입 제거) |
| **Ephemeral Token** | 1회용 30분 유효 Gemini 인증 토큰 (API Key 노출 방지) |
| **Session Type** | PLAYLIST / PRESET / FIXED (v0203 Session 모델) |
| **Session Trigger** | MANUAL / SCHEDULE |
| **위험 명령** | reboot / factoryReset / fwUpdate / fileUpload 등 시스템 파괴 명령 |

## 3. 기능 요구사항

### 3.1 [F-AI-REST] 자연어 제어 (REST 모드)

#### F-AI-REST-01: 자연어 명령 처리 및 비동기 보호
- **설명**: 사용자가 자연어로 입력한 명령을 Gemini API를 통해 해석하고 실행
- **입력**: `POST /api/v001/ai/gemini`  
  `{ message: string, history: [{role, text}], lang: "ko"|"en", voiceMode: bool }`
- **출력**: `{ ok, text, _speechHint, _lang, actions[], session }`
- **비동기 보호 규약 (NEW)**: `async_tcp` 스레드 DoS 방어 필수. 백엔드는 네트워크 I/O 동안 `async_tcp` 이벤트 루프를 블로킹하지 않도록 비동기 처리(Worker Task 분리 또는 클라이언트 오케스트레이션)를 적용하여 대시보드/웹소켓 무응답 방지.
- **우선순위**: 🔴 필수
- **수용 기준**:
  - 응답 시간 < 5초 (Turn1+Turn2)
  - 최근 6턴 이력 유지
  - 실패 시 자동 폴백 (TTS 힌트)
  - AI 통신 중에도 `/api/v001/state` 및 WebSocket 핑/퐁 지연 100ms 미만 유지

#### F-AI-REST-02: 도구 세트 (12개)
- **설명**: Gemini가 호출 가능한 함수 12개

| # | 도구명 | 목적 | 인자 | 백엔드 위임 C++ 타깃 (현재 소스 연동) |
|---|---|---|---|---|
| 1 | `start_playlist` | 프로필 재생 | profileId, profileName | `CL_CT10_ControlManager::startUserProfileByNo(profileNo)` |
| 2 | `start_preset` | 프리셋 재생 | presetCode (enum 10), styleCode (enum 5) | `CL_CT10_ControlManager::startOverridePreset(...)` |
| 3 | `start_fixed` | PWM 고정 | percent (0~100) | `CL_CT10_ControlManager::startOverrideFixed(pct)` |
| 4 | `pause_session` | 일시정지 | - | `CL_CT10_ControlManager::pauseSession()` |
| 5 | `resume_session` | 재개 | - | `CL_CT10_ControlManager::resumeSession()` |
| 6 | `stop_session` | 정지 | - | `CL_CT10_ControlManager::stopSession()` |
| 7 | `set_timer` | AutoOff | minutes (1~1440) | `CL_CT10_ControlManager::setSessionAutoOff(min)`<br>*(★ 세션 라이프사이클에 바인딩된 1회성 `runtimeAutoOff`. 세션 종료/전환 시 자동 소멸되며 NVS 전역 설정 간섭 금지)* |
| 8 | `get_status` | 상태 조회 | - | `CL_CT10_ControlManager::getSessionSnapshot()` / `getStateSnapshot()` |
| 9 | `add_schedule` | 스케줄 등록 | name, days[], startTime, endTime, profileId | `CL_C10_ConfigManager::addSchedule(...)`<br>*(★ profileId 존재 여부 사전 검증 필수)* |
| 10 | `list_profiles` | 프로필 목록 | - | `CL_C10_ConfigManager::getUserProfilesSnapshot()` |
| 11 | `add_profile` | 프로필 생성 | name, steps[], repeat, repeatCount | `CL_C10_ConfigManager::saveUserProfiles(...)`<br>*(★ `g_A20_config_root` 직접 참조 금지, 스냅샷 기반 안전 저장)* |
| 12 | `release_manual_to_schedule` | 수동 해제 | - | `CL_N10_NvsManager::setManualOvrSchedule(false)` + `CL_CT10_ControlManager::clearManual()`<br>*(★ `stopSession()` 호출 금지! 스케줄 활성 시 물리 바람 무중단 복귀)* |

- **우선순위**: 🔴 필수
- **수용 기준**: 각 도구 실행 후 Session 상태 반영 확인

#### F-AI-REST-03: 2-turn 자연어 응답
- **설명**: Function Call 실행 후 결과를 Gemini에 반환하여 자연어 요약 생성
- **예시**:
  - 사용자: "1시간 후 꺼줘"
  - Turn1: `set_timer({minutes:60})` → 실행
  - Turn2: "네, 1시간 후에 꺼드릴게요"
- **우선순위**: 🔴 필수
- **수용 기준**: 2-turn 실패 시 로컬 `_speechHint` 폴백

#### F-AI-REST-04: 대화 이력 관리
- **설명**: 최근 6턴 이력을 localStorage에 저장
- **저장 키**: `snw.ai.history` (배열, 최대 20턴)
- **우선순위**: 🟠 권장
- **수용 기준**: 페이지 새로고침 후 이력 유지

#### F-AI-REST-05: 응답 캐시
- **설명**: 동일 질문 60초 내 재호출 시 캐시 반환
- **적용 조건**: 액션 없는 응답만 (액션은 매번 실행)
- **우선순위**: 🟡 선택
- **수용 기준**: 캐시 히트 시 응답 < 100ms

### 3.2 [F-AI-LIVE] 실시간 음성 (Live API)

#### F-AI-LIVE-01: Ephemeral Token 발급 및 백엔드 게이트키핑
- **설명**: API Key를 브라우저에 노출하지 않기 위해 1회용 토큰 발급
- **API**: `POST /api/v001/ai/live-token` → `{ token, expire, wsUrl }`
- **유효 기간 및 게이트키핑 (보안 강화)**:
  - 1회 발급 시 유효기간을 10~15분으로 제한.
  - 백엔드 `N10`의 당일 누적 오디오 사용량이 30분 상한(Cap)에 도달한 경우, 백엔드가 토큰 발급을 HTTP 403(`cost_capped`)으로 원천 차단하여 클라이언트 조작에 의한 과금 폭증 방지.
- **우선순위**: 🔴 필수
- **수용 기준**: 브라우저는 실제 API Key 접근 불가, 상한 도달 시 신규 토큰 발급 불가

#### F-AI-LIVE-02: Live WebSocket 연결
- **설명**: 브라우저 → Gemini Live WS 직접 연결
- **엔드포인트**: `wss://generativelanguage.googleapis.com/ws/.../BidiGenerateContent?access_token=<token>`
- **Setup 메시지**: model, system_instruction, tools, voice_config
- **우선순위**: 🔴 필수
- **수용 기준**: `setupComplete` 수신 < 10초

#### F-AI-LIVE-03: 오디오 입력 (마이크) 및 Worklet 캡슐화
- **설명**: 100ms 청크 단위 PCM 스트리밍
- **포맷**: 16kHz, 16-bit LE, Mono, Base64
- **AEC**: 필수 (`echoCancellation: true`)
- **AudioWorklet 인라인 캡슐화 (번들 파이프라인 준수)**: 별도 `.js` 파일 분리 시 LittleFS 정적 서빙 404 및 CORS 문제가 발생하므로, `147a.audio.capture.js` 내에서 인라인 Blob URL(`URL.createObjectURL(new Blob([...]))`)로 AudioWorklet 프로세서를 등록.
- **모바일 대응**: 사용자 첫 클릭/터치 이벤트에서 `AudioContext.resume()` 필수 체이닝.
- **우선순위**: 🔴 필수
- **수용 기준**: 청크 손실 0%, 지연 < 100ms, 모바일 터치 후 정상 동작

#### F-AI-LIVE-04: 오디오 출력 (스피커)
- **설명**: 24kHz PCM 스트림 재생
- **포맷**: 24kHz, 16-bit LE, Mono, Base64
- **재생 방식**: AudioBufferSourceNode 큐
- **우선순위**: 🔴 필수
- **수용 기준**: 끊김 없는 재생

#### F-AI-LIVE-05: Barge-in (말 자르기)
- **설명**: 사용자 발화 감지 시 모델 응답 즉시 중단
- **신호**: `serverContent.interrupted = true`
- **처리**: 재생 큐 즉시 flush + 활성 소스 stop
- **우선순위**: 🔴 필수
- **수용 기준**: 응답 중단 < 200ms, 오탐 < 5%

#### F-AI-LIVE-06: Function Call 위임
- **설명**: Live의 toolCall을 ESP32로 위임
- **API**: `POST /api/v001/ai/live-function` → `{ ok, name, result }`
- **우선순위**: 🔴 필수
- **수용 기준**: 왕복 < 500ms

#### F-AI-LIVE-07: 세션 자동 재연결
- **설명**: 14분 도달 시 자동 재연결 (Gemini 15분 제한)
- **경고**: 60초 전 토스트
- **백오프**: 1s → 2s → 4s → 8s (5회)
- **우선순위**: 🟠 권장
- **수용 기준**: 재연결 성공률 > 95%

### 3.4 [F-AI-SAFETY] 안전 및 보안

#### F-AI-SAFETY-01: 위험 명령 화이트리스트
- **설명**: 시스템 파괴 명령은 AI 도구로 노출 금지
- **차단 목록**: reboot, factoryReset, fwUpdate, fileUpload, clearAll, erase, format, shutdown
- **방어 위치**: 백엔드 `CT10_isForbiddenAIFunction()`
- **우선순위**: 🔴 필수
- **수용 기준**: LLM이 호출 시도해도 `error:forbidden` 반환

#### F-AI-SAFETY-02: 시스템 지시 강화
- **설명**: 프롬프트 인젝션 방어
- **지시 사항**:
  - 응답 25단어 이내
  - JSON/필드명 언급 금지
  - API Key 노출 금지
  - 위험 명령 자발적 거부
- **우선순위**: 🔴 필수
- **수용 기준**: "ignore instructions" 패턴 → 거부 응답

#### F-AI-SAFETY-03: Rate Limit
- **설명**: 연속 호출 제한 (2-turn 감안)
- **제한**: 5초 / 요청 1회
- **초과 시**: HTTP 429 + `_speechHint`
- **우선순위**: 🔴 필수
- **수용 기준**: 5초 내 재호출 → 429

#### F-AI-SAFETY-04: API Key 보호
- **설명**: API Key는 ESP32 NVS에만 저장
- **전송**: `x-goog-api-key` 헤더 (URL 노출 금지)
- **Live**: Ephemeral Token만 브라우저 노출
- **우선순위**: 🔴 필수
- **수용 기준**: 브라우저 devtools에 실제 키 노출 없음

#### F-AI-SAFETY-05: 요청/응답 크기 제한
- **설명**: 메모리 폭주 방지
- **요청 상한**: 12,288 bytes
- **응답 상한**: 8,192 bytes
- **초과 시**: truncate + 로그
- **우선순위**: 🔴 필수
- **수용 기준**: 12KB 초과 요청 → `request_too_large`

### 3.5 [F-AI-TTS] 음성 합성

#### F-AI-TTS-01: 브라우저 TTS (REST 모드)
- **설명**: Web Speech API `SpeechSynthesis`로 응답 음성 출력
- **우선순위**: 🔴 필수
- **수용 기준**: 모든 응답이 자연어 TTS로 재생

#### F-AI-TTS-02: 로컬 폴백 (`_speechHint`)
- **설명**: 2-turn 실패 시 백엔드가 TTS용 문구 생성
- **생성 규칙**: 도구별 한글 문구 테이블
- **우선순위**: 🔴 필수
- **수용 기준**: 2-turn 실패해도 자연스러운 TTS

#### F-AI-TTS-03: 언어 자동 감지
- **설명**: 응답 텍스트의 한글 비율 > 20% → `ko-KR`, 그 외 `en-US`
- **우선순위**: 🟠 권장
- **수용 기준**: 혼합 언어 응답도 자연스러움

#### F-AI-TTS-04: 에러 응답 TTS
- **설명**: 4xx/5xx 응답에도 `_speechHint` 필수
- **예시**:
  - 429: "요청이 너무 많습니다"
  - 403: "API 키가 유효하지 않습니다"
