백엔드(CT10_Ctl_StMG_0202.cpp의 decideRunSource())는 매우 명확한 우선순위를 가지고 모드를 결정합니다.

· useProfileMode (Bool):
  · true (프로필 모드): 스케줄을 완전히 무시하고 무조건 프로필을 실행합니다. (단, curProfileIndex >= 0 이어야 함)
  · false (스케줄 모드): 현재 시간과 요일을 계산하여 등록된 스케줄을 실행합니다.
· runSource (Enum): 현재 제어 소스 (NONE, SCHEDULE, USER_PROFILE)
· overrideState.active (수동 제어): 위의 모든 모드를 무시하고 즉각적인 명령을 최우선으로 실행합니다.

백엔드의 제어 우선순위:

1. 수동 제어 (Override) 최우선
2. AutoOff 래치 (정지 상태)
3. 프로필 모드(useProfileMode == true): 선택된 프로필이 없으면 IDLE, 있으면 실행
4. 일반 모드: 스케줄 시간이면 SCHEDULE_RUN, 아니면 IDLE

---

2. 사용자 관점의 문제점 및 혼란

사용자는 기기를 사용할 때 다음과 같은 시나리오를 가집니다.

· "매일 아침 8시에 자동으로 바람이 나왔으면 좋겠다." → 스케줄 모드
· "지금 당장 내가 만든 '수면 모드'를 2시간 동안 실행해 줘." → 수동 제어(Override)
· "스케줄은 잠시 끄고, 내가 선택한 프로필대로 계속 돌려줘." → 프로필 모드

현재 UI의 문제:
현재 대시보드에는 단순히 "켜기/끄기" 버튼(Override)과 프리셋(강도)만 있습니다. 스케줄과 프로필 중 어떤 모드로 기기가 동작 중인지 알 수 없고, 전환할 방법도 없습니다.
