## 1. 설계 목표 및 범위

### 1.1 목표
1. `async_tcp` 태스크에서 `W10_callGeminiApi()` 동기 HTTPS/TLS 호출(~2.0초, 2-turn·지연 시 최대 20~40초)을 완전히 분리해 **HTTP/WebSocket 응답성을 무중단(~0 ms 블로킹)**으로 유지한다.
2. `ESPAsyncWebServer`의 비스레드 안전성으로 인한 `AsyncWebServerRequest*` UAF(`LoadProhibited`) 위험을 구조적으로 제거한다.
3. 1-turn 제어 최적화 환경에서 불필요한 `JsonDocument` 및 프롬프트 재생성을 제거하고, 대용량 버퍼를 PSRAM으로 분리해 내부 SRAM 피크를 낮춘다.
4. 프론트엔드 호출부(`145.ai.client.js`, `290.page.ai.js`, `999b.ai-sheet.js`)는 수정 없이 `040.api.js` 단일 지점 래핑으로 호환성을 유지한다.

### 1.2 범위 제외
* `POST /api/v001/ai/execute-action` (`routeAIExecuteAction`): 외부 네트워크 호출 없이 로컬 액션만 즉시 실행(<10 ms)하므로 기존 동기 `200 OK` 구조를 유지한다.

## 2. 상세 아키텍처 설계

### 2.1 태스크 및 메모리 배치 (`T-ai` 신규)

| 항목 | 설계 사양 | 근거 |
|---|---|---|
| **태스크명** | `gemini_worker` (`T-ai`) | 상주 1개 고정 (반복 생성/해제에 따른 힙 단편화 방지) |
| **스택 크기 / 위치** | `10,240 B` / **내부 SRAM** | `WiFiClientSecure` + mbedTLS + `HTTPClient` + `ArduinoJson` 동시 실행 여유 확보 및 Flash/SPI 접근 안전성 |
| **우선순위 / 코어** | Priority `1` / Core `1` (또는 `tskNO_AFFINITY`) | `loopTask`, `async_tcp`, `WF10_Reconnect`, `dht_task`와 동일 Priority 1로 기아 방지 |
| **Job 버퍼 위치** | **PSRAM** (`MALLOC_CAP_SPIRAM \| MALLOC_CAP_8BIT`) | 가용 PSRAM `~1.85 MB` 활용, 내부 SRAM(`~173 KB`) 보호 |
| **TLS 버퍼** | 호출 시 할당 후 `Connection: close` 반납 | 유휴 시 ~35 KB 상시 점유 방지 |

### 2.2 단일 슬롯 Job 상태 머신 (`ST_W10_AiJobSlot_t`)

동시 1건 처리를 전제로 고정 1슬롯을 운영한다. 슬롯 메타데이터(`state`, `jobId`, `finishedMs`, `httpStatus`)는 전용 `SemaphoreHandle_t` (`s_aiJobMutex`, 또는 `portMUX_TYPE`)로 보호한다.

```text
  [IDLE] ──(POST 접수 + 복사 완료)──▶ [RUNNING] ──(워커 처리 성공)──▶ [DONE]
    ▲                                    │                              │
    │                                    └──(네트워크/파싱 오류)──▶ [ERROR]
    │                                                                   │
    └────(결과 조회 완료 또는 TTL 30초 경과 또는 다음 POST 덮어쓰기)──────┘
```

* **`POST` 수신 시 전이 규칙**:
  * 현재 상태가 `RUNNING`이면 즉시 `429 Too Many Requests` (`{"error":"ai_busy","jobId":"..."}`) 반환.
  * `IDLE`, `DONE`, `ERROR` 상태이면(이전 결과가 남아 있어도) 새 `jobId`를 발급하고 `RUNNING`으로 전환 후 워커에 시그널 전송.
* **TTL 만료 규칙**:
  * 클라이언트가 폴링 중 탭을 닫아 결과를 회수하지 않더라도 `DONE`/`ERROR` 상태는 다음 `POST` 시 즉시 덮어쓰며, `GET` 조회 시 `finishedMs` 기준 30초 경과분은 `404 {"error":"job_expired"}`로 정리해 `IDLE` 복귀.

### 2.3 HTTP API 상세 명세

#### A. 작업 등록: `POST /api/v001/ai/gemini`
* **요청 헤더/바디**: 기존과 동일 (`X-API-Key`, 최대 `12,288 B`, `G_RATE_LIMIT_MS = 5,000 ms` 유지).
* **응답**:
  * **성공(접수)**: `202 Accepted`
    ```json
    { "ok": true, "jobId": "ai_1732186388_1", "status": "pending" }
    ```
  * **워커 실행 중 / 레이트 리밋**: `429 Too Many Requests`
    ```json
    { "error": "ai_busy" } // 또는 "rate limited, please wait a few seconds"
    ```
  * **바디 누락/초과/인증 실패**: 기존과 동일 (`400`, `413`, `401`).

#### B. 결과 조회: `GET /api/v001/ai/gemini?jobId=<id>`
* **인증**: `requireApiKey(p_request)` 적용.
* **응답 분기**:
  * `jobId` 불일치 또는 만료: `404 Not Found` (`{"error":"job_not_found"}`)
  * `RUNNING`: `202 Accepted` (`{"ok":true,"jobId":"...","status":"pending"}`)
  * `DONE`: `200 OK` + 기존과 **100% 동일한 최종 응답 JSON** (`ok`, `text`, `_speechHint`, `_lang`, `actions`, `session`)
  * `ERROR`: `502 Bad Gateway` + 기존 에러 JSON (`ok:false`, `error`, `_speechHint`, `_lang`)

### 2.4 백엔드 처리 플로우 및 5대 최적화 반영

1. **`async_tcp` 최소 작업 (`routeGeminiProxy` POST 콜백)**
   * 인증·크기(`<= 12,288 B`)·레이트 리밋·`s_aiJobMutex`로 `RUNNING` 여부만 확인.
   * raw JSON 바디(`v_bodyBuf`, `v_bodyLen`)를 **PSRAM Job 요청 버퍼**에 그대로 복사(`memcpy`)하고 `freeBody(p_request)`.
   * JSON `deserializeJson()`조차 `async_tcp`에서 수행하지 않고 즉시 `202` 응답 전송 후 `xTaskNotifyGive(s_aiWorkerTask)` 호출.
2. **`gemini_worker` 처리 (`handleGeminiWorkerJob`)**
   * **API 키 캐싱/격리**: `W10_getGeminiApiKey()`의 `static char s_keyBuf[64]`는 워커 전용으로만 호출.
   * **파싱 및 분기**: PSRAM 요청 버퍼에서 `deserializeJson(v_inDoc, ...)` 수행 후, `message` 필드 유무에 따라 자연어 모드 / 레거시 프록시 모드 분기.
   * **Turn 1 조립 & 수명 조기 종료**:
     * `v_t1Body` 직렬화 완료 후, 후속 Turn 2가 필요 없는 일반 명령이면 `v_turn1Req.clear()`로 내부 메모리 즉시 반환 후 `W10_callGeminiApi()`(TLS 할당) 진입.
   * **Turn 2 지연 생성(Lazy Init)**:
     * `v_turn2Req`는 `v_needTurn2 == true`가 확정된 시점에만 생성하고 `CT10_AI::buildAIPromptStrict()` 및 `v_contents` 복사를 수행. (일반 1-turn 제어 명령에서 중복 생성/직렬화 비용 0)
   * **결과 저장**: 최종 응답 직렬화 문자열(최대 `8,192 B` 내외)을 **PSRAM Job 응답 버퍼**에 저장하고 상태를 `DONE`(또는 `ERROR`)으로 전환.
   * **구간 프로파일링**: `[AI_PROF]` 로그에 `queueWaitMs`, `turn1Ms`, `actionMs`, `turn2Ms`, `totalMs` 출력.

### 2.5 프론트엔드 투명 래핑 (`040.api.js`)

```javascript
async gemini(body) {
    const first = await _fetch(SNW.CFG.API.gemini, {
        method: 'POST',
        body,
        timeoutMs: SNW.CFG.TIMEOUT_MS.GEMINI
    });
    // 하위 호환: 백엔드가 200 즉시 응답을 주면 그대로 반환
    if (!first || first.status !== 'pending' || !first.jobId) {
        return first;
    }
    const deadline = Date.now() + SNW.CFG.TIMEOUT_MS.GEMINI;
    // 적응형 폴링: 1-turn 평균(~2.0s) 고려 첫 조회 700ms 대기 후 350ms 간격
    await new Promise(r => setTimeout(r, 700));
    while (Date.now() < deadline) {
        const res = await _fetch(`${SNW.CFG.API.gemini}?jobId=${encodeURIComponent(first.jobId)}`, {
            method: 'GET',
            timeoutMs: SNW.CFG.TIMEOUT_MS.DEFAULT
        });
        if (!res || res.status !== 'pending') return res;
        await new Promise(r => setTimeout(r, 350));
    }
    throw new ApiError(504, { error: 'ai_poll_timeout' });
}
```
* 주의: `_fetch()` 내부에서 `GET` 요청에 대해 `inflight` 중복 제거(`dedupeKey`)가 동작하지만, 순차 `await` 폴링이므로 매 회 완료 후 다음 `GET`이 발행되어 충돌하지 않는다.
* `OFFLINE_ROUTES`의 `POST /ai/gemini`는 기존처럼 즉시 객체를 반환하므로 `first.status !== 'pending'` 분기를 타고 무변경 동작한다.

## 6. 구현 누락 체크리스트 (Implementation Completeness Checklist)

실제 코딩 단계에서 빠뜨리기 쉬운 세부 항목을 사전 고정한다.

* **백엔드 (`W10_Web_Gemini_0203.cpp`, `W10_Web_0203.h`)**
  * [ ] `CL_W10_WebAPI::routeGeminiProxy()`에서 `HTTP_POST` 외 **`HTTP_GET` (`/api/v001/ai/gemini?jobId=...`) 라우트** 등록 누락 여부
  * [ ] `HTTP_GET` 핸들러에서도 **`requireApiKey(p_request)` 인증** 적용
  * [ ] `POST` 수신 시 **`beginBody()` / `appendBody()` / `takeBodyBuf()` / `freeBody()`** 모든 에러·조기 리턴 경로에서 누수 없이 해제
  * [ ] PSRAM Job 버퍼(`heap_caps_malloc(..., MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)`) 할당 실패 시 **내부 SRAM 폴백 또는 503 안전 실패** 처리
  * [ ] `s_aiJobMutex`로 `state`, `jobId`, `finishedMs`, `httpStatus`, `respLen` 보호 (임계 구역 내 `vTaskDelay`/네트워크 호출 절대 금지)
  * [ ] `W10_getGeminiApiKey()`의 `static char s_keyBuf[64]`가 워커(`gemini_worker`) 컨텍스트에서만 호출되도록 보장 (또는 워커 초기화 시 1회 복사)
  * [ ] `v_turn1Req` 직렬화 후 `v_needTurn2` 불필요 시 조기 `.clear()`, `v_turn2Req`는 `v_needTurn2 == true` 블록 내부에서만 지연 생성
  * [ ] `handleNaturalLanguageTurn` 외 **레거시 프록시 분기(`contents` 직접 전달)**도 동일하게 워커 내부에서 처리되도록 분기 유지
  * [ ] `[AI_PROF]` 로그에 `queueWaitMs`, `turn1Ms`, `actionMs`, `turn2Ms`, `totalMs` 및 `stackHwm` 출력
* **프론트엔드 (`040.api.js`)**
  * [ ] `SNW.Api.gemini(body)`에서 `202` (`status === 'pending' && jobId`) 폴링과 기존 `200` 즉시 반환 모두 지원
  * [ ] 첫 폴링 `700 ms` 대기 후 `350 ms` 간격 적용, 전체 상한 `SNW.CFG.TIMEOUT_MS.GEMINI` (45초) 준수
  * [ ] `GET` 폴링 중 `404` (`job_not_found`/`job_expired`) 또는 `502` 수신 시 무한 루프 없이 즉시 `ApiError` throw

## 8. 테스트 계획 및 목표 (Test Plan & Acceptance Targets)

### 8.1 테스트 목표 및 합격 기준 (Acceptance Criteria)

| 지표 | 목표 기준 | 검증 방법 |
|---|---|---|
| **`async_tcp` 무블로킹** | AI 요청 처리 중 동시 호출한 `GET /api/v001/state` 응답 시간 **`< 50 ms`** (기존 ~2,000 ms+ 대비 해소) | 동시 HTTP 폴링 + 타임스탬프 측정 (TC-05) |
| **`POST` 접수 지연** | `POST /api/v001/ai/gemini` → `202 Accepted` 반환 **`< 50 ms`** | 클라이언트 RTT 측정 (TC-02) |
| **워커 스택 여유** | `gemini_worker` (`10,240 B`) `uxTaskGetStackHighWaterMark()` 잔여 **`>= 2,048 B`** | 시리얼 `[AI_PROF]` 로그 확인 (TC-07) |
| **내부 SRAM 안정성** | 연속 5~10회 AI 호출 전후 `MALLOC_CAP_INTERNAL` 가용량 편차 **`<= 1 KB`** (누수 없음) | 호출 전후 `/api/v001/diag`·시리얼 비교 (TC-07) |
| **기능·회귀 무결성** | 1-turn/2-turn/오류/동시성/TTL/UI E2E/계약 검증 **전 항목 100% PASS** | 자동화 스크립트 및 실기 확인 (TC-01~08) |
