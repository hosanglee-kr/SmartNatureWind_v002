# FLOW.md — 데이터 흐름 및 시퀀스 명세

> F-03~F-06, I-1~I-4 반영 후 최신. T-loop/T-async/T-wf 라벨 유지.

## 1. 부팅 시퀀스 (setup())
```
Serial.begin → Logger::begin → Logger::setLevel
→ A00_init():
    LittleFS.begin
    → C10::begin (mutex 생성)
    → C10::loadAll (8섹션 파일 I/O) → g_A20_config_root 채움
    → N10::begin
    → A30 LED begin (g_A00_ledController)
    → WF10::init (WiFi + TM10::begin + reconnect task 생성)
       → startSTA() 성공 시 TM10::onWiFiConnected() 명시 호출 (F-01)
    → TM10::begin (멱등)
    → P10::begin (LEDC)
    → CT10::begin (mutex + members reset + _pendingMotionSimApply=false)
    → M10::M10_begin (singleton)
    → CT10.setMotion(g_M10_motionLogic)
    → W10::begin (모든 라우트 등록)
    → CT10_WS_setBrokers + CT10_WS_begin
    → WDT init(10s) + add(NULL)
```
**가드**: WDT는 init 완료 후 add — 블로킹 재시도 중 리셋 방지.

## 2. 메인 루프 (A00_run) — F-03/F-04/F-05 반영
```
[1] WDT reset
[2] F-05: consumePendingReload()
    if true:
        reloadAll() [T-loop]
        applySystemRuntimeFromConfig() [성공 시]
[3] CT10::tick() → tickLoop()
    ├ F-06: _pendingMotionSimApply.exchange(false)
    │       → applyMotionSimConfigToSim()
    ├ 40ms 스로틀
    ├ decideRunSource → applyDecision → 상태별 실행
    └ sim.tick() (OVERRIDE/PROFILE/SCHEDULE)
[4] CT10_WS_tick() — dirty → pending → 우선순위 1개 전송
[5] F-03: g_M10_motionLogic->tick()
        → PIR holdSec 감쇠 + _state 전이
[6] TM10::tick() — SNTP fallback 감시
[7] C10::processPendingFree() — grace 3s 경과분 free
[8] F-04: N10::tick() — dirty 10s 게이트 flush
[9] LED.run(wifiStatus)
[10] delay(10)
```
**부팅 후 첫 tick 순서**: F-05(무) → F-06(무) → CT10 tick → WS → M10 tick → TM10 → free → N10 → LED.

## 3. CT10 제어 tick 파이프라인 (tickLoop) — F-06 반영
```
[0] s_stateMutex 획득 (recursive)
[0-a] F-06: _pendingMotionSimApply.exchange(false) → applyMotionSimConfigToSim()
      (active/pwm 여부 무관, 파라미터만 갱신)
[1] active/pwm 체크, 40ms 스로틀
[2] 이벤트 hold/ack 체크 (override 우선)
[3] decideRunSource()  ← SSOT 상태 결정
[4] applyDecision()    ← runSource/idx/segRt/autoOffRt 확정
[5] 상태별 실행:
    OVERRIDE   → tickOverride → sim.tick (resolved일 때)
    PROFILE    → tickUserProfile → checkAutoOff → tickSegmentSequence(profile)
    SCHEDULE   → tickSchedule → checkAutoOff → tickSegmentSequence(schedule)
    그 외       → sim.stop
[6] maybePushMetricsDirty (1.5s 주기)
```

## 4. Config 재로드 (Reload) — F-05 반영 (async_tcp → loopTask 위임)
```
T-async (routeReload)                   T-loop (A00_run)
────────────────────────────────────────────────────────────────
[1] POST /reload
    checkApiKey
    requestReload()                     
      CAS(false→true)                   
      실패 → 409 반환                   
      성공 → 202 {result:queued}        
[2] 응답 반환 (< 50ms)                  
                                        [3] 다음 cycle (≤10ms)
                                        consumePendingReload()
                                          exchange(false) → true
                                        [4] reloadAll()
                                          a. C10::loadAll(v_new) [T-loop, C10 mutex]
                                          b. CT10 mutex 획득
                                          c. portMUX: g_A20_config_root ↔ v_old
                                          d. CT10 멤버 리셋
                                             _pendingMotionSimApply = false (I-3)
                                          e. mutex 해제
                                          f. queuePendingFree(v_old)
                                        [5] applySystemRuntimeFromConfig() [성공 시]
                                        [6] 다음 cycle processPendingFree (3s 후)
```

**프론트엔드 폴링**: `GET /api/v001/state` → `control.pendingReload`가 `false`로 전환될 때까지 대기.  
**의존 순서 문서**: SPEC.md §5.1 — patch는 반드시 `POST /config/save` → `POST /reload`.

## 5. WebSocket 브로드캐스트 파이프라인
```
[생산자] CT10 상태 변화 → markDirty(key)  [mutex]
[수집] T-loop CT10_WS_tick():
  collectPending: consumeDirty*()  [mutex]
  → 우선순위 s_prio[] 순회
  → trySendOne_v03(ch, now):
      interval 스로틀 (chart 대형 시 × mul)
      s_doc_<ch>.clear() (file-static, T-loop 전용)
      exportXxxJson(s_doc_<ch>)   ← I-1 pendingReload 포함
      s_bcast_<ch>(s_doc_<ch>, diffOnly)
[전송] W10::_broadcast(ws, doc, diffOnly):
  serializeJson → client별 canSend() → text()
[정리] cleanupClients (wsCleanupMs 주기)
```
**경계 계약**: WS-connect 콜백(T-async)은 caller-owned doc. file-static doc은 T-loop만.

## 7. 시간 동기화 흐름 (SNTP 콜백 기반) — F-01 반영
```
[트리거1] WiFi GOT_IP 이벤트 (T-sys_evt) → TM10::onWiFiConnected()
[트리거2] startSTA 성공 직후 (T-wf) → TM10::onWiFiConnected()  ← F-01 보조 경로
[트리거3] HTTP time/set → TM10_applyTimeConfigFromSystem + requestTimeSync(true)

[동작] _startSntpWithServer:
  SNTP_OPMODE_POLL + setservername + set_time_sync_notification_cb + init

[감시] T-loop TM10::tick():
  syncIntervalMs 재적용
  waitingCallback && timeout(15s) → _switchToNextServer (fallback 순환)

[완료] SNTP 콜백 → _isTimeSane() → s_timeValid=true, s_lastSyncMs=millis
[조회] getLocalTime() → _isTimeSane() + localtime_r NULL 방어
```
**F-01 후**: 트리거1이 mutex 경합으로 실패해도 트리거2가 `s_wifiUp=true` 보장 → SNTP 영구 미동기 방지.

## 8. PIR 피드 흐름 — F-03 반영
```
[1] T-async POST /motion/pir/feed
      → M10::feedPIR(pir)  [mutex]
        → notifyPIRDetected: _pir.active=true, _pir.lastDetected_ms=millis
[2] T-loop A00_run → g_M10_motionLogic->tick()  ← F-03
      [mutex]
      → holdSec 초과: _pir.active=false
      → 상태 변화 시 _state.pirActive/lastChange_ms 갱신
      → _onChange 콜백 (있으면)
[3] T-loop CT10::decideRunSource()
      → isMotionBlocked() → motion->isActive()
        isActive: _state.pirActive || (millis - lastChange_ms < holdSec*1000)
```
**F-03 후**: 부팅 후 `holdSec` 동안 false-positive (F-09) 자연 해소 — `_state.lastChange_ms`가 tick마다 갱신.

## 11. 예외/폴백 경로
| 이상 | 감지 | 폴백 |
|---|---|---|
| WiFi 연결 실패 (STA) | `startSTA` 반환 false | AP fallback |
| GOT_IP mutex 실패 | `isAcquired()==false` | **startSTA 성공 시 명시 통지** (F-01) |
| SNTP 타임아웃 | `waitStartMs` 15s 초과 | 다음 서버 fallback |
| 재연결 5회 초과 | `s_reconnectAttempts` | 로그만 |
| Config 파싱 실패 | `Load_File2JsonDoc_V21` | `.bak` → `.bak.old` 순 복구 |
| 저장 실패 (atomic) | rename 실패 | 원본 복원 후 false |
| Motion 없음 | `isMotionBlocked` | MOTION_BLOCKED + sim.stop |
| AutoOff 발동 | timer/offTime/offTemp | `_autoOffLatched` → ack 전 재개 차단 |
| **Reload 실패** | `reloadAll` false | 로그만, `_pendingReload` 소비됨 → 재요청 필요 |
| **Reload + Motion patch 경쟁** | 순서 민감 | SPEC §5.1: patch → save → reload 강제 |
