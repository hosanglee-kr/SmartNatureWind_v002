## 1. 시스템 개요

- **프로젝트명**: Smart Nature Wind (Standalone Firmware v0200 / 코드 접미사 v0201)
- **MCU**: ESP32-S3-N16R8 (16MB Flash, 8MB OPI PSRAM, dual-core Xtensa LX7 @ 240MHz)
- **프레임워크**: PlatformIO + Arduino-ESP32 (C++17 `-std=gnu++17`)
- **파일시스템**: LittleFS (`data_dir = ./src/v0200/data_v0200`)
  - **웹 개발 원본**: `data_src_v0200/html_v3/` (8분할 JS + HTML/CSS)
  - **빌드 파이프라인**: `pio_gzip_0200.py` (8 JS → `P010_bundle_0200.js` 단일 번들 + Level 9 Gzip)
  - **스테이징 배포**: `data_v0200/html_v3/` (LittleFS 이미지 대상)
- **아키텍처**: Standalone 풀스택 임베디드 펌웨어 (비동기 REST + WS + Gzip 정적 + 물리 시뮬레이터)

### 1.1 리팩토링 이력 (Batch A~F)

- **A** (P0): FIXED self-heal 무한 재호출 차단, CT10 캡슐화 위임, checkApiKey null 방어
- **B** (SSOT): 버전 상수, 화이트리스트, SemVer, NVS 키 상수화, preset 기본값
- **C** (매직넘버): S10 물리 상수, A00 WDT/loop, WF10 백오프, 시간 sanity
- **D** (성능): WS mutex 배치, String 할당 최소화, atomic 전환, 고정 배열
- **E** (Dead Code): 미사용 include, 주석 레거시, saveToFile 제거
- **E-2** (분할): 29파일 (W10 Routes 6분할, TM10 .cpp, Sch/UzProf/WindDc 5분할, CT10_Ctl 4분할, A25 IO)
- **F** (로직): Factory reset NVS 초기화, POST/PATCH 헬퍼, Logger INFO, profile fall-through 차단

## 5. 통신 및 API 사양

- **REST**: `/api/v001/*`
  - 인증: `X-API-Key` 헤더 (비어있으면 개방, **A-3 null 방어**)
  - 주요 경로: `/state`, `/control/*`, `/motion/*`, `/system`, `/wifi/*`, `/reload`, `/config/save`
- **WebSocket**: `/ws/{log|state|chart|metrics|summary}` (`?apiKey=...`)
- **OTA**: `/api/v001/fwUpdate` (multipart, `Update.h` 스트리밍)
- **파일 업로드**: `/api/v001/fileUpload` (최대 2MB, **N-4 safeAbort**)
- **정적 웹 호스팅**:
  - `Accept-Encoding` 검사 후 gzip/raw 분기 (RFC 7231)
  - `^/html_v3/.+` regex 라우트로 `.gz` 우선 서빙
  - `P010_bundle_0200.js` 단일 번들, `W10_guessMime` MIME 자동 판별
  - Root fallback 시 메인 HTML 부재 → 404 진단 메시지
  - **D-2/D-3**: `.gz` 경로 사전 계산 + regex 시 스택 버퍼(128B) → 요청당 힙 0회

### 5.1 API 응답 필드 (Batch N-1, F-2, F-3)

- `/api/v001/version`: `fw="FW_Ver_2.0.0"`, `control="CT10_Ctl_0201"` 등 (B-1)
- `/api/v001/system/firmware/check`: SemVer 비교 (`FW_VERSION_SEMVER="2.0.0"`, **B-3**)
- `/api/v001/state`: `control.pendingReload`, `control.lastReloadOk` (**N-1**)
- `/api/v001/system` POST/PATCH: **F-2 `_routeSystemPatchBody`** 응답 동일
- `/api/v001/wifi/config` POST/PATCH: **F-3 `_routeWifiConfigPatchBody`** 응답 동일
- `/api/v001/control/factoryReset`: `N10::resetRuntime()` 호출 (**F-1**)

### 5.2 설정 재적용(Reload) 정책 (I-2, F-05)

**핵심 원칙**: `POST /api/v001/reload`는 **디스크 저장 상태로 메모리 전면 재로드**. 디스크에 저장되지 않은 in-flight patch는 **소실**.

**동작 흐름**:

```text
[T-async]
  POST /api/v001/reload → requestReload() atomic CAS
  → 202 Accepted 즉시 반환 (< 1ms)

[T-loop]
  consumePendingReload() 확인 (≤ 10ms)
  → true → reloadAll():
      1. C10::loadAll(디스크 → v_new_root)
      2. s_rootSwapMux 하 원자 스왑
      3. CT10 상태 리셋 (_pendingMotionSimApply=false)
      4. queuePendingFree(v_old) 3초 grace
      5. applySystemRuntimeFromConfig()
```

**클라이언트 필수 원칙**:
1. `POST /motion`, `/system`, `/wifi/config`는 메모리 patch만.
2. reload 이전에 반드시 `POST /config/save` 호출.
3. reload 완료 폴링: `control.pendingReload` true→false, 성공 여부는 `control.lastReloadOk`.
4. 이미 pending 상태 시 재요청 → **409 Conflict**.

**금지 패턴**: `POST /motion` → (save 없이) `POST /reload` → 패치 유실.

## 6. 코딩 및 품질 컨벤션

- **JSON**: ArduinoJson v7 (`JsonDocument` 단일, `containsKey`/`createNested*` 금지)
- **문자열**: `memset` + `strlcpy` / `A25_Com_Utils_0201` 안전 복사
- **네이밍**:
  - 상수 `G_`, 전역변수 `g_`, 클래스 `CL_`, 구조체 `ST_..._t`, Enum `EN_`
  - 지역변수 `v_`, 인자 `p_`, 정적멤버 `s_`, private `_`
- **로깅**: `CL_D10_Logger::log(EN_L10_LOG_*, "[모듈] ...")`
- **매크로 정책 (E-2)**: 다중 .cpp 참조 매크로는 `*_Internal_0201.h`로 승격
  - 예: `G_C10_SCH_ID_START` → `C10_Config_Sch_Internal_0201.h`
- **Include 원칙 (E-2)**: 각 분할 .cpp는 참조 심볼의 헤더를 **직접 include**
  - 예: `C10_Config_Sch_JSON_0201.cpp`가 `A22_Com_Lookup_0201.h` 직접 include
- **A25 자립성**: `ST_A20_AutoOff_t`/`ST_A20_Motion_t` 참조 → `A20_Const_Sch_0201.h` 자체 include
