### 2.3 코드 검토 중 추가 반영된 안전성 보완 (4건)

1. **OOM DoS 방지 (크기 선검사)**: `p_total > G_MAX_REQUEST_BODY` 검사를 `beginBody()`(`malloc`) 호출 **이전**으로 이동하고, `beginBody()` 내부에도 1MB(`W10_MAX_ACCUM_BODY`) 상한 가드 추가.
2. **빈 body (`Content-Length: 0`) POST hang 방지**: `ESPAsyncWebServer`는 바디가 0바이트일 때 `onBody`를 호출하지 않고 `onRequest`만 호출하므로, `onRequest`에서 `contentLength() == 0` 분기 처리(`/ai/cost-reset`은 기본 리셋 후 `200`, 나머지 AI POST는 `400`).
3. **다중 청크 `401` 중복 `send()` 방지**: `onBody`에서 매 청크마다 `requireApiKey()`를 호출하지 않고 `p_index == 0`에서만 검사하도록 제한(실패 시 후속 청크는 `!acc`로 무시).
4. **연결 끊김 시 메모리 누수 차단**: `ST_W10_BodyAccum`을 단일 블록 `malloc(sizeof(ST_W10_BodyAccum) + total)`(flexible array)로 `_tempObject`에 할당해, 비정상 종료 시 `ESPAsyncWebServer` 소멸자가 한 번에 해제하도록 개선.

## 4. Stage 1~13 재발 방지 패턴 (7대 카테고리 · 28개 패턴)

코드 리뷰 및 신규 라우트 작성 시 아래 7대 카테고리를 기준으로 점검한다.

1. **AsyncWebServer 콜백·수명주기와 이중 `send()`**
   - `onRequest` vs `onBody` 호출 순서 및 빈 body(`contentLength == 0`) 처리 누락 금지
   - 응답 전송 후 반드시 `return`하여 이중 `send()` 어서트 크래시 방지
   - 라우트 등록 시 람다 캡처/경로 문자열 수명 보장(`cloneStr2SharedStr_safe` 등)
2. **TCP 단편화 Body 누적**
   - `if (index + len != total) return;` 후 `data, len`만 파싱하는 패턴 전면 금지 → `beginBody` / `appendBody` / `takeBodyBuf` / `freeBody` 사용
   - 크기 초과 검사는 반드시 `beginBody()` **이전**에 수행
3. **인증 게이트 (`requireApiKey`)**
   - `if (!checkApiKey(r)) return;` (응답 없는 hang 패턴) 금지 → `requireApiKey(r)` 사용
   - 컴파일 타임 게이트(`W10_USE_API_KEY`)와 런타임 설정 키 일관성 유지
4. **정적 자산·MIME·HTTP 헤더**
   - `strstr` 대신 `endsWith` 정확 매칭으로 `.json` 오판 방지
   - `X-Content-Type-Options: nosniff`와 missing `404` 반환 동반 적용
5. **메모리·OOM·동시성 (`async_tcp` vs `loopTask`)**
   - `async_tcp` 컨텍스트에서 `g_A20_config_root` 직접 참조 금지 (`getRootSnapshot` 또는 위임 플래그 사용)
   - `_tempObject`는 단일 블록 할당으로 연결 끊김 시 누수 방지
6. **외부 API·토큰·보안**
   - API Key는 URL 쿼리가 아닌 HTTP 헤더(`x-goog-api-key`)로 전달
   - 매직 넘버(예: 경고 임계 1500초) `constexpr` 상수화
7. **프론트엔드·백엔드 계약 정합성**
   - 세션/상태 응답 스키마(`session.type` 숫자 + `typeName` 문자열) 일치 유지
