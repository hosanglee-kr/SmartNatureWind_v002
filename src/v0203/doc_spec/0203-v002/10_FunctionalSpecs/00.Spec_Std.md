첨부된 79개 백엔드 소스 파일(*_0203.h/cpp) 구성을 기준으로, 임베디드(ESP32-S3/C3) 제어 로직·상태 머신·설정 영속화·웹 API/WebSocket·AI 연동 특성을 모두 포괄하는 **기능 명세서(Functional Specification) 표준 형식 및 항목 정의**임.
### 1. 기능 명세서 문서 계층 구조 (모듈 매핑 기준)
전체 79개 파일을 기능 도메인 단위로 7개 대분류(FN-01 ~ FN-07)로 구획하여 작성함.
 * **FN-01. 시스템 코어 및 공통 유틸리티**
   * 대상 파일: A00_Main, A20_Const_*, A22_Com_Lookup, A23_Com_ResetCfg, A30_LED, A40_Com_Utils*, D10_Logger
   * 포함 기능: 부팅 시퀀스, FreeRTOS 태스크/큐 초기화, 상태 LED 패턴, 공통 룩업/유틸리티, 공장 초기화 및 직렬 로거
 * **FN-02. 네트워크 및 시간 동기화**
   * 대상 파일: WF10_WiFiMgr, TM10_TimeMg
   * 포함 기능: Wi-Fi STA/AP 모드 전환 및 재연결 상태 머신, NTP 시간 동기화, 타임존/RTC 관리
 * **FN-03. 데이터 영속화 및 설정 관리 (CRUD/JSON/NVS)**
   * 대상 파일: C10_Config_* (Core, Sys, Sch, UzProf, WindDc, Extras), N10_NvsManager
   * 포함 기능: LittleFS JSON 직렬화/역직렬화(ArduinoJson v7), NVS 키-값 관리, 스케줄(Sch)·사용자 프로필(UzProf)·바람 사전(WindDc)·시스템 설정(Sys) CRUD 및 무결성 검증
 * **FN-04. 바람 제어 엔진 및 상태 머신 (핵심 제어)**
   * 대상 파일: CT10_Ctl_* (Ctl, Basic, Mode, Ovr, Seg, StMG, Comfort, IOWS), P10_PWM_ctrl
   * 포함 기능: 제어 모드 전환(Mode), 세그먼트/플레이리스트 실행(Seg), 수동 오버라이드(Ovr), 쾌적도(DI/온습도) 보정(Comfort), PWM 출력 연산 및 하드웨어 구동(P10), 상태 관리(StMG) 및 제어-웹 동기화(IOWS)
 * **FN-05. 센서 모니터링 및 물리 시뮬레이션**
   * 대상 파일: CT10_Monitor, M10_MotionLogic, S10_Simul_* (Core, IO, Physic, Const), S20_WindSolver
   * 포함 기능: 온습도/PIR/모션 센서 데이터 수집 및 디바운싱(Monitor, MotionLogic), 가상 환경/물리 시뮬레이터(Simul), 바람 파형/유동 솔버(WindSolver)
 * **FN-06. AI 연동 및 프롬프트/액션 제어**
   * 대상 파일: CT10_Ctl_AIPrompt, CT10_Ctl_AIAction, W10_Web_Gemini, W10_Web_Routes_AILive
   * 포함 기능: Gemini API 요청 페이로드 및 시스템 프롬프트 조립(AIPrompt), AI 응답 파싱 및 제어 파라미터 반영(AIAction), 라이브 AI 라우트 처리
 * **FN-07. 웹 서버, REST API 및 실시간 통신**
   * 대상 파일: W10_Web_* (Routes_*, WS, Static, Upload, Util, Const)
   * 포함 기능: 비동기 HTTP 라우팅(Control, Config, CRUD, Comfort, Session, System, Network, Monitor, WindDict), WebSocket 실시간 양방향 상태 브로드캐스트(WS), 정적 파일 서빙 및 OTA/설정 파일 업로드(Static, Upload)
### 2. 단위 기능 명세서 표준 템플릿 (필수 작성 항목)
각 세부 기능(예: FN-04-01. 제어 모드 전환 및 수동 오버라이드)별로 아래 8개 섹션을 필수 항목으로 정의함.
#### ① 문서 메타데이터 (Header Table)
 * **기능 ID / 명칭**: 계층형 고유 코드 및 명확한 기능명 (예: FN-04-02 / 세그먼트 기반 자연풍 파형 제어)
 * **관련 소스 파일**: 구현 및 선언이 위치한 .h / .cpp 파일 목록 및 핵심 함수/클래스명
 * **실행 컨텍스트**: 실행 주체(FreeRTOS Task명, Core 번호, 호출 주기 ms, 인터럽트/비동기 콜백 여부)
 * **선행 조건 (Pre-condition)**: 기능 진입 전 충족되어야 할 시스템 상태(예: Wi-Fi 연결 완료, Config 로드 완료, 센서 초기화 완료)
#### ② 기능 개요 및 비즈니스 규칙 (Overview & Rules)
 * **목적**: 해당 기능이 해결하는 사용자 요구사항 및 제어 목표 (1~2줄 요약)
 * **핵심 동작 규칙 (Business Rules)**: 우선순위 정책, 계산 수식(예: 감성 슬라이더 → PWM 매핑 공식, 불쾌지수 DI 산출식), 경계값(Min/Max/Default) 및 예외 처리 원칙
#### ③ 입출력 및 데이터 구조 명세 (I/O & Schema)
 * **입력 데이터 (Input)**: 내부 구조체(ST_*), 전역 상태 변수, 센서 Raw 값, HTTP 요청 파라미터/Body, WS 수신 JSON 페이로드
 * **출력 데이터 (Output)**: 하드웨어 제어 신호(PWM Duty/Freq, GPIO), NVS/LittleFS 저장 키 및 JSON 스키마, HTTP 응답 코드/Body, WS 송신 이벤트
 * **데이터 제약 및 검증 규칙**: 허용 범위(Range), 필수 필드 여부, 타입 검증 및 범위 초과 시 클램핑(Clamping) 또는 폴백(Fallback) 기준
#### ④ 상태 전이 및 처리 흐름 (State & Sequence)
 * **상태 머신 정의 (State Table)**: 상태명(EN_*), 진입 조건(Entry), 유지 동작(Do), 전이 이벤트(Trigger), 다음 상태(Next State)
 * **단계별 처리 시퀀스**: 정상 흐름(Main Flow)을 번호 매기기(1, 2, 3...)로 기술하며, 분기 조건 및 상호배제(Mutex/Semaphore) 점유 구간 명시
#### ⑤ 외부 인터페이스 명세 (API / WS / File I/O - 해당 시 작성)
 * **REST API 규격**: Method, Endpoint URL, Request JSON 예시, Response JSON 예시, HTTP Status Code (200/400/500)
 * **WebSocket 메시지 규격**: Event Type, Direction (C->S / S->C), Payload 필드 정의, 발행 트리거(주기적/이벤트성)
 * **저장소 스키마**: 파일 경로(/config/*.json) 또는 NVS Namespace/Key 구조 및 버전 호환성 필드
#### ⑥ 예외 처리 및 폴트 톨러런스 (Exception & Fail-safe)
 * **예외 시나리오 표**: 발생 조건(센서 단선, JSON 파싱 실패, Wi-Fi 단절, API 타임아웃, 메모리 부족 등) → 감지 방법 → 폴백 동작(안전 정지, 기본값 복구, 재시도 횟수) → 로그 코드(D10_Logger 레벨 및 메시지)
#### ⑦ 비기능 요구사항 및 리소스 제약 (Non-Functional)
 * **성능 및 타이밍**: 최대 응답 지연 시간(Latency), 제어 루프 지터(Jitter) 허용치
 * **메모리 안전성**: 정적 버퍼 크기(StaticJsonDocument 또는 JsonDocument 풀 크기), 동적 할당 금지 구간, 스레드 안전성(Thread-safety) 보장 방식
#### ⑧ 검증 기준 (Acceptance Criteria / Test Cases)
 * **단위/통합 검증 시나리오**: 정상 케이스(Happy Path), 경계값 테스트(Boundary), 장애 주입 테스트(Fault Injection)별 입력값과 기대 결과(Expected Output)
### 3. 명세서 작성 시 점검 체크리스트 (품질 검증 항목)
 * **코드-문서 일치성**: 소스 코드의 상수 정의(A20_Const_*.h)와 명세서의 기본값·한계치가 100% 일치하는지 확인함.
 * **명명 규칙 준수**: 모든 변수·구조체·모듈 표기 시 코드베이스의 접두어 규칙(M010_, CT10_, ST_, EN_, G_ 등)을 그대로 병기하여 추적성을 확보함.
 * **교차 계층 정합성**: C++ 내부 구조체 필드명과 C10_Config_*_JSON.cpp의 JSON 키, W10_Web_*의 API 응답 필드가 누락이나 오타 없이 매핑되는지 대조함.
우선적으로 상세 명세서 초안을 작성할 **기능 도메인(FN-01 ~ FN-07 중 선택)** 또는 **특정 모듈군(예: CT10_Ctl_* 제어 로직 또는 W10_Web_Routes_* API 명세)** 지정 요청함.

### 3. 효율적 작성 및 보완 실행 계획 (4단계 워크플로우)
스크립트 개발 없이 **기존 79개 초안(.md)을 뼈대(Skeleton)로 삼고, 대용량 핵심 원본 소스(.h/.cpp)만 선별 대조**하여 투입 시간을 최소화하는 전략임.
#### Phase 1. 부록(Cross-Cutting Schema) 선행 확정 (1일차)
본편 작성 전 데이터 구조와 인터페이스의 단일 진실 공급원(SSOT)을 먼저 확정하여 본편 간 불일치를 차단함.
 * **작업 1 (APP-02 작성)**: C10_Config_*_JSON_0203.cpp 4종 및 A23_Com_ResetCfg_0203.h를 참조하여 전체 JSON 키, 데이터 타입, 기본값(Default), 유효 범위 표 완성
 * **작업 2 (APP-01 작성)**: W10_Web_Routes_*_0203.cpp 10종 및 CT10_Ctl_IOWS_0203.cpp를 참조하여 전체 REST URI 및 WS 이벤트 타입 일람표 완성
 * **작업 3 (APP-03 작성)**: A20_Const_*.h 7종 및 D10_Logger_0203.h를 참조하여 열거형(EN_*), Mutex 핸들, 에러/로그 코드 매트릭스 완성
#### Phase 2. 핵심 제어·영속화 도메인 집중 작성 (FN-04 → FN-03) (2~3일차)
시스템 동작의 70%를 차지하는 제어 엔진과 설정 관리를 최우선 작성함.
 * **작성 방식**:
   1. 해당 도메인의 기존 .md 초안 내용(함수 목록, 구조체 정의)을 표준 템플릿의 **① 메타데이터** 및 **③ 입출력 구조**에 1차 배치함.
   2. 15KB 이상 핵심 원본 코드(CT10_Ctl_Ctl, CT10_Ctl_IOWS, CT10_Ctl_Basic, CT10_Ctl_StMG, CT10_Ctl_Ctl_Seg, C10_Config_Sys, C10_Config_Core, C10_Config_Extras)에서 **수식, 상태 전이 조건(if/switch), 클램핑 경계값, 에러 리턴 분기**만 발췌하여 **② 비즈니스 규칙, ④ 상태/흐름, ⑥ 예외 처리**를 채움.
   3. **⑤ 외부 인터페이스**는 Phase 1에서 만든 APP-01, APP-02의 해당 섹션을 링크 또는 발췌 삽입함.
#### Phase 3. 외부 연동 및 인프라 도메인 작성 (FN-07 → FN-06 → FN-05 → FN-01/02) (4~5일차)
상대적으로 로직이 직관적인 라우팅, 센서, 인프라 영역을 표준 템플릿에 맞춰 빠르게 정리함.
 * **FN-07 (웹 API/WS)**: APP-01의 라우트 명세를 기능 그룹별로 분류하고, W10_Web_Upload 및 W10_Web_WS의 버퍼 크기·동시 접속 제한(**⑦ 비기능 제약**)을 보강함.
 * **FN-06 (AI 연동)**: W10_Web_Gemini와 CT10_Ctl_AIAction의 타임아웃 처리, API 키 누락/응답 파싱 실패 시 폴백 동작(**⑥ 예외 처리**)을 집중 기술함.
 * **FN-05, FN-01, FN-02**: 기존 초안(.md)의 완성도가 높은 편이므로, 누락된 ④ 처리 시퀀스(부팅 순서, Wi-Fi 재연결 루프)와 ⑧ 검증 케이스(TC)만 추가하여 마감함.
#### Phase 4. 교차 검증 및 마스터 인덱스(00_FN_Master_Index.md) 생성 (6일차)
 * **정합성 점검**:
   * 79개 소스 파일이 FN-01 ~ FN-07 중 최소 1개 이상에 누락 없이 매핑되었는지 00_FN_Master_Index.md의 매핑 테이블로 전수 확인함.
   * 본편 문서 내 상수값과 A20_Const_*.h 상수값 일치 여부를 최종 대조함.
