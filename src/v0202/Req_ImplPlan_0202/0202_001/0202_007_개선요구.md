# [0202_007] 웹 및 백엔드 전면 UI/UX 기능 개선안 (대시보드 · 스케줄 · 프로필 · 백엔드)

> **문서 목적**: 대시보드, 스케줄, 사용자 프로필, 실시간 차트 등 스마트 자연풍(SmartNatureWind) 웹 전반의 UI/UX를 직관적으로 개선하고, 기존의 복잡한 상대 편차(`adjust Delta`) 방식을 폐기하며 **웹과 백엔드(C++/JSON) 전체를 `Override (절대값 0~100%)` 방식으로 일원화**하여 아키텍처의 단순성, 안정성 및 사용자 조작 편의성을 극대화합니다.

## 1. 대시보드 (Dashboard)

대시보드는 사용자가 현재 기기의 상태를 확인하고 즉각적으로 바람을 제어하는 핵심 메인 화면입니다.

### 1.1. 프리셋 및 스타일 선택 확장
- **모든 프리셋(10종) Grid 선택 제공**:
  - `OCEAN`(해안풍), `COUNTRY_BREEZE`(시골바람), `MEDITERRANEAN`(지중해풍), `MOUNTAIN`(산바람), `PLAINS`(평원바람), `HARBOR_BREEZE`(항구바람), `FOREST_CANOPY`(숲속바람), `URBAN_SUNSET`(도심노을풍), `TROPICAL_RAIN`(열대우림풍), `DESERT_NIGHT`(사막밤바람)
- **모든 스타일(5종) 선택 버튼 제공**:
  - `BALANCE` (자연풍/균형 - 기본)
  - `ACTIVE` (돌풍/활성)
  - `FOCUS` (주기풍/집중)
  - `RELAX` (산들바람/휴식)
  - `SLEEP` (수면풍 - **신규 추가**, 백엔드 매핑 완료)

### 1.2. 3대 물리 제어 슬라이더 및 정량적 실시간 설명 제공

대시보드에서 강도(Intensity) 슬라이더 1개만 제공하던 방식을 확장하여, **자연풍 3대 핵심 물리 파라미터(강도, 변동성, 돌풍 빈도)**를 직관적인 슬라이더로 조절할 수 있도록 합니다.

#### 📊 3대 파라미터 정량 지표 요약표

| 파라미터 | 조절 범위 | 핵심 정량 환산 지표 | 대표 체감 기준 |
| :--- | :---: | :--- | :--- |
| **바람 강도**<br>(Intensity) | 0 ~ 100% | • **체감 풍속**: 0.0 ~ 5.5 m/s<br>• **선풍기 환산**: 초미풍 ~ 4단 강풍<br>• **팬 모터 출력**: PWM 0 ~ 100% | 전체 바람의 볼륨(크기)을 비례적으로 스케일링 |
| **바람 변동성**<br>(Variability) | 0 ~ 100% | • **풍속 전환 수렴 시간**: 15초 ~ 3초<br>• **풍속 변화폭**: ±10% ~ ±60%<br>• **목표 풍속 갱신 주기**: 20초 ~ 4초 | 바람 세기가 얼마나 빠르고 다이내믹하게 바뀌는가 |
| **돌풍 빈도**<br>(Gust Frequency) | 0 ~ 100% | • **돌풍 발생 간격**: 120초 ~ 15초에 1회<br>• **순간 피크 배율**: 기본 대비 ×1.5 ~ ×2.5배<br>• **돌풍 지속 시간**: 약 3 ~ 5초간 | 큰 바람(돌풍)이 얼마나 자주 몰아치는가 |

#### 🔍 구간별 정량적 실시간 피드백 텍스트
1. **바람 강도 (Intensity, 0~100%)**:
   - `0%`: `0.0 m/s` · 팬 정지 (대기 모드)
   - `1 ~ 30%` (초미풍/수면풍): `0.5 ~ 1.5 m/s` · PWM 10~30% · 저소음 `< 25dB`  
     *"부채질 수준의 고요한 미풍입니다. 수면 시 또는 영유아에게 적합합니다."*
   - `31 ~ 70%` (표준 자연풍/1~2단): `1.5 ~ 3.5 m/s` · PWM 31~70% · `25 ~ 35dB`  
     *"나뭇잎이 살랑거리는 기분 좋은 산들바람입니다. 일상 휴식에 가장 쾌적합니다."*
   - `71 ~ 100%` (강풍/환기 3~4단): `3.5 ~ 5.5 m/s` · PWM 71~100% · `35 ~ 45dB`  
     *"창문을 열었을 때 부는 시원한 야외 바람입니다. 운동 직후나 빠른 환기에 적합합니다."*
2. **바람 변동성 (Variability, 0~100%)**:
   - `0 ~ 30%` (규칙적): `전환 시간 약 10~15초` · `변화폭 ±10% 미만`  
     *"바람 세기가 10초 이상 천천히 바뀌어 체감상 거의 일정하고 부드럽습니다."*
   - `31 ~ 70%` (자연풍): `전환 시간 약 5~8초` · `변화폭 ±20~40%`  
     *"숲속 바람처럼 5~8초 간격으로 풍속이 오르내리며 자연스러운 리듬감을 줍니다."*
   - `71 ~ 100%` (변화무쌍): `전환 시간 약 2~4초 급변` · `변화폭 최대 ±60% 이상`  
     *"2~3초 만에 풍속이 급격히 전환되어, 계곡이나 해변처럼 역동적이고 시원합니다."*
3. **돌풍 빈도 (Gust Frequency, 0~100%)**:
   - `0%` (돌풍 없음): `발생률 0` · *"돌풍 없이 평온한 기류만 부드럽게 유지됩니다."*
   - `1 ~ 20%` (잔잔함): `약 60~120초에 1회` (지속시간 ~3초)  
     *"1~2분에 1번 가벼운 돌풍이 지나갑니다. 수면이나 독서에 방해되지 않습니다."*
   - `21 ~ 60%` (보통): `약 30~50초에 1회` (순간 풍속 ×1.5~2.0배)  
     *"30~45초마다 시원한 바람이 훅 불어와 답답함을 해소해 줍니다."*
   - `61 ~ 100%` (빈번함): `약 15~25초에 1회` (순간 풍속 최대 ×2.5배)  
     *"15~20초마다 강력한 돌풍이 연속 유입되어 야외 언덕에 있는 듯 상쾌합니다."*

## 2. 스케줄 및 사용자 프로필 공통 개선 (Schedule & Profiles)

스케줄(`220.page.schedule.js`)과 프로필(`230.page.profiles.js`)은 동일한 세그먼트 실행 구조를 가지므로 일관된 고도화 설계를 적용합니다.

### 2.1. 입력 및 수정 항목 명확화
1. **프리셋/스타일 텍스트 입력 → 드롭다운(Select) 변경**:
   - 영문 텍스트 타이핑(`HARBOR_BREEZE`, `BALANCE`) 방식 대신, 10종 프리셋 및 5종 스타일 한글 드롭다운 제공 (`[ 항구 바람 (HARBOR_BREEZE) ▼ ]`).
   - 오타 발생 및 백엔드 파싱 거부 에러 원천 차단.
2. **조건부 입력 필드 비활성화 (Disabled)**:
   - '예약 종료', '온도 종료', 'PIR 센서 활성화' 체크 해제 시 연관 하위 입력 필드(종료 시간, 기준 온도, PIR 유지시간)를 `disabled` 처리하고 배경을 회색으로 음영 처리.
   - 비활성화된 필드는 저장 시 유효성 검사 대상에서 자동 제외.
3. **직관적인 용어 통일**:
   - `On(분)` / `Off(분)` $\rightarrow$ `작동 시간(분)` / `정지 시간(분)`
   - 모달 상단 타이틀을 `스케줄 수정: {스케줄명}`, `프로필 수정: {프로필명}`으로 명확히 표시.

### 2.2. 세그먼트 실행 제어 및 순서 편집
1. **세그먼트 순서 변경 (Up ▲ / Down ▼)**:
   - 세그먼트 헤더 우측에 `[▲]` / `[▼]` 버튼 배치.
   - 삭제 및 재입력 없이 한 번의 클릭으로 세그먼트 순서를 교체하고 `segNo` 자동 재정렬(10, 20, 30...).
   - 첫 번째 카드는 `▲` 비활성화, 마지막 카드는 `▼` 비활성화.
2. **아코디언 닫힘 시 요약 정보(Summary) 노출**:
   - 세그먼트 아코디언이 접혀 있어도 요약 정보 노출:  
     예: `바람 세그먼트 (총 2개) · 1: 항구 바람 20분/10분 → 2: 고정 55% 15분/5분`
   - 스마트 안심 종료 아코디언 접힘 시:  
     예: `안심 종료: PIR 모션 감지(120초), 예약 종료(23:00)`

### 2.3. 세그먼트 고급 물리 설정: Override (절대값 0~100%) 방식 전면 적용

복잡하고 불투명한 델타 편차(`adjust`) 방식을 배제하고, **화면 UI와 백엔드 엔진 모두 `Override (0~100% 절대값)` 방식으로 일원화**합니다.

#### 🎯 Override 방식 동작 및 UI 설계
1. **기본 동작 (비활성화 상태)**:
   - 세그먼트 카드 내 `[▼ 고급 물리 설정 (Override)]` 접이식 아코디언 배치.
   - 기본적으로는 "프리셋 고유값 사용" 상태(`override.enabled = false`)이며, 프리셋의 기본 물리 파라미터로 동작.
2. **Override 활성화**:
   - 사용자가 `[✔ 이 세그먼트에서 바람 세부 설정 직접 지정]`을 체크하면 슬라이더 활성화.
   - 3대 항목 모두 **대시보드와 동일한 0~100% 절대값 슬라이더**로 조작:
     - **강도 (Intensity)**: `0 ~ 100%` (조작 시 `3.5 m/s 산들바람` 등 정량 피드백 실시간 갱신)
     - **변동성 (Variability)**: `0 ~ 100%` (조작 시 `전환 시간 약 6초` 피드백 실시간 갱신)
     - **돌풍 빈도 (Gust Frequency)**: `0 ~ 100%` (조작 시 `약 40초 주기` 피드백 실시간 갱신)
3. **[프리셋 기본값 불러오기] 편의 버튼**:
   - 현재 선택된 프리셋의 기준 물리값을 슬라이더 초기 위치로 즉시 채우는 버튼 제공.
4. **프론트엔드 - 백엔드 1:1 직결 통신**:
   - 프론트엔드가 델타로 역산할 필요 없이, 사용자가 입력한 절대값(`0~100%`)을 그대로 백엔드 `override` 객체에 담아 전송.

## 3. 백엔드(C++/JSON) Override 리팩토링 아키텍처

레거시 `ST_A20_AdjustDelta_t`를 폐기하고 백엔드 전체를 `ST_A20_SegmentOverride_t`로 전환합니다.

### 3.1. C++ 데이터 구조체 변경 (`A20_Const_Sch_0202.h`)
```cpp
/* ======================================================
 * [신규] Segment Override (세그먼트 개별 물리 파라미터 덮어쓰기)
 *  - enabled == false : 프리셋 기본 물리값 사용
 *  - enabled == true  : 설정된 절대값(0~100%)으로 직접 덮어쓰기
 * ====================================================== */
typedef struct {
    bool  enabled         = false; // Override 활성화 여부
    float windIntensity   = -1.0f; // 0~100% (음수면 미사용/프리셋 유지)
    float windVariability = -1.0f; // 0~100%
    float gustFrequency   = -1.0f; // 0~100%
} ST_A20_SegmentOverride_t;

// 세그먼트 구조체 내 adjust -> override 필드 교체
typedef struct {
    uint8_t                  segId      = 0;
    uint16_t                 segNo      = 0;
    uint16_t                 onMinutes  = 0;
    uint16_t                 offMinutes = 0;
    EN_A20_segment_mode_t    mode       = EN_A20_SEG_MODE_PRESET;
    char                     presetCode[A20_Const::MAX_CODE_LEN] = {0};
    char                     styleCode[A20_Const::MAX_CODE_LEN]  = {0};
    
    // [변경] ST_A20_AdjustDelta_t adjust -> ST_A20_SegmentOverride_t override
    ST_A20_SegmentOverride_t override;

    float                    fixedSpeed = 0.0f;
} ST_A20_ScheduleSegment_t;
```

### 3.2. 물리 엔진 솔버 로직 변경 (`S20_WindSolver_0202.h`)
기존의 가산 연산(`+=`) 대신 **조건부 덮어쓰기(`=`) 로직**으로 변경:
```cpp
// 4) Segment Override 적용 (활성화 시 프리셋*스타일 값을 직접 덮어씀)
if (p_override && p_override->enabled) {
    if (p_override->windIntensity >= 0.0f) {
        v_int = A40_ComFunc::clampVal<float>(p_override->windIntensity, 0.0f, 100.0f);
    }
    if (p_override->windVariability >= 0.0f) {
        v_var = A40_ComFunc::clampVal<float>(p_override->windVariability, 0.0f, 100.0f);
    }
    if (p_override->gustFrequency >= 0.0f) {
        v_gust = A40_ComFunc::clampVal<float>(p_override->gustFrequency, 0.0f, 100.0f);
    }
}
```

### 3.3. JSON 스키마 변경 (`cfg_schedules_0202.json` / `cfg_userProfile_0202.json`)
```json
{
  "segId": 1,
  "segNo": 10,
```

```text
[세그먼트 1]                                     [▲] [▼] [🗑]
------------------------------------------------------------
작동 시간(분)    [ 20 ]     정지 시간(분)  [ 10 ]

모드 선택
(●) 프리셋 모드     ( ) 고정 풍속 모드

프리셋 선택
[ 항구 바람 (HARBOR_BREEZE) ▼ ]

스타일 선택
```
