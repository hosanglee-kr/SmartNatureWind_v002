[C-1] while(!Serial) 무한 루프 — 스탠드얼론 배포 시 기기 먹통

위치: main.cpp setup()

```cpp
Serial.begin(115200);
delay(1500);
while (!Serial) {                    // ← USB 호스트 없으면 무한 대기
    delay(A20_Const::G_A00_USB_CDC_POLL_MS);
}
```

· ESP32-S3 Native USB CDC 모드(ARDUINO_USB_CDC_ON_BOOT=1)에서 USB 호스트 미연결 시 !Serial이 영원히 true
· PC 없이 전원만 인가하면 setup()에서 영구 정지 → Wi-Fi/제어/웹 모두 시작 안 됨
· 개발 환경에서만 테스트했다면 절대 드러나지 않는 버그

수정안:

```cpp
uint32_t t0 = millis();
while (!Serial && (millis() - t0 < 3000)) {   // 3초 타임아웃
    delay(A20_Const::G_A00_USB_CDC_POLL_MS);
}
```

[C-2] 대시보드 프리셋 그리드가 영원히 비어있음

위치: 200.page.dashboard.js mount()

```javascript
async mount() {
    this.el.innerHTML = ''; this.el.appendChild(SNW.Tpl.dashboard());
    try {
        const [stateData, profileData] = await Promise.all([...]);
        if (!this._active) return;
        this._applyInitialState(stateData);
        if (profileData) this._applyPresetList(profileData);   // ① components.presets 없음(no-op)

수정안: _mountComponents() 이후로 재배치하고 필요 시 데이터 재조회

this._mountComponents();

if (profileData) this._applyPresetList(profileData);   // 컴포넌트 장착 후
```

[C-3] M10 isActive() — holdSec가 2배로 늘어남

위치: M10_MotionLogic_0202.h isActive()

```cpp
if (_state.pirActive) return true;
if (v_hold > 0 && (v_now - _state.lastChange_ms) < (v_hold * 1000UL))
    return true;   // ← 문제
```

_state.lastChange_ms는 상태가 바뀔 때마다(감지→활성, 활성→만료) 갱신됨:

· t=0: PIR 감지 → _state.pirActive=true, lastChange=0
· t=holdSec*1000: 만료 → _state.pirActive=false, lastChange=holdSec*1000
· t=holdSec*1000+1: 첫 조건 false, 두 번째 조건 (t - lastChange) < holdSec*1000 → true 반환

결과적으로 만료 후 다시 holdSec 동안 "활성" 상태 유지 → 실효 hold = 2×holdSec. holdSec=120초면 실제 240초간 fan 가동.

수정안: 두 번째 조건 삭제 (또는 lastChange_ms를 "감지 시점"만 기록)

```cpp
return _state.pirActive;   // 첫 조건만
```

_state.pirActive가 이미 hold 로직을 포함하므로 중복.

[A-1] WebSocket 브로드캐스트 스레드 안전성

CT10_WS_tick() (T-loop) → broadcastState() → AsyncWebSocketClient::text() 호출. text()는 내부 _messageQueue에 push하는데, ESPAsyncWebServer 소스 상 이 큐에 명시적 락이 없는 것으로 보임. async_tcp이 동시에 pop 중이면 std::list 손상 위험.

· 현재 메시지율(채널별 0.5~1.5s)이 낮아 실충돌 확률 낮음
· 권장: T-loop → T-async 전용 큐 → async_tcp에서 text() 호출, 또는 ESPAsyncWebServer의 락 문서 확인

routeGeminiProxy → W10_callGeminiApi가 최대 15초간 async_tcp 태스크를 점유. WiFiClientSecure의 readBytes/readBytesUntil은 내부적으로 available() 폴링이라 timeout(15s) 동안 다른 요청 처리 불가. 단일 사용자라면 수용 가능하나, 폴링 병행 시 UI 멈춤.

권장: Gemini 호출도 F-05/F-06처럼 T-loop 또는 별도 태스크로 위임.

[A-3] routeScan 블로킹

🔴 새로 발견된 크리티컬 버그

[NEW-C1] || 연산자로 인한 0값 손실 — 유효한 GPIO/브라이트니스가 기본값으로 덮어써짐

영향 필드 8곳:

필드 현재 코드 문제 시나리오
pwm.pin \|\| 6 GPIO 0 (유효) → 6으로 표시 → 저장 시 6 덮어씀
pir.pin \|\| 13 GPIO 0 → 13으로 덮어씀
dht.pin \|\| 17 GPIO 0 → 17로 덮어씀
led.pin \|\| 48 GPIO 0 → 48로 덮어씀
led.defaultBrightness \|\| 20 0 = LED 끄기 (유효) → 20으로 덮어씀
curve.startPercentMin \|\| 18 0% 시작 (유효) → 18로 덮어씀
curve.comfortPercentMin \|\| 22 0% (유효) → 22로 덮어씀
pir.holdSec \|\| 120 0 = PIR 비활성 (유효) → 120으로 덮어씀

원인: JavaScript ||는 falsy(0, '', null, undefined) 전부 폴백. 값 0은 정상 값이지만 폴백됨.
해결: ?? (nullish coalescing) — null/undefined만 폴백.

참고: 이미 pwm.channel ?? 0, pwm.res ?? 10은 올바르게 사용 중. 나머지는 놓쳤습니다.

    // ======================================================

    if (nvs_set_u32  (v_handle, G_N10_KEY_AUTOOFF_MINUTES,  s_state.autoOffMinutes)          != ESP_OK) v_setFail = true;

// ======================================================
// [B-5] Accept-Encoding 파서 (RFC 7231 q-value 지원)
//  - 이전: indexOf("gzip") → "gzip;q=0" 오탐지
//  - 이후: 토큰별 파싱 + q 값 검사 (q=0은 거부, 없으면 1.0)
// ======================================================
static bool W10_acceptsGzip(AsyncWebServerRequest* r) {
    if (!r || !r->hasHeader("Accept-Encoding")) return false;

    String v_ae = r->getHeader("Accept-Encoding")->value();
    v_ae.toLowerCase();

    int v_start = 0;
    while (v_start < (int)v_ae.length()) {
        int v_end = v_ae.indexOf(',', v_start);
        if (v_end < 0) v_end = v_ae.length();

        String v_token = v_ae.substring(v_start, v_end);
        v_token.trim();

        // 토큰은 "<coding>" 또는 "<coding>;q=<float>"
        String v_coding = v_token;
        int    v_semi   = v_token.indexOf(';');
        if (v_semi >= 0) v_coding = v_token.substring(0, v_semi);
        v_coding.trim();

        // gzip 또는 * 매칭
        if (v_coding == "gzip" || v_coding == "*") {
            // q 값 확인
            int v_qpos = v_token.indexOf("q=");
            if (v_qpos < 0) return true;   // q 없으면 기본 1.0 → 허용
            float v_qval = v_token.substring(v_qpos + 2).toFloat();
            return v_qval > 0.0f;          // q=0 → 거부
        }

        v_start = v_end + 1;
    }
    return false;
}

// ======================================================
// [D-2] W10_registerStaticRoute: .gz 경로 등록 시 사전 계산

void CL_W10_WebAPI::W10_registerStaticRoute(const char* p_uri, const char* p_file, const char* p_mime) {
    if (!p_uri || !p_file || !p_mime) return;

    auto v_uri  = A40_ComFunc::cloneStr2SharedStr_safe(p_uri);
    auto v_file = A40_ComFunc::cloneStr2SharedStr_safe(p_file);
    auto v_mime = A40_ComFunc::cloneStr2SharedStr_safe(p_mime);

    String v_gzPathString = String(p_file) + ".gz";
    auto   v_gz_file      = A40_ComFunc::cloneStr2SharedStr_safe(v_gzPathString.c_str());

    if (!v_uri || !v_file || !v_mime || !v_gz_file) {
        CL_D10_Logger::log(EN_L10_LOG_ERROR, "[W10] Route alloc failed: %s", p_uri);
        return;
    }

    s_server->on(v_uri.get(), HTTP_GET, [v_file, v_gz_file, v_mime](AsyncWebServerRequest* r) {
        // [B-5] RFC 7231 준수 gzip 판정
        if (W10_acceptsGzip(r) && LittleFS.exists(v_gz_file.get())) {
            auto* v_resp = r->beginResponse(LittleFS, v_gz_file.get(), v_mime.get());
            v_resp->addHeader("Content-Encoding", "gzip");
            v_resp->addHeader("Vary", "Accept-Encoding");

            r->send(v_resp);
