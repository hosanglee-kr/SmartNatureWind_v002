## 3. CT10 제어 tick 파이프라인 (tickLoop)
1. 이벤트 hold/ack 체크 (override 우선)
2. decideRunSource()  ← SSOT 상태 결정
3. applyDecision()    ← runSource/idx/segRt/autoOffRt 확정
4. 상태별 실행:
   - OVERRIDE → tickOverride → sim.tick (resolved일 때)
   - PROFILE  → tickUserProfile → checkAutoOff → tickSegmentSequence(profile)
   - SCHEDULE → tickSchedule → checkAutoOff → tickSegmentSequence(schedule)
   - 그 외    → sim.stop
5. maybePushMetricsDirty (1.5s 주기)

## 4. Config 재로드 (Reload) — 크로스태스크 협력
- T-async (routeReload) → CT10::reloadAll()
  1. C10::loadAll(v_new)     [T-async, C10 mutex]
  2. CT10 mutex 획득          [s_stateMutex]
  3. portENTER_CRITICAL       [s_rootSwapMux]
     g_A20_config_root ↔ v_old
  4. CT10 멤버 리셋
  5. v_guard.unlock()
  6. C10::queuePendingFree(v_old) → pending queue 2슬롯
  7. 반환
- T-loop (processPendingFree)
  - 3s 경과 항목 local copy → freeAll (mutex 밖)

**불변식**: `v_old` 메모리는 `queuePendingFree` 이후 즉시 접근 금지. `getRootSnapshot()` 캡처본 사용자는 3s 내 종료 필수.

## 5. WebSocket 브로드캐스트 파이프라인
- 생산자: CT10 상태 변화 → markDirty(key)  [mutex]
- 수집 (T-loop CT10_WS_tick):
  - collectPending: consumeDirty*()  [mutex]
  - 우선순위 s_prio[] 순회
  - trySendOne_v03(ch, now):
    - interval 스로틀 (chart 대형 시 × mul)
    - s_doc_<ch>.clear() (file-static, T-loop 전용)
    - exportXxxJson(s_doc_<ch>)
    - s_bcast_<ch>(s_doc_<ch>, diffOnly)

- 정리: cleanupClients (wsCleanupMs 주기)

**경계 계약**: WS-connect 콜백(T-async)은 caller-owned doc 사용. file-static doc은 T-loop만.

## 7. 시간 동기화 흐름 (SNTP 콜백 기반)
- 트리거1: WiFi GOT_IP 이벤트 (T-sys_evt) → TM10::onWiFiConnected()  [F-01 위험]
- 트리거2: startSTA 성공 직후 (T-wf) → TM10::onWiFiConnected()  [Fix-1]
- 트리거3: HTTP time/set → TM10_applyTimeConfigFromSystem + requestTimeSync(true)
- 동작 (_startSntpWithServer):
  - SNTP_OPMODE_POLL + setservername + set_time_sync_notification_cb + init
- 감시 (T-loop TM10::tick):
  - syncIntervalMs 재적용
  - waitingCallback && timeout(15s) → _switchToNextServer (fallback 순환)
- 완료 (SNTP 콜백): _isTimeSane() → s_timeValid=true, s_lastSyncMs=millis
- 조회: getLocalTime() → _isTimeSane() + localtime_r NULL 방어

## 8. PIR 피드 흐름 (외부 → M10 → CT10)
- T-async (POST /motion/pir/feed) → M10::feedPIR(pir)  [mutex]
  - notifyPIRDetected: _pir.active=true, _pir.lastDetected_ms=millis
- M10::tick — GAP F-03 미호출
  - holdSec 초과 시 _pir.active=false
  - 상태 변화 시 _state 업데이트 + _onChange 콜백
- CT10: isMotionBlocked() → motion->isActive()

**F-03 영향**: tick 미호출로 `_state.pirActive` 및 `_state.lastChange_ms` 갱신 안 됨 → `isActive()` 오작동.

## 10. 예외/폴백 경로
| 이상 | 감지 | 폴백 |
|---|---|---|
| WiFi 연결 실패 (STA) | `startSTA` 반환 false | AP fallback |
| GOT_IP mutex 실패 | `isAcquired()==false` | (F-01 수정 전: TM10 미동기) |
| SNTP 타임아웃 | `waitStartMs` 15s 초과 | 다음 서버 fallback |
| 재연결 5회 초과 | `s_reconnectAttempts` | 로그만, 수동 재시도 대기 |
| Config 파싱 실패 | `Load_File2JsonDoc_V21` | `.bak` → `.bak.old` 순 복구 |
| 저장 실패 (atomic) | rename 실패 | 원본 복원 후 false |
| Motion 없음 | `isMotionBlocked` | MOTION_BLOCKED + sim.stop |
| AutoOff 발동 | timer/offTime/offTemp | `_autoOffLatched` → ack 전 재개 차단 |
