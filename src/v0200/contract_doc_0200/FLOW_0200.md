# FLOW_0200.md — 데이터 흐름 및 시퀀스 명세

> **목적**: Smart Nature Wind v0200의 부팅 초기화, 메인 루프 파이프라인, 태스크 간 비동기 위임 시퀀스 및 예외 복구 흐름을 명세한다.  
> T-loop (`loopTask`), T-async (`async_tcp`), T-wf (`WF10_Reconnect`), T-sys_evt (`esp_event_loop`) 간의 협력 구조를 다룬다.  
> F-01~F-06, I-1~I-5 반영 완료.

---

## 1. 부팅 시퀀스 (`A00_init()`)

부팅 시 모든 모듈은 의존성 순서에 따라 정밀하게 초기화된다:

```text
[1] Serial & Logger
    └── CL_D10_Logger::begin() → 레벨 설정 (EN_L10_LOG_INFO)

[2] LittleFS 마운트
    └── LittleFS.begin(true) (실패 시 에러 로깅 후 복구 모드 대비)

[3] Config & NVS 초기화
    ├── CL_C10_ConfigManager::begin() (재귀 뮤텍스 생성)
    ├── CL_C10_ConfigManager::loadAll(g_A20_config_root) (8개 섹션 JSON 역직렬화)
    └── CL_N10_NvsManager::begin() (NVS Preferences 네임스페이스 오픈 및 런타임 복구)

[4] 필수 설정 검증 및 Status LED 시작
    ├── system / wifi 섹션 nullptr 방어 검사
    └── static CL_A30_LED 생성 → g_A00_ledController 할당 → begin()

[5] Wi-Fi 및 네트워크 관리자 시작
    └── CL_WF10_WiFiManager::init(v_wifi, v_sys)
         ├── attachWiFiEvents() (이벤트 리스너 1회 등록)
         ├── CL_TM10_TimeManager::begin() (NTP 멱등 초기화)
         └── startSTA() 시도
              ├── 성공: CL_TM10_TimeManager::onWiFiConnected() 직접 통지 [F-01]
              └── 실패: SoftAP 모드 폴백 유지

[6] PWM 및 중앙 제어기 시작
    ├── g_P10_pwm.P10_begin(*g_A20_config_root.system) (LEDC 25kHz 타이머 설정)
    └── CL_CT10_ControlManager::begin() (뮤텍스 lazy-init, 멤버 리셋, _pendingMotionSimApply=false)

[7] 모션 센서 로직 시작 및 바인딩
    ├── CL_M10_MotionLogic::M10_begin() (싱글톤 생성, g_M10_motionLogic 할당)
    └── A00_getControl().setMotion(g_M10_motionLogic) (CT10에 모션 인스턴스 주입)

[8] Web API 및 비동기 서버 시작
    ├── CL_W10_WebAPI::begin(g_A00_server, A00_getControl()) (REST/WS 라우트 등록)
    └── g_A00_server.begin() (포트 80 리스닝 시작)

[9] WebSocket 브로커 주입 및 스케줄러 시작
    ├── CT10_WS_setBrokers(...) (W10 브로드캐스트 콜백 함수 포인터 전달)
    └── CT10_WS_begin() (우선순위 큐 활성화)

[10] Task Watchdog Timer (WDT) 활성화
    ├── esp_task_wdt_init(10, true) (10초 타임아웃, 리셋 활성화)
    └── esp_task_wdt_add(NULL) (현재 loopTask를 WDT 감시 대상에 등록)
```

> **가드 원칙**: WDT는 초기화 중 Wi-Fi 연결 대기 등으로 인한 리셋을 방지하기 위해 반드시 `A00_init()`의 맨 마지막에 등록한다.

## 2. 메인 루프 파이프라인 (`A00_run()`)

`loopTask`가 전담하는 메인 루프는 매 10ms 주기로 비동기 위임 처리, 제어 로직, 센서 갱신, 메모리 해제를 순차 실행한다:

```text
[Step 1] WDT 리셋
         └── esp_task_wdt_reset()

[Step 2] [F-05] Pending Reload 비동기 위임 실행
         └── if (CL_CT10_ControlManager::consumePendingReload()) {
                 CL_CT10_ControlManager::reloadAll();
                 CL_W10_WebAPI::applySystemRuntimeFromConfig(*g_A20_config_root.system);
             }

[Step 3] CT10 메인 제어 루프
         └── CL_CT10_ControlManager::tick() ──► tickLoop()
                 ├─ [F-06] _pendingMotionSimApply 소비 ──► applyMotionSimConfigToSim()
                 ├─ 40ms 주기 스로틀 검사
                 ├─ decideRunSource() ──► applyDecision() (FSM 상태 전이)
                 └─ sim.tick() (물리 시뮬레이션 및 PWM 하드웨어 출력 반영)

[Step 4] WebSocket 브로드캐스트 스케줄러
         └── CT10_WS_tick() (Dirty 플래그 검사 후 우선순위 높은 채널 1개 전송)

[Step 5] [F-03] M10 모션 센서 루프
         └── if (g_M10_motionLogic) g_M10_motionLogic->tick();
                 └── PIR holdSec 시간 감쇠 및 상태 머신 전이

[Step 6] TM10 시간 관리자 루프
         └── CL_TM10_TimeManager::tick(g_A20_config_root.system);
                 └── NTP fallback 서버 타임아웃 감시 및 동기화 주기 관리

[Step 7] [E-1] 지연 메모리 해제 처리
         └── CL_C10_ConfigManager::processPendingFree();
                 └── 이전 설정 루트의 3초 grace period 경과분 안전 해제

[Step 8] [F-04] N10 런타임 데이터 플러시
         └── CL_N10_NvsManager::tick();
                 └── 10초 게이트 인터벌 확인 후 dirty 상태 NVS 플래시 기록

[Step 9] 상태 표시 LED 실행
         └── if (g_A00_ledController) g_A00_ledController->run(wifiStatus);

[Step 10] 태스크 스로틀
         └── delay(10) (FreeRTOS IDLE 태스크에 CPU 양보)
```

## 3. 설정 재로드(Reload) 위임 시퀀스 (F-05)

`async_tcp`의 100~500ms 파일 I/O 블로킹을 방지하기 위해 `loopTask`로 작업을 완전 위임한다:

```text
웹 클라이언트 (HTTP)         T-async (async_tcp)              T-loop (loopTask / A00_run)
      │                              │                                     │
      │── POST /api/v001/reload ────►│                                     │
      │                              │── requestReload() (atomic CAS)      │
      │                              │   ├── 이미 true: 409 Conflict 반환  │
      │                              │   └── 성공: s_pendingReload = true  │
      │◄── 202 Accepted ─────────────│                                     │
      │    (< 1ms 즉시 반환)         │                                     │
      │                              │                       (다음 루프 시작부 ≤ 10ms)
      │                              │                       consumePendingReload() == true
      │                              │                                     │──► reloadAll()
      │                              │                                     │     1. C10::loadAll(v_new)
      │                              │                                     │     2. s_rootSwapMux 하 스왑
      │                              │                                     │     3. queuePendingFree(v_old)
      │                              │                                     │──► applySystemRuntime...
      │                                                                    │
      │── GET /api/v001/state ──────►│ (폴링)                              │
      │◄── pendingReload: false ─────│ (reloadAll 완료 후 확인)            │
```

## 4. 모션 패치(Motion Patch) 위임 시퀀스 (F-06)

웹 클라이언트의 모션 설정 변경 시 CT10 뮤텍스 경합 대기를 제거한다:

```text
웹 클라이언트 (HTTP)         T-async (async_tcp)              T-loop (loopTask / CT10::tickLoop)
      │                              │                                     │
      │── POST /api/v001/motion ────►│                                     │
      │                              │── patchMotionFromJson(*g_root.motion)
      │                              │── requestMotionSimApply()           │
      │                              │   └── _pendingMotionSimApply = true │
      │◄── 200 OK {"updated":true} ──│                                     │
      │    (< 5ms 즉시 반환)         │                                     │
      │                              │                         (다음 제어 주기 ≤ 40ms)
      │                              │                         _pendingMotionSimApply.exchange(false)
      │                              │                                     │──► applyMotionSimConfigToSim()
      │                              │                                     │     (s_stateMutex 보유 상태)
```

## 5. Wi-Fi 연결 및 재연결 흐름 (F-01, F-02)

```text
T-async (HTTP 라우트)                 T-wf (WF10_Reconnect)            T-sys_evt / 시스템
        │                                      │                                │
        │── requestReconnect()                 │                                │
        │   ├── _ensureWifiTask() [F-02]       │                                │
        │   └── sem give ─────────────────────►│ (sem take 대기 해제)           │
        │   (즉시 반환)                        │                                │
        │                                      │── getRootSnapshot()            │
        │                                      │── applyConfig()                │
        │                                      │    ├── WiFi.disconnect()       │
        │                                      │    └── startSTA() (최대 5회)   │
        │                                      │         ├── 성공:              │
        │                                      │         │    TM10 통지 [F-01]─►│ (s_wifiUp = true)
        │                                      │         └── 실패: SoftAP 유지  │
```

## 6. 시간 동기화 흐름 (SNTP 콜백 및 다중 경로)

```text
[트리거 1] Wi-Fi GOT_IP 이벤트 발생 (T-sys_evt) ──► CL_TM10_TimeManager::onWiFiConnected()
[트리거 2] startSTA 연결 성공 직후 (T-wf) ─────────► CL_TM10_TimeManager::onWiFiConnected() [F-01 보조]
[트리거 3] HTTP /api/v001/time 수동 요청 ──────────► CL_TM10_TimeManager::requestTimeSync(true)

[동작] _startSntpWithServer(s_activeServerIdx)
         ├── esp_sntp_setoperatingmode(SNTP_OPMODE_POLL)
         ├── esp_sntp_setservername(0, serverName)
         └── esp_sntp_init()

[감시] T-loop TM10::tick():
         └── waitingCallback 상태에서 15초 초과 시 ──► _switchToNextServer() (Fallback 서버 순환)

[완료] SNTP 알림 콜백 수신 ──► _isTimeSane() ──► s_timeValid = true, s_timeSyncedRecently = true
```

## 7. PIR 모션 센서 피드 및 감쇠 흐름 (F-03)

```text
[1] 외부 피드 수신
    HTTP POST /api/v001/motion/pir/feed (T-async)
    └── CL_M10_MotionLogic::feedPIR(true)
         └── notifyPIRDetected(): _pir.active = true, _pir.lastDetected_ms = millis()

[2] 주기 감쇠 루프 (T-loop / A00_run)
    └── g_M10_motionLogic->tick() [F-03]
         ├── millis() - _pir.lastDetected_ms >= holdSec * 1000UL
         │    └── _pir.active = false
         └── 상태 변화 감지 시 _state.pirActive 및 lastChange_ms 갱신

[3] 제어 판정 반영 (T-loop / CT10::tickLoop)
    └── decideRunSource() ──► isMotionBlocked() ──► g_M10_motionLogic->isActive()
         └── _state.pirActive 확인 후 부재 시 MOTION_BLOCKED 전환
```

## 8. 예외 및 폴백 경로 요약

| 장애 유형 | 감지 지점 | 폴백 및 안전 복구 전략 |
|---|---|---|
| **Wi-Fi STA 접속 불가** | `startSTA` 5회 재시도 실패 | SoftAP 모드로 즉시 폴백하여 웹 UI 접근 유지 |
| **GOT_IP 이벤트 뮤텍스 경합** | `v_guard.isAcquired() == false` | `startSTA` 성공 시점의 명시 통지 경로로 보완 (F-01) |
| **NTP 동기화 타임아웃** | 15초간 콜백 미수신 | Google → Cloudflare → Pool.ntp.org 순환 fallback |
| **설정 JSON 파일 손상** | LittleFS 파일 오픈/파싱 실패 | `.bak` 백업 파일 자동 복구 시도 |
| **중복 Reload 요청** | `requestReload` atomic CAS 실패 | 즉시 409 Conflict 반환하여 불필요한 루프 부하 차단 |
| **재실자 부재 감지** | PIR holdSec 만료 | `MOTION_BLOCKED` 상태 진입 및 팬 즉시 정지 |
| **AutoOff 조건 충족** | 타이머/시간/온도 초과 | `_autoOffLatched = true` 설정 및 팬 안전 정지 |
| **Gzip 압축 파일 부재** | `LittleFS.exists(uri + ".gz") == false` | 비압축 원본 파일(`.html`, `.js`, `.css`)로 투명하게 폴백 서빙 |

## 9. 웹 에셋 빌드 및 정적 서빙 파이프라인

### 9.1 빌드 전처리 파이프라인 (`pio_gzip_0200.py`)
PlatformIO의 `buildfs` / `uploadfs` 타깃 빌드 시 Pre-script로 자동 트리거되어 정적 에셋을 최적화한다:

```text
[개발 소스 원본]
src/v0200/data_src_v0200/html_v3/
  ├── P010_main_0200.html (8개 분할 스크립트 태그 포함)
  ├── P000_common_0200.js ~ P018_main_ws_0200.js (8개 모듈)
  └── 기타 서브페이지 HTML/JS/CSS/SVG (총 29개 파일)
            │
            ▼ (PlatformIO extra_scripts: pre:pio_gzip_0200.py)
[1] 번들 결합: 8개 메인 JS 모듈을 순서대로 병합 ──► P010_bundle_0200.js 생성
[2] HTML 변환: P010_main_0200.html의 8개 <script> 태그 ──► <script src="P010_bundle_0200.js"></script> 1개로 치환
[3] 사전 압축: HTML, JS, CSS, SVG, JSON 등 모든 텍스트 에셋 gzip (Level 9) ──► *.gz 생성
            │
            ▼
[LittleFS 빌드 스테이징]
src/v0200/data_v0200/html_v3/
  └── 번들 JS, 변환된 HTML, 전체 사전 압축 파일 배포 (428.9KB → 114.6KB, -73.3%)
```

### 9.2 런타임 정적 웹 서빙 흐름 (`W10_Web_Static_0200.cpp`)

```text
브라우저 (Client)               T-async (async_tcp / W10)            LittleFS (Flash)
       │                                     │                              │
       │── GET /html_v3/P010_main_0200.html ─►│                              │
       │   Accept-Encoding: gzip             │── exists("/...html.gz") ────►│
       │                                     │◄── true ─────────────────────│
       │                                     │── beginResponse(..., gzPath) │
       │                                     │── addHeader("Content-Encoding", "gzip")
       │◄── 200 OK (Gzip 바이너리 스트림) ───│                              │
       │    Content-Encoding: gzip           │                              │
       │                                                                    │
(브라우저 자체 Gzip 압축 해제 렌더링)
       │
       │── GET /html_v3/P010_bundle_0200.js ─►│

       │
(8개 분할 요청 없이 1회의 번들 로드로 대시보드 로드 즉시 완료)
```
