🔴 새로 발견된 크리티컬 버그

[NEW-C1] || 연산자로 인한 0값 손실 — 유효한 GPIO/브라이트니스가 기본값으로 덮어써짐

영향 필드 8곳:

필드 현재 코드 문제 시나리오
pwm.pin \|\| 6 GPIO 0 (유효) → 6으로 표시 → 저장 시 6 덮어씀
pir.pin \|\| 13 GPIO 0 → 13으로 덮어씀
dht.pin \|\| 17 GPIO 0 → 17로 덮어씀
led.pin \|\| 48 GPIO 0 → 48로 덮어씀
led.defaultBrightness \|\| 20 0 = LED 끄기 (유효) → 20으로 덮어씀
curve.startPercentMin \|\| 18 0% 시작 (유효) → 18로 덮어씀
curve.comfortPercentMin \|\| 22 0% (유효) → 22로 덮어씀
pir.holdSec \|\| 120 0 = PIR 비활성 (유효) → 120으로 덮어씀

원인: JavaScript ||는 falsy(0, '', null, undefined) 전부 폴백. 값 0은 정상 값이지만 폴백됨.
해결: ?? (nullish coalescing) — null/undefined만 폴백.

참고: 이미 pwm.channel ?? 0, pwm.res ?? 10은 올바르게 사용 중. 나머지는 놓쳤습니다.

🟡 UX / 보안 개선점

[NEW-U1] API Key가 password 필드에 실제 값으로 프리필

```html
<input type="password" id="api-key" value="${esc(sec.apiKey || '')}">
```

· 화면엔 ●●●이지만 DOM 검사로 평문 노출 (devtools → input.value)
· 실사용 UX 패턴: 빈 필드로 두고 placeholder로 "변경 시에만 입력" 안내
· 저장 로직: 빈 필드면 키 미변경 (현재 백엔드는 ""로 삭제 처리 — B-4 수정과 충돌)

권장안: 별도 "삭제" 버튼 + 빈 필드 유지.

[NEW-U2] API Key 삭제 UI 부재

B-4 백엔드 수정으로 {"security":{"clearApiKey":true}}를 지원하지만, 프론트에 UI가 없음. 설정 페이지에 "키 삭제" 체크박스 필요.

[NEW-U3] wsChConfig 빈 배열 시 채널 설정 UI 미표시

```javascript
const wsCh = ws.wsChConfig || [];
const wsHtml = `...<h3>WebSocket 채널 설정</h3>`;
wsCh.forEach(...);   // 빈 배열이면 채널 없음
```

WS 채널 4개(고정)는 필수인데 손상된 config 시 UI에 아무것도 없어 복구 불가.

[NEW-U4] Boolean 처리 — pir.enabled가 문자열일 경우

```javascript
${pir.enabled?'checked':''}
```

pir.enabled가 문자열 "true"여도 truthy → checked. "false"도 truthy → 잘못된 상태. 백엔드는 bool 반환하지만 방어 필요.

async _onSave() {
    const q = sel => this.el.querySelector(sel);

    // [NEW-U1/U2] API Key 처리: 빈 필드=변경 안함, 체크박스=삭제
    const apiKeyVal      = q('#api-key').value.trim();
    const geminiKeyVal   = q('#gemini-key').value.trim();
    const clearApiKey    = q('#clear-api-key').checked;
    const clearGeminiKey = q('#clear-gemini-key').checked;

    const securityPatch = {};
    if (clearApiKey)              securityPatch.clearApiKey = true;
    else if (apiKeyVal.length)    securityPatch.apiKey = apiKeyVal;
    // 빈 필드 + 미체크 → 보안 필드 미변경 (전송 안 함)

    if (clearGeminiKey)           securityPatch.clearGeminiApiKey = true;
    else if (geminiKeyVal.length) securityPatch.geminiApiKey = geminiKeyVal;

    // WS 채널 수집
    const wsChArr = [];
    this.el.querySelectorAll('[data-ws-itv]').forEach(el => {
        const idx  = Number(el.getAttribute('data-ws-itv'));
        const prio = Number(q(`[data-ws-prio="${idx}"]`).value);
        wsChArr.push({ chIdx: idx, chIntervalMs: Number(el.value), priority: prio });
    });

    const patch = {
        meta: { deviceName: q('#meta-deviceName').value },
        system: {
            logging: { level: q('#log-level').value, maxEntries: Number(q('#log-maxEntries').value) },
            webSocket: {
                wsChConfig: wsChArr,
                wsEtcConfig: {
                    chartLargeBytes:  Number(q('#ws-chartLarge').value),
                    chartThrottleMul: Number(q('#ws-chartThrottle').value),
                    wsCleanupMs:      Number(q('#ws-cleanup').value)
                }
            }
        },
        // securityPatch는 항상 포함 (빈 객체여도 OK — 백엔드 무시)
        security: securityPatch,
        hw: {
            fanPwm: { pin: Number(q('#hw-pwm-pin').value), channel: Number(q('#hw-pwm-ch').value), freq: Number(q('#hw-pwm-freq').value), res: Number(q('#hw-pwm-res').value) },
            fanConfig: {
                startPercentMin:   Number(q('#hw-fan-start').value),
                comfortPercentMin: Number(q('#hw-fan-cmin').value),
                comfortPercentMax: Number(q('#hw-fan-cmax').value),
                hardPercentMax:    Number(q('#hw-fan-hmax').value)
            },
            pir: { enabled: q('#hw-pir-enabled').checked, pin: Number(q('#hw-pir-pin').value), debounceSec: Number(q('#hw-pir-debounce').value), holdSec: Number(q('#hw-pir-hold').value) },
            tempHum: { enabled: q('#hw-dht-enabled').checked, type: q('#hw-dht-type').value, pin: Number(q('#hw-dht-pin').value), intervalSec: Number(q('#hw-dht-int').value) },
            led: { pin: Number(q('#hw-led-pin').value), numPixels: Number(q('#hw-led-num').value), defaultBrightness: Number(q('#hw-led-bright').value) }
        }
    };

    try {
        await SNW.Api.patchSystem(patch);
        await SNW.Api.saveConfig();

// ======================================================
// [B-5] Accept-Encoding 파서 (RFC 7231 q-value 지원)
//  - 이전: indexOf("gzip") → "gzip;q=0" 오탐지
//  - 이후: 토큰별 파싱 + q 값 검사 (q=0은 거부, 없으면 1.0)
// ======================================================
static bool W10_acceptsGzip(AsyncWebServerRequest* r) {
    if (!r || !r->hasHeader("Accept-Encoding")) return false;

    String v_ae = r->getHeader("Accept-Encoding")->value();
    v_ae.toLowerCase();

    int v_start = 0;
    while (v_start < (int)v_ae.length()) {
        int v_end = v_ae.indexOf(',', v_start);
        if (v_end < 0) v_end = v_ae.length();

        String v_token = v_ae.substring(v_start, v_end);
        v_token.trim();

        // 토큰은 "<coding>" 또는 "<coding>;q=<float>"
        String v_coding = v_token;
        int    v_semi   = v_token.indexOf(';');
        if (v_semi >= 0) v_coding = v_token.substring(0, v_semi);
        v_coding.trim();

        // gzip 또는 * 매칭
        if (v_coding == "gzip" || v_coding == "*") {
            // q 값 확인
            int v_qpos = v_token.indexOf("q=");
            if (v_qpos < 0) return true;   // q 없으면 기본 1.0 → 허용
            float v_qval = v_token.substring(v_qpos + 2).toFloat();
            return v_qval > 0.0f;          // q=0 → 거부
        }

        v_start = v_end + 1;
    }
    return false;
}

        [](AsyncWebServerRequest* p_request) {
