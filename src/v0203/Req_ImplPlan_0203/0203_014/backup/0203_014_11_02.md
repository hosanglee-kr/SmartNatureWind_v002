

# 시작/운전/중단·재실행/종료 Trigger 관점 — 보완 및 재검토

요청하신 4차원 트리거 관점으로 현재 구현을 대조하고, **Gap → 보완 설계 → 영향 범위** 순서로 정리했습니다.

---

## Part 1. 사용자 정의 요약표

### ① 시작 Trigger (4종)

| # | Trigger | 사용자 표현 | 신규/기존 |
|:---:|---|---|:---:|
| T1 | Manual 일반모드 | "프리셋 눌러서 시작" | 기존 (MANUAL) |
| T2 | Schedule 요일/시작시간 | "예약된 시간에 자동 시작" | 기존 (SCHEDULE) |
| T3 | Manual 완전 Auto (스마트쾌적) | "AI가 알아서 켜줘" | **신규** |
| T4 | Manual 선택 Auto | "이 프로파일로, 풍량은 알아서" | **신규** |

### ② 운전 Mode (5종)

| # | Mode | 정의 | 신규/기존 |
|:---:|---|---|:---:|
| M1 | 고정 속도 | 일반 선풍기 (PWM %) | 기존 (FIXED) |
| M2 | 플레이리스트 | 사용자 Step 시퀀스 (파라미터 고정) | 기존 (PLAYLIST) |
| M3 | 프리셋 | WindDict 프리셋+스타일 (파라미터 고정) | 기존 (PRESET) |
| M4 | 완전 Auto | 시스템이 프리셋+스타일+강도 모두 결정 | **신규** |
| M5 | 선택 Auto | 사용자가 base 선택, 강도/스타일 자동 | **신규** |

### ③ 운전 중 중단/재실행 Trigger (3종)

| # | Trigger | 조건 | 재개 조건 |
|:---:|---|---|---|
| P1 | PIR | 사람 없음 (`holdSec` 경과) | 재실 감지 |
| P2 | 특정온도 이하 | `tempC < stopBelowC` | `tempC ≥ resumeAboveC` (히스테리시스) |
| P3 | 불쾌지수 이하 | `DI < stopBelowDI` | `DI ≥ resumeAboveDI` |

### ④ 종료 Trigger (3종)

| # | Trigger | 성격 |
|:---:|---|---|
| S1 | 사용자 중단 | 즉시 완전 종료 |
| S2 | Timer | N분 후 완전 종료 (ACK 필요) |
| S3 | Schedule 종료 | 시간 윈도우 벗어나면 종료 |

## Part 2. 현재 구현 대비 Gap 분석

### 2.1 시작 Trigger Gap

| 항목 | 현재 (`EN_CT10_trigger_t`) | Gap |
|---|---|:---:|
| MANUAL | 1 | ✅ |
| SCHEDULE | 2 | ✅ |
| AUTO_COMFORT | 3 (스위치만, 5분 후 자동) | ⚠️ **T3 사용자 즉시 시작 불가** |
| MANUAL_AUTO_FULL | — | 🔴 **T3 미지원** |
| MANUAL_AUTO_SELECT | — | 🔴 **T4 미지원** |

**핵심 문제**: 현재 `AUTO_COMFORT`는 `POST /comfort/auto`로 스위치만 켜면 **5분 후 자동 기동**만 가능. "지금 즉시 AI 모드로 시작"이 불가능.

### 2.2 운전 Mode Gap

| 항목 | 현재 (`EN_CT10_session_type_t`) | Gap |
|---|---|:---:|
| FIXED | 3 | ✅ |
| PLAYLIST | 1 | ✅ |
| PRESET | 2 | ✅ |
| AUTO_FULL | — | 🔴 **M4 미지원** |
| AUTO_SELECT | — | 🔴 **M5 미지원** |

**핵심 문제**:
- `_session.type`이 3종뿐 → AUTO 계열 표현 불가
- `_session.payload`에도 auto 계열 필드 없음

### 2.3 중단/재실행 Gap

| 항목 | 현재 | Gap |
|---|---|:---:|
| PIR (P1) | ✅ MOTION_BLOCKED + 자동 재개 | ✅ |
| 온도 히스테리시스 (P2) | ❌ OffTemp = **완전 종료**만 | 🔴 **재개 경로 없음** |
| 불쾌지수 히스테리시스 (P3) | ❌ 미지원 | 🔴 **미지원** |

**핵심 문제**:
- `checkAutoOff()`는 `true` 반환 시 **`onAutoOffTriggered()` → `AUTOOFF_STOPPED` (래치)**
- **일시정지 vs 종료가 구분되지 않음** → 온도 낮아지면 무조건 종료 후 ACK 필요
- 히스테리시스 (재개 임계) 없음 → 경계값 flapping 위험

### 2.4 종료 Trigger Gap

| 항목 | 현재 | Gap |
|---|---|:---:|
| 사용자 (S1) | ✅ `stopSession()` | ✅ |
| Timer (S2) | ✅ Timer / RuntimeAutoOff | ✅ |
| Schedule 종료 (S3) | ✅ `findActiveScheduleIndex()==-1` | ✅ |

**판정**: 종료 트리거는 **이미 완전 지원**. 재검토 불필요.

### 3.3 중단/재실행을 **Stop과 분리** (핵심 재설계)

**설계 원칙**: 
- **Pause**: 조건 해소 시 **자동 재개** (사용자 개입 불필요)
- **Stop**: 사용자 확인(ACK) 또는 새 세션 시작 전까지 **지속**

```cpp
// 신규: Pause Reason (자동 재개 대상)
typedef enum : uint8_t {
    EN_CT10_PAUSE_NONE            = 0,
    EN_CT10_PAUSE_MOTION          = 1,   // P1: PIR 부재
    EN_CT10_PAUSE_TEMP_LOW        = 2,   // P2: 온도 이하
    EN_CT10_PAUSE_DI_LOW          = 3,   // P3: 불쾌지수 이하
} EN_CT10_pause_t;

// Stop Reason (S1/S2/S3 종료 트리거로 한정 — 온/습도는 Pause로 완전 분리)
typedef enum : uint8_t {
    EN_CT10_REASON_NONE                = 0,
    // ... 기존 1~8 (State Manager 내부 상태 사유 유지) ...
    EN_CT10_REASON_AUTOOFF_TIMER       = 9,   // S2: Timer 만료 (Stop)
    EN_CT10_REASON_AUTOOFF_TIME        = 10,  // S3: Schedule 종료 (Stop)
    EN_CT10_REASON_USER_STOP           = 11,  // S1: 사용자 명시 중단
    // ※ 기존 EN_CT10_REASON_AUTOOFF_TEMP(11) 및 온/습도 Stop 사유 제거 → EN_CT10_pause_t(Pause)로 일원화
} EN_CT10_reason_t;
```

**FSM State 확장**:

```cpp
typedef enum : uint8_t {
    EN_CT10_STATE_IDLE            = 0,
    EN_CT10_STATE_OVERRIDE        = 1,
    EN_CT10_STATE_PROFILE_RUN     = 2,
    EN_CT10_STATE_SCHEDULE_RUN    = 3,
    EN_CT10_STATE_MOTION_BLOCKED  = 4,   // 기존: P1
    EN_CT10_STATE_AUTOOFF_STOPPED = 5,   // 기존: Stop 상태 (ACK 필요)
    EN_CT10_STATE_TIME_INVALID    = 6,
    EN_CT10_STATE_ENV_PAUSED      = 7,   // 신규: P2/P3 통합 (자동 재개)
} EN_CT10_state_t;
```

**`MOTION_BLOCKED`는 `ENV_PAUSED`로 일반화 통합**:
- `runCtx.pauseReason` 필드 추가로 어떤 pause인지 구분
- `MOTION_BLOCKED`는 `ENV_PAUSED + pauseReason=MOTION`의 alias

### 3.4 상태 전이 상세

#### 3.4.1 Pause 전이 (P1/P2/P3)

```
[RUNNING 상태] ──pause 조건 만족──► [ENV_PAUSED]
                 (PIR 없음 / tempC < stopBelowC / DI < stopBelowDI)
                 
[ENV_PAUSED] ──resume 조건 만족──► [이전 RUNNING 상태]
              (PIR 감지 / tempC ≥ resumeAboveC / DI ≥ resumeAboveDI)
```

**히스테리시스 강제** (flapping 방지):
- `resumeAboveC = stopBelowC + 0.5°C` (최소)
- `resumeAboveDI = stopBelowDI + 3` (최소)
- 스키마 검증에서 위반 시 리젝트

#### 3.4.2 Stop 전이 (S1/S2/S3)

```
[RUNNING] ──stop 조건──► [AUTOOFF_STOPPED]
                          (runCtx.reason = TIMER / TIME / USER_STOP)
                          _autoOffLatched = true
                          
[AUTOOFF_STOPPED] ──ACK (사용자 명시)──► [IDLE]
                    (POST /control/ack 또는 새 세션 시작)
```

**원칙**: 환경 조건(온도/습도/PIR)은 일체 Stop을 유발하지 않으며(Pause로만 동작), Stop은 오직 사용자 조작(S1) 또는 시간 규칙(S2 Timer, S3 Schedule 종료)에 의해서만 발생합니다.

#### 3.4.3 우선순위 (결정 매트릭스)

| 우선순위 | 조건 | 결과 |
|:---:|---|---|
| 1 | `overrideState.active` (수동 개입) | OVERRIDE |
| 2 | `_autoOffLatched` | AUTOOFF_STOPPED |
| 3 | Pause 조건 만족 (P1/P2/P3) | ENV_PAUSED |
| 4 | profile mode + profile 선택 | PROFILE_RUN |
| 5 | 스케줄 활성 | SCHEDULE_RUN |
| 6 | (기본) | IDLE |

### 3.5 통합 TriggerRule 스키마 (모든 모드 공통)

```cpp
typedef struct {
    // ═══════ S2: Timer (Stop) ═══════
    struct { bool enabled; uint32_t minutes; } timer;
    
    // ═══════ S3: OffTime (Stop) ═══════
    struct { bool enabled; char time[6]; } offTime;
    
    // ═══════ Pause: 온도 (자동 재개) ═══════
    struct {
        bool  enabled;
        float stopBelowC;
        float resumeAboveC;   // 히스테리시스 강제
    } tempPause;
    
    // ═══════ Pause: 불쾌지수 (자동 재개) ═══════
    struct {
        bool  enabled;
        float stopBelowDI;
        float resumeAboveDI;  // 히스테리시스 강제
    } diPause;
    
    // ═══════ Pause: PIR (자동 재개) ═══════
    struct { bool enabled; uint16_t holdSec; } pirPause;
    
    // ═══════ 스마트 쾌적 (M4/M5용) ═══════
    struct {
        bool     enabled;
        uint16_t intervalMin;   // 기본 5
        uint8_t  level;         // 0=off, 1=warn-only, 2=full
    } smartComfort;
} ST_A20_TriggerRule_t;
```

### 3.7 AUTO_FULL (M4) 상세 동작

```
[세션 시작: MANUAL_AUTO_FULL]
  │
  ├─ 초기 상태: 사용자 아무것도 선택 안 함
  │  → 5분 주기 DI/온도 평가
  │  → 추천 프리셋+스타일 자동 세팅
  │  → PRESET과 동일하게 재생
  │
  ├─ 실행 중 지속 모니터링 (5분 주기)
  │  → 환경 변화 감지 시 프리셋 자동 전환 (부드러운 crossfade)
  │
  ├─ 사용자가 프리셋 수동 선택 시
  │  → AUTO_FULL 자동 해제, MANUAL_PRESET으로 전환 (사용자 의도 우선)
  │
  └─ Pause/Stop은 공통 규칙 (P1/P2/P3/S1/S2/S3) 적용
```

### 3.8 AUTO_SELECT (M5) 상세 동작

```
[세션 시작: MANUAL_AUTO_SELECT + payload {baseType, baseValue}]
  │
  ├─ PRESET base인 경우: presetCode 고정, styleCode+intensity 자동
  │  → DI/온도에 따라 styleCode 선택 (SLEEP/BALANCE/ACTIVE)
  │  → 강도 = Preset.factors × SmartFactor(DI)
  │
  ├─ PLAYLIST base인 경우: 각 step의 styleCode+intensity 자동 오버라이드
  │  → step.presetCode 유지, styleCode만 DI 기반 재선택
  │
  ├─ 5분 주기 재평가
  │  → style/intensity 부드럽게 조정 (급격한 변화 방지)
  │
  └─ Pause/Stop은 공통 규칙 (P1/P2/P3/S1/S2/S3) 적용
```

### 1. 온도/습도 Stop 사유 제거 및 Pause(일시정지/재개) 일원화

* **배경 및 원칙**: 환경 조건(온도/DI/PIR)은 사용자 ACK가 필요한 **완전 종료(Stop)**가 아니라, 조건 해소 시 스스로 복귀하는 **일시정지(Pause / `ENV_PAUSED`)**로 역할을 명확히 분리하였습니다.
* **`EN_CT10_reason_t` (Stop Reason enum) 정리 (§3.3)**:
  * 아래 3종 제거 완료:
    * `EN_CT10_REASON_AUTOOFF_TEMP = 11` (온도 감기방지 Stop)
    * `EN_CT10_REASON_AUTOOFF_TEMP_HIGH = 12` (온도 과열 Stop)
    * `EN_CT10_REASON_AUTOOFF_HUMIDITY = 13` (습도 이탈 Stop)
  * Stop 사유는 종료 Trigger 3종으로만 한정:
    * `EN_CT10_REASON_AUTOOFF_TIMER = 9` (S2: 타이머 만료)
    * `EN_CT10_REASON_AUTOOFF_TIME = 10` (S3: 스케줄 종료)
    * `EN_CT10_REASON_USER_STOP = 11` (S1: 사용자 명시 중단)
* **스키마 간소화 (`ST_A20_TriggerRule_t`, §3.5)**:
  * Stop 계열 환경 멤버(`tempLowStop`, `tempHighStop`, `tempDeltaStop`, `humidityStop`) 4종 제거.
  * 환경 조건은 `tempPause`(히스테리시스 포함), `diPause`, `pirPause`만 유지.
* **UI 및 전이 규칙 반영 (§3.4.2, §4.4)**:
  * 규칙 편집기 모달의 ⏹ **완전 종료** 섹션에서 온도/습도 체크박스를 삭제하고 타이머/예약시각만 남김.
