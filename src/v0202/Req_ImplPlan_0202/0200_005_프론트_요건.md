## 1. 목적 및 설계 원칙

### 1.1 목적
- 백엔드 제공 기능(v0202 REST + v0202 ACK/시간 기준점)으로 완결되는 프론트엔드 요구사항 정의
- 4개 사용자 역할(L1~L4)에 따른 계층적 접근 권한 및 UI 복잡도 제어
- 페이지별 API/WS 매핑 확정 및 SPA 아키텍처 기반 L1 MVP 화면 설계

### 1.2 설계 원칙
1. **백엔드 계약 우선**: API/WS 미지원 기능은 "Gap"으로 명시하며 백엔드 계약을 우회하지 않는다.
2. **역할 기반 점진적 노출**: L1(초보)은 필수 조작만, L4(엔지니어)는 시스템 전체 제어권 노출.
3. **Stateless 클라이언트**: 인증은 `X-API-Key` 헤더 + WS 쿼리 파라미터만, 세션은 localStorage.
4. **WS 우선, REST 폴백**: 실시간은 WS 5채널 최우선, 연결 실패 시 지수 백오프 + REST 폴링.
5. **Save → Reload 순서 강제**: 설정 수정 시 반드시 `PATCH/POST` → `/config/save` → `/reload`.
6. **시간 필드 단위 준수**: `SPEC_0202.md §5.3` 규격 엄수 (epochms vs uptimeMs vs duration).
7. **SPA 단일 진입점**: 모든 페이지 이동은 해시 라우팅(`#/page`), 서버 요청 0건.

## 5. 페이지별 핵심 기능 요구사항

### 5.1 Dashboard
- **접근**: L1~L4 / **목적**: 상태 모니터링 + 즉시 팬 제어
- L1: 전원 On/Off, 10종 프리셋 원클릭, 0~100 강도 슬라이더, 상태/센서 요약
- L2+: 스타일·미세조정(variability, gustFreq, fanLimit, minFan), Override, 미니차트
- L3+: FSM state/reason 툴팁, AutoOff 상태 및 ACK 버튼
- L4: `pendingReload`, `lastReloadOk`, `control.system.{uptimeMs, epochNowMs}`
- *(상세 스펙은 §6 참조)*

### 5.2 Chart
- **접근**: L2~L4 / **목적**: WS 기반 실시간 물리 곡선
- 120초 다중선(wind/target/pwm), phase 배경, gust/thermal 마커
- L3+: 시간축 변경(5/30/120초), CSV export, L4 원본 필드
- **제약**: 샘플 최대 120개, SNTP sync 전 push 없음, full dump 10초 throttle

### 5.3 Schedule
- **접근**: L2~L4 / **목적**: 요일/시간 자동 제어
- 8 스케줄 목록 + 활성 토글, 세그먼트 시각화, L3+ CRUD + AutoOff/Motion
- **제약**: schId/segId 서버 발급(요청 무시), schNo/segNo 사용자 지정, 겹침 save 시만 검증

### 5.4 Profiles
- **접근**: L2~L4 / **목적**: 개인화 프로필
- 6 프로필 목록 + 원클릭 시작/정지(`/control/profile/{select,stop}`), L3+ CRUD, L4 일괄 patch
- **제약**: profileId 서버 발급, profileNo 사용자 지정

### 5.5 Sensors
- **접근**: L2~L4 / **목적**: DHT22 + PIR
- 온습도/PIR 실시간, holdSec 카운트다운, L3+ 설정 및 피드 테스트, L4 원시값
- **제약**: DHT22 2초 캐시, holdSec는 config 참조

### 5.6 Settings
- **접근**: L3~L4 / **목적**: 시스템 환경설정
- 로그레벨/WS채널/NTP/API Key, config export/save/reload
- L4: HW 핀맵, Fan Curve 4구간, Factory Reset, Reboot
- **제약**: patch는 메모리만 → save 필수, HW 핀맵 변경은 재부팅 필요

### 5.7 Network
- **접근**: L3~L4 / **목적**: Wi-Fi + NTP
- AP/STA/스캔/연결, NTP 3중 폴백, timeValid 표시
- L4: 재연결 이벤트 로그, TM10 내부 상태
- **제약**: 재연결 백그라운드 90초, NTP 콜백 기반, AP IP 192.168.4.1 고정

### 5.8 Logs
- **접근**: L3~L4 / **목적**: 링버퍼 조회 + 실시간 스트림
- 최대 256개, 레벨 필터, L4 모듈별 검색 + JSON export
- **제약**: 최대 256개, 메시지 128자

### 5.9 Diagnostics
- **접근**: L4 / **목적**: FSM/NVS/Heap 진단
- Heap/FS, FSM 상태코드, AutoOff 3종, NVS 통계, Dirty Flag, API 버전 4종
- **제약**: 모든 데이터가 `/state`에 포함

### 5.10 Firmware
- **접근**: L4 / **목적**: OTA + 에셋 관리
- SemVer 확인, OTA multipart 업로드, LittleFS 파일 업로드
- **제약**: OTA 후 자동 재시작, 파일 확장자별 자동 분류, API Key 필수

### 5.11 AI
- **접근**: L4 / **목적**: Gemini 자연어 제어
- 진단/프리셋 추천/스케줄 생성, rate limit 3초
- **제약**: 요청 8KB/응답 4KB, Gemini API Key 필요

### 5.12 Info
- **접근**: L1~L4 / **목적**: 버전 + 시스템 정보
- API 버전 4종, Heap/FS, 매뉴얼 링크

## 6. Dashboard 메인 제어 상세 스펙

### 6.1 사용자 흐름

**L1 흐름**:
```text
[부팅/접속] → GET /state (초기) → WS 3채널 연결
        │
        ├─→ [전원 On/Off]   → POST /control/override/fixed?forever=true / /override/clear
        ├─→ [프리셋 선택]   → POST /simulation (presetCode)
        └─→ [강도 조절]     → POST /simulation (intensity, 디바운스 300ms)
                                    ↓
                        WS /ws/state (800ms) 실시간 반영
```

**L2~L4 확장**:
```text
[스타일/변수 조정]  → POST /simulation (styleCode/variability/gustFreq/fanLimit/minFan)
[정밀 Override]     → POST /control/override/{fixed, preset, clear}
[미니차트]          → WS /ws/chart (diffOnly 최신 1개)
[FSM 진단]          → GET /state (.control.state/reason/runSource)
[ACK (v0202)]       → POST /control/ack  ← AutoOff 해제
```

### 6.5 UX 세부 규칙

**6.5.1 초기 로딩**:
1. (L4) `GET /version`
2. `GET /state` 즉시 렌더
3. WS 병렬: `/ws/state`, `/ws/summary`, `/ws/metrics`
4. (L2+) `/ws/chart`
5. (L3+) `/ws/log`

**6.5.2 에러 처리**:

| 에러 | 원인 | 대응 |
|---|---|---|
| `401` | API Key 불일치 | 재입력 모달 |
| `409` | Reload 중복 | "재로드 진행 중" 토스트 |
| `500` | 부팅 미완료 | 10초 후 자동 재시도 |
| WS 끊김 | 네트워크/재부팅 | 헤더 "오프라인" + 지수 백오프 |
| `updated:false` | 무변경/검증 실패 | "변경 없음 또는 유효하지 않음" |

**6.5.3 휘발성 제어 원칙**:
- Dashboard 조작은 **휘발성** (`POST /simulation`, `/control/*`)
- Dashboard에서 자동 `/config/save` 호출 **금지** (플래시 마모 방지)
- 영구 보존은 명시적 "설정 저장" 버튼(Settings)에서만

**6.5.4 AutoOff 경고**:
- `control.sensor.tempC` ≥ `control.autoOffRt.offTemp` → "과냉 방지 정지 임박" 배지
- `control.autoOffRt.timerArmed` → "타이머 진행 중" 표시

**6.5.5 시간 필드 규격 (SPEC_0202.md §5.3 준수)**:
- **금지**: `new Date(control.lastDecisionMs)` — millis를 epochms로 오해
- **금지**: `Date.now() - control.event.holdUntilMs` — 클라이언트 epoch와 서버 millis 기준점 혼합
- **허용**: `control.event.holdRemainMs` 그대로 사용 (백엔드 계산 남은 ms)
- **허용**: `override.remainSec` 그대로 사용 (초 단위)
- **절대시각 변환 (v0202)**: `serverBootEpochMs = control.system.epochNowMs - control.system.uptimeMs` → `fieldEpochMs = serverBootEpochMs + fieldMs`
- `control.system.epochNowMs == 0`이면 절대 시각 표시 금지, 상대 시간만

## 11. 계약 준수 사항 및 개발 가이드라인

1. **API 인증**: REST `X-API-Key` 헤더, WS `?apiKey=...` 쿼리 필수.
2. **Save → Reload 순서**: `/system`, `/motion`, `/wifi/config` patch 후 반드시 `/config/save` → `/reload`.
3. **Reload 폴링**: `control.pendingReload` true→false 관측 후 `control.lastReloadOk` 확인.
4. **시간 필드 규격** (`SPEC_0202.md §5.3`):
   - `sim.chart[].t`만 epochms
   - `*Ms`는 **uptimeMs (부팅 후 경과)** → 절대 시각 표시 금지, 상대 시간만
   - `override.remainSec`, `*RemainMs`는 계산값 그대로 사용
   - 절대 시각 변환은 v0202 `control.system.{uptimeMs, epochNowMs}` 활용
5. **에러 응답**: `{"error":"<reason>"}` 표준 파싱 → 토스트/모달.
6. **AutoOff ACK**: v0202 `POST /control/ack`, v0202 폴백 Override 재시작/Profile 재개.
7. **WS 재연결**: exponential backoff(1→30초), 3회 실패 시 REST 폴링 2초.
8. **SPA 라우팅**: 모든 페이지 이동은 해시(`#/page`). 서버 요청 금지.
9. **페이지 클래스 계약**: `mount()` / `unmount()` 필수 구현. Store 구독은 `unmount()`에서 해제.
10. **번들 예산**: JS + CSS + HTML 총 gzip < 60 KB 유지.
