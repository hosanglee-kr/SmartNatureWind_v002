## 1. 시스템 개요
- 프로젝트명: Smart Nature Wind (Standalone Firmware)

- 프레임워크: PlatformIO + Arduino (C++17)
- 파일시스템: LittleFS (`/html_v3`, `/json`)
- 아키텍처: Standalone 풀스택 (REST + WebSocket + Web UI + 물리 시뮬레이터)

## 5. 통신 사양

### 5.1 설정 재적용(reload) 정책 — I-2 반영

**핵심 원칙**: `POST /api/v001/reload` 는 **디스크 상태로 전면 교체**한다.  
메모리 상의 in-flight patch는 **소실**된다.

**동작 흐름 (F-05 반영 후)**
```
T-async: POST /reload  → 202 {"result":"queued", "note":"..."}  (즉시 응답)
T-loop : 다음 cycle    → reloadAll() 실행:
                          1. C10::loadAll(디스크 → v_new)
                          2. g_A20_config_root 스왑 (v_new ↔ v_old)
                          3. CT10 멤버 리셋
                          4. v_old → queuePendingFree (3s 후 free)
```

**사용자 유의사항 (필수)**
1. `POST /api/v001/motion`, `/system`, `/wifi/config` 등은 **메모리 patch만** 수행한다.
   - `saveDirtyConfigs()`가 호출되는 경로(WiFi route 등)는 예외.
2. reload 이전에 **in-memory patch를 디스크에 저장**하려면 **반드시** `POST /api/v001/config/save` 를 먼저 호출.
3. reload 완료 시점 확인:
   - **폴링**: `GET /api/v001/state` → `control.pendingReload` 필드가 `false` 로 전환됨.
   - **WebSocket**: `/ws/state` 브로드캐스트에서 `control.pendingReload` 변화 관찰.

**실패 시 재요청**
- `reloadAll()` 실패 시 `_pendingReload`는 이미 소비된 상태 → 다음 reload 요청 필요.
- `GET /api/v001/state` 의 `control.pendingReload` 는 `false` 로 남으나, reload 실패 로그(`[A00] Pending reload done (ok=0)`)로 판별.

**연속 요청 처리**
- pending 상태에서 재요청 시 **409 Conflict** 반환 (`{"error":"reload already pending"}`).

**금지 패턴**
```
POST /motion (patch)   ─┐
                         ├─ (100ms 이내) → POST /reload   ← patch가 조용히 소실됨
                        ─┘
```
→ 반드시 `POST /config/save` → `POST /reload` 순서 유지.

## 6. 코딩·정책 컨벤션
- JSON: ArduinoJson v7 전용, `JsonDocument` 단일 타입, containsKey/createNested* 금지
- 문자열: `memset + strlcpy`, `A40_ComFunc::copyStr2Buffer_safe` 강제
- 네이밍: `G_`, `g_`, `CL_`, `ST_`, `EN_`, `T_`, `_t`, `v_`, `p_`, `s_`
- 로깅: `CL_D10_Logger::log(EN_L10_LOG_*, ...)`, A40_LOGE/W/I/D 매크로
- 주석: 소스 선두 "구현 규칙·네이밍 규칙" 블록 유지
