## 1. 설계 철학 (기존 구조의 문제 → 해결)

### 1.1 기존 구조의 3대 문제

| 문제 | 현상 | 영향 |
|---|---|---|
| **중복 로드** | 대시보드 번들(`P010_bundle`)에 common 포함. 서브페이지는 common 재구현 또는 미사용 | 서브페이지 첫 진입 시 common 재다운로드 또는 누락 |
| **번들 파편화** | `P010_main_*` 8개 분할의 근거가 "로드 순서"뿐 (gzip 후 21.9KB는 이미 작음) | 유지보수는 좋지만 개발 흐름이 파일 이동에 최적화되지 않음 |
| **페이지별 진입점 상이** | HTML마다 다른 `<script>` 태그 세트 | 빌드 파이프라인이 HTML별로 다르게 동작해야 함 |

### 1.2 v2.0 핵심 결정

| 결정 | 근거 |
|---|---|
| **단일 번들 통합** (`P010_bundle_0202.js`) | 모든 HTML이 동일 스크립트 로드. 브라우저 캐시로 2번째 페이지부터 0 HTTP 요청 |
| **`data-page` 디스패치** | `<body data-page="dashboard">` → 앱 부트스트랩이 해당 페이지 모듈만 활성화 |
| **계층별 00~999 넘버링** | 파일명 정렬 = 로드 순서. `pio_gzip_0202.py`는 정렬 후 단순 concat |
| **개발 파일 20개 / 배포 파일 1개** | 개발 중 유지보수성, 배포 시 단일 요청 |
| **상수/설정/i18n 최상위** | 모든 계층이 참조. 다른 어떤 파일도 이들을 참조하지 않음 (순환 차단) |

### 1.3 런타임 성능 예측

| 시나리오 | 기존 (8파일+분리) | v2.0 (단일 번들) |
|---|---|---|
| Dashboard 첫 방문 | bundle 1요청 (21.9KB gz) | bundle 1요청 (**~31KB gz**) |
| Chart 첫 방문 | bundle 1 + chart.js 1 = **2요청** | bundle 1 = **1요청** (HTML만 새로) |
| Chart 2번째 방문 | bundle + chart.js 캐시 | **0 JS 요청** (bundle 캐시) |
| 전체 세션 (5페이지) | ~10 HTTP | **~6 HTTP** (-40%) |
| Common 중복 로드 | 서브페이지마다 재다운로드 위험 | **0 (한 번만)** |

**LWIP TCP PCB 압박 40% 감소** — `BUDGET_0202.md` §7.2 정합 개선.

## 3. 단일 번들 전략

### 3.1 `pio_gzip_0202.py` 변경 (최소)

```python
# glob으로 소스 자동 수집 (파일 추가 시 리스트 수정 불필요)
MAIN_BUNDLE_PATTERN = "*.js"       # html_v3/*.js 전량
MAIN_BUNDLE_OUTPUT_NAME = "P010_bundle_0202.js"

def collect_js_files(src_dir):
    # 자동으로 정렬 (000~999 넘버링이 로드 순서 보장)
    files = sorted(src_dir.glob(MAIN_BUNDLE_PATTERN))
    return [f.name for f in files if f.name != MAIN_BUNDLE_OUTPUT_NAME]
```

### 3.2 HTML 변경 (모두 동일)

모든 HTML이 다음 패턴:

```html
<body data-page="dashboard">
    <!-- ... 컨텐츠 ... -->
    <script src="./P010_bundle_0202.js" defer></script>
</body>
```

**`pio_gzip_0202.py`의 `process_main_html` 로직 삭제** — 더 이상 script 태그 치환 불필요 (모두 이미 동일).

### 3.3 `999.app.js` (부트스트랩)

```javascript
(function (SNW) {
    'use strict';

    const PAGE_INIT = {
        dashboard: () => new SNW.Page.Dashboard().init(),
        chart:     () => new SNW.Page.Chart().init(),
        schedule:  () => new SNW.Page.Schedule().init(),
        profiles:  () => new SNW.Page.Profiles().init(),
        settings:  () => new SNW.Page.Settings().init(),
        info:      () => new SNW.Page.Info().init()
    };

    document.addEventListener('DOMContentLoaded', async () => {
        SNW.I18n.applyTo(document);
        SNW.LevelUtil.applyTo(document.body);
        SNW.StoreBridge.start();
        SNW.WsManager.initByLevel();
        SNW.Router.init();

        const page = document.body.dataset.page || '';
        const init = PAGE_INIT[page];
        if (!init) {
            SNW.LogUtil.warn(`페이지 초기화 미정의: data-page="${page}"`);
            return;
        }
        try { await init(); }
        catch (e) { SNW.ErrorHandler.handle(e, `page.${page}`); }
    });

})(window.SNW);
```

## 5. 예상 번들 크기

| 카테고리 | 파일 수 | Raw | Gzip |
|---|---:|---:|---:|
| Layer 0 (기반) | 3 | 21 KB | **6.2 KB** |
| Layer 1 (인프라) | 4 | 12 KB | **3.5 KB** |
| Layer 2 (서비스) | 4 | 16 KB | **4.8 KB** |
| Layer 3 (UI) | 4 | 22 KB | **6.5 KB** |
| Layer 4 (페이지) | 11 | 26 KB | **7.8 KB** |
| Layer 5 (부트) | 1 | 2 KB | **0.6 KB** |
| **합계** | **27 파일** | **~99 KB** | **~29.4 KB** |

**결론**:
- gzip 29.4KB → **현재 21.9KB 대비 +7.5KB** (i18n/const/config 신규 + 미사용 페이지 skeleton)
- 전체 웹 에셋 gzip ~120KB → **114KB 예산 내** 유지
- **HTTP 요청 수 40% 감소** + **서브페이지 재방문 0 JS 요청** 효과 압도

# 4) process_all_assets()에서 js 제외 (bundle만 배포, 개별 js 제외)
def process_all_assets(src_dir, dst_dir):
