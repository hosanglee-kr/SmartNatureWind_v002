임베디드 실시간 멀티태스킹 환경(FreeRTOS)의 **계약 기반 설계(Contract-Based Design)** 문서 체계를 이론적 배경, 파일별 명세, 상호 정합성, 실무 워크플로 및 검증 기준 순으로 통합 정리함.
### 1. 이론적 배경 및 산업계 표준 접점
 * **계약 기반 설계 (Contract-Based Design / CBD)**
   * Meyer의 "Design by Contract" 개념을 컴포넌트 및 태스크 간 인터페이스로 확장한 방법론임.
   * 모듈 간 전제 조건(Pre-conditions), 보증 조건(Post-conditions), 불변식(Invariants)을 사전 명세하여 멀티코어 및 멀티스레드 환경의 비결정성(Non-determinism)을 통제함.
   * 자동차 전장 표준(AUTOSAR) 및 모델 기반 아키텍처(EAST-ADL, AADL)의 가상 버스·인터페이스 계약 모델과 직결되어 오류 전파를 차단함.
 * **실시간 실행 예산 프레임워크 (Execution Time Budgeting & WCET)**
   * 실시간 스케줄링 이론(RMS, EDF)의 핵심 전제인 최악 실행 시간(WCET) 보장을 위해 항공우주(DO-178C) 및 전장(ISO 26262)의 예산 명세 기법을 경량화함.
   * RTOS 주기별 태스크의 데드라인, 실행 마진, 스택 고수위(High-watermark)를 사전에 할당하고 런타임에 감시함.
### 2. 5대 핵심 문서의 역할 및 작성 방법론
 * **SPEC.md (상위 사양 및 단일 진실 공급원)**
   * **이론적 기반**: 단일 진실 공급원(SSOT), 시스템 엔지니어링 V-모델.
   * **핵심 역할 및 작성 기준**:
     * 시스템 전체 요구사항, 하드웨어 핀맵, 통신 프로토콜, 데이터 스키마(JSON v5 등), 상수 테이블의 기준점을 제공함.
     * SafeBoot/OTA Guard 등 안전 메커니즘과 소스코드 명명 규칙(G_, CL_, ST_, EN_ 등) 및 라이브러리 정책(ArduinoJson v7 등)을 총괄함.
     * 하위 4개 계약 문서가 준수해야 하는 상위 요구사항과 전체 개정 이력(Revision History)을 동기화하여 관리함.
 * **FLOW.md (데이터 흐름 및 파이프라인 명세)**
   * **이론적 기반**: 데이터 흐름 지향 아키텍처(Data-flow Architecture), 방어적 프로그래밍(Defensive Programming).
   * **핵심 역할 및 작성 기준**:
     * **직렬/병렬 파이프라인**: 센서 입력 → 노이즈 제거 → 적응형 필터 → DPI 가속 → 축 스냅 → 최종 게이트로 이어지는 데이터 변환 경로를 단방향 순차 흐름(Mermaid 순서도 등)으로 고정함.
     * **시퀀스 흐름**: 프로파일 전환, Wake/Sleep, OTA 게이트 등 시간 축에 따른 처리 순서를 명세함.
     * **선제적 가드(Early Guard)**: NaN, 바이어스 오염, 통신 단절 감지 시 즉시 틱(Tick)을 스킵하고 버스를 복구하는 조기 탈출(Early Return) 및 폴백(Fallback) 경로를 시각화함.
 * **CONTRACT.md (동시성 경계 및 API 계약)**
   * **이론적 기반**: 상호 배제(Mutual Exclusion), 비동기 메시지 큐 통신 패턴, 단방향 의존성 규칙.
   * **핵심 역할 및 작성 기준**:
     * **소유권 분리(Task Ownership)**: 특정 하드웨어 인터페이스(BLE HID, I2C 센서 드라이버 등)를 단일 태스크에 독점 배정하고, 타 태스크의 직접 호출을 금지하며 큐 기반 요청으로 일원화함.
     * **함수 계약 명세**: 각 함수별 허용 호출자(Caller), 실행 컨텍스트(Context), 부수효과(Side-effects), 예외 처리를 정의함.
     * **논블로킹 강제(Non-blocking Enqueue)**: 센서 수집 및 통신 주기 지연을 방지하기 위해 큐 송신 타임아웃을 timeout=0으로 고정하고 오버플로 시 Drop 정책을 사전 정의함.
     * **위임 패턴(Delegation)**: 인터럽트나 타 태스크에서 발생하는 긴급 상태 변경은 직접 호출하지 않고 volatile 플래그를 통한 지연 실행으로 위임함.
 * **STATE.md (상태 머신 및 단일 쓰기 원칙)**
   * **이론적 기반**: 유한 상태 머신(FSM), 단일 기록자 원칙(Single-Writer Principle), 원자성(Atomicity).
   * **핵심 역할 및 작성 기준**:
     * **소유권 매트릭스**: Lock-free 성능을 위해 모든 상태 변수마다 쓰기 권한(Writer)을 오직 1개의 태스크에만 부여하고, 다중 읽기(Reader) 시 volatile 메모리 배리어 또는 뮤텍스 보호 구간을 명확히 지정함.
     * **FSM 명세**: Click-Freeze, Snap-to-Axis, Macro, Power FSM 등 복합 로직의 진입 조건(Entry), 이탈 조건(Exit), 상태 전이 간 부수효과(Action)를 분리 명시하여 레이스 컨디션을 차단함.
     * **취소/대체(Abort/Replace) 토큰**: 비동기 매크로나 시퀀서 동작 중 모드 변경, 연결 해제 등 상태 전환 시 즉각적이고 안전한 중단을 보장하는 단조 증가 토큰 체계를 운용함.
     * **위임 플래그 라이프사이클**: 비동기 위임 플래그의 소비 순서를 반드시 Read → Clear → Execute 순으로 고정하여 중복 진입을 방지함.
 * **BUDGET.md (시간 및 시스템 자원 배정)**
   * **이론적 기반**: 고정 우선순위 선점형 스케줄링(Fixed-Priority Preemptive Scheduling), 스택 프로파일링.
   * **핵심 역할 및 작성 기준**:
     * **태스크 자원 배정**: 각 FreeRTOS 태스크의 CPU Core 할당, 우선순위, 실행 주기(Period), 스택 크기, 최악 실행 시간(WCET), 지터 마진을 명시하여 스케줄러 오버런을 수학적으로 검증함.
     * **잠재적 블로킹 식별**: 플래시 파일시스템 I/O, I2C 버스 리셋, 캘리브레이션 루프, LED 제어(_led.suspend() 등) 등 주기를 초과할 수 있는 블로킹 지점의 지연 상한과 완화책(비동기 상태머신 전환, 타임아웃 제한 등)을 기록함.
     * **관측성(Observability) 메트릭**: 런타임 성능 지표(dt_max, overrun_count, 스택 여유 공간) 수집 기준과 데드라인 위반 감시 조건을 정의함.
### 3. 문서 간 추적성(Traceability) 및 데이터 정합성 체계
 * **설계 전파 순서**: SPEC.md(사양 정의) → FLOW.md(처리 순서 배치) → CONTRACT.md(호출 경계 및 큐 정의) → STATE.md(상태 변수 및 소유권 할당) → BUDGET.md(실행 시간 영향 산출) 순으로 하위 문서에 요구사항이 전파됨.
 * **핵심 동기화 지점**:
   * **큐 및 구조체**: CONTRACT.md의 큐 용량/타입 ↔ BUDGET.md의 큐 정책 ↔ SPEC.md의 데이터 구조체 명세 일치.
   * **블로킹 지연 한계**: CONTRACT.md의 실행 컨텍스트 제한 ↔ BUDGET.md의 함수별 최대 블로킹 수치 일치.
   * **비동기 위임 경로**: STATE.md의 위임 플래그 목록 ↔ CONTRACT.md의 공유 변수 동기화 규칙 ↔ FLOW.md의 시퀀스 다이어그램 일치.
### 4. 신규 기능 도입 시 단계별 작성 워크플로
 * **1단계 (SPEC.md)**: 신규 기능의 상수, 유효 범위, 기본값, 동작 조건을 추가하고 명명 규칙 및 라이브러리 정책 준수 여부를 기재함.
 * **2단계 (FLOW.md)**: 태스크 루프 내 배치 순서를 확정하여 데이터 흐름도 및 시퀀스 다이어그램을 작성하고, 센서 이상치(NaN, 통신 오류) 발생 시 조기 탈출 경로를 명시함.
 * **3단계 (CONTRACT.md)**: 실행 태스크 컨텍스트를 고정하고 타 태스크 직접 호출을 차단함. 통신 특성에 맞게 수단(단방향 덮어쓰기 xQueueOverwrite, 비동기 명령 xQueueSend(timeout=0), 단순 트리거 volatile bool 위임)을 선정하며, 재진입 필요 시 Recursive Mutex와 pdMS_TO_TICKS 타임아웃을 설정함.
 * **4단계 (STATE.md)**: 상태 변수별 단독 Writer를 1개로 지정함. FSM 포함 시 상태별 진입·이탈 조건 및 출력값을 정의하고, 중단(Abort)·강제 리셋 시 전이 규칙과 위임 플래그 소비 순서(Read → Clear → Execute)를 확정함.
 * **5단계 (BUDGET.md)**: 해당 태스크 주기 내 WCET를 측정·기재하고, 내부 delay()나 Busy-wait 존재 시 타이머 기반 비동기 상태머신으로 리팩터링함. 오버런 감시 조건과 에러 카운터를 반영함.
### 5. 코드 리뷰 및 정적·동적 검증 체크리스트
 * **태스크 침범 검사 (CONTRACT.md 기준)**
   * Web Task 등에서 HID나 하드웨어 제어 함수를 직접 호출하지 않고 전용 큐(_qHidCmd 등)나 위임 플래그를 경유하는지 확인함.
   * 특정 태스크 전용 함수(_handleSpecial, I2C 초기화 등)가 타 태스크 컨텍스트에서 호출되는지 점검함.
 * **블로킹 유발 검사 (BUDGET.md 기준)**
   * 주기적 태스크(sensorTask, commTask, ledTask 등) 내부 큐 송신(xQueueSend)에 0이 아닌 타임아웃이 설정되어 있는지 전수 검사함.
   * 루프를 점유하는 긴 지연 로직 존재 여부를 확인함.
 * **상태 경합 검사 (STATE.md 기준)**
   * 뮤텍스 보호 없이 2개 이상의 태스크에서 쓰기를 수행하는 다중 Writer 공유 변수를 식별함.
   * 위임 플래그 처리 시 클리어 시점(flag = false)이 로직 실행 완료 후로 밀려 중복 실행을 유발하는지 점검함.
 * **문서 형상 동기화 검사**
   * 코드 수정 시 변경 내역을 5개 양식 파일 전체의 개정 이력(Revision History) 및 헤더 메타데이터에 동일한 버전과 날짜로 동시 반영함.

## 계약 문서의 변경 이력을 효율적으로 관리하기 위한 체계
### 1. 문서 구조 분리 전략 (본문 vs 이력 분리)
 * **문서 본문과 상세 이력 분리**
   * 5개 계약 문서 상단에는 **현재 기준 버전, 기준 커밋 해시(Git SHA), 최종 수정일, 영향 범위 요약**만 유지함.
   * 상세 변경 내역은 문서 하단 경량 요약 또는 별도 CHANGELOG_CONTRACTS.md / Git 커밋 로그로 이원화하여 본문 가독성 및 토큰 효율성을 확보함.
 * **단일 기준 버전(Global Revision ID) 동기화**
   * 개별 파일마다 독립적인 버전 번호를 부여하지 않고, 기능·아키텍처 변경 단위로 공통 리비전 ID(예: REV-014)를 부여함.
   * 변경이 발생한 계약 문서 그룹에 동일한 리비전 ID와 날짜를 일괄 기입하여 문서 간 시점 불일치를 차단함.
### 2. Git 기반 변경 이력 자동화 및 추적성 확보
 * **커밋 메시지 규약 강제**
   * 커밋 헤더에 계약 영향 태그와 리비전 ID를 포함함(예: feat(contract/REV-014): add axis snap stage and queue contract).
   * 코드 변경 커밋과 계약 문서 갱신 커밋을 동일 작업 단위로 묶어 **코드 ↔ 계약 ↔ Git 이력** 간 양방향 추적성을 확보함.
 * **경로 기반 변경 감지(Path Filter)**
   * PR 또는 커밋 검증 단계에서 펌웨어 소스(src/, include/) 변경 시 연관된 계약 문서(docs/contracts/*.md) 수정 여부를 자동 점검함.
   * SPEC.md나 CONTRACT.md 수정 시 하위 연관 문서(STATE.md, BUDGET.md, FLOW.md)의 정합성 검토 누락을 방지함.
### 3. 변경 유형별 갱신 범위 최소화 규칙
 * **단순 상수·파라미터 조정 (경미 변경)**
   * SPEC.md 상수/기본값 및 BUDGET.md 수치만 갱신하고, 구조적 흐름이나 동시성 변경이 없으면 FLOW.md, CONTRACT.md, STATE.md 본문 재작성을 생략함.
 * **파이프라인 순서·예외 경로 변경**
   * FLOW.md 순서도·시퀀스를 갱신하고, 단계 추가/삭제로 인한 실행 시간 변화가 있을 때만 BUDGET.md를 함께 수정함.
 * **태스크 경계·큐·공유 상태 변경 (핵심 계약 변경)**
   * CONTRACT.md(호출자·큐·위임)와 STATE.md(단독 Writer·FSM·토큰)를 우선 갱신한 뒤, FLOW.md 시퀀스와 BUDGET.md WCET·블로킹 수치를 연쇄 검증함.
### 4. 변경 이력 항목 표준 기록 요소
 * **식별 및 시점**: 리비전 ID, 날짜, 작성자/에이전트 식별자, 연관 커밋/PR 번호.
 * **변경 대상 문서 및 섹션**: 수정된 파일명과 대상 항목(예: CONTRACT.md 큐 계약, STATE.md FSM 전이).
 * **변경 사유 및 핵심 요약**: 기능 추가·결함 수정·성능 최적화 등 변경 배경과 핵심 delta를 한 줄 단위로 간결히 기록함.
 * **파급 영향(Impact)**: 영향받는 태스크, 공유 변수, 큐 용량, WCET/스택 마진 변동 여부 명시.
### 5. 드리프트(Drift) 방지 및 주기적 정합성 점검
 * **문서-코드 드리프트 점검 기준**
   * 신규 큐 생성, 뮤텍스/플래그 추가, 주기적 태스크 내 블로킹 호출 변경 발생 시 계약 문서 미반영 여부를 리뷰 필수 항목으로 고정함.
 * **마일스톤 단위 스냅샷 및 정리**
   * 주요 릴리스 또는 아키텍처 리팩터링 마일스톤마다 5개 계약 문서의 기준선(Baseline)을 태그(v0203-contract-base 등)로 고정함.
