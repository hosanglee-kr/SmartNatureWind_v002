§2. 아키텍처 결정 사항 (ADR)

ADR-1: Session Engine — 위임 모델 채택

현상: startSession()은 _session 상태만 갱신. FSM은 이를 무시.

결정: startSession/pauseSession/resumeSession/stopSession을 기존 제어 메서드에 위임하고, _session은 API 응답용 미러로 유지.

```cpp
// CL_CT10_ControlManager::startSession() 재설계 (의사코드)
bool startSession(type, trigger, payload) {
    CL_A40_MutexGuard v_guard(s_stateMutex, ...);
    if (!v_guard.isAcquired()) return false;

    // ① 기존 제어 경로 위임 (실제 실행)
    bool v_ok = false;
    switch (type) {
        case PLAYLIST:
            v_ok = instance().startUserProfileByNo(payload.profileId);
            if (v_ok) instance().setProfileMode(true);  // 스케줄 배제
            break;
        case PRESET:
            instance().startOverridePreset(payload.presetCode, payload.styleCode,
                                           &payload.override, 0, true);
            v_ok = true;
            break;
        case FIXED:
            instance().startOverrideFixed(payload.percent, 0, true);
            v_ok = true;
            break;
    }
    if (!v_ok) return false;

    // ② API 응답용 mirror 세팅
    memset(&_session, 0, sizeof(_session));
    _session.type = type;
    _session.trigger = trigger;
    _session.state = EN_SESSION_ACTIVE;
    _session.startedAt = millis();
    // payload 복사...
    return true;
}

bool pauseSession() {
    // overrideState.active 검사 후 sim.stop + pwm 0
    _session.state = EN_SESSION_PAUSED;
    _session.pausedAtMs = millis();
    ...// overrideState 일시 해제
}
```

근거:

· 기존 startUserProfileByNo, startOverridePreset, startOverrideFixed는 검증된 실행 경로 (PIR·AutoOff·Motion 등 통합 처리)
· _session은 API 노출 계층(exportStateJson)만 사용 → FSM 무영향
· 회귀 위험 최소

파급: exportStateJson_v02 session 블록이 _session(mirror) 기반으로 남음. FSM의 runCtx와 이중화되나, mirror는 export 전용임을 CONTRACT에 명시.

void _internalInitAndTake(TickType_t p_timeout) {
    if (!_mutexPtr) return;

    // Fast path
    if (*_mutexPtr != nullptr) {
        if (xSemaphoreTakeRecursive(*_mutexPtr, p_timeout) == pdTRUE) _acquired = true;
        return;
    }

    // [신규] critical section 밖에서 생성 (heap alloc 안전)
    SemaphoreHandle_t v_newMutex = xSemaphoreCreateRecursiveMutex();
    if (!v_newMutex) {
        CL_D10_Logger::log(EN_L10_LOG_ERROR, "[A40] CreateRecursiveMutex failed");
        return;
    }

    // Double-check: 다른 task가 먼저 생성했을 수 있음
    static portMUX_TYPE s_initMux = portMUX_INITIALIZER_UNLOCKED;
    bool v_owned = false;
    portENTER_CRITICAL(&s_initMux);
    if (*_mutexPtr == nullptr) {
        *_mutexPtr = v_newMutex;
        v_owned = true;
    }
    portEXIT_CRITICAL(&s_initMux);

    if (!v_owned) {
        vSemaphoreDelete(v_newMutex);   // 다른 task가 이미 생성 → 폐기
    }

    if (*_mutexPtr && xSemaphoreTakeRecursive(*_mutexPtr, p_timeout) == pdTRUE) {
        _acquired = true;
    }
}
