사용자 시나리오 관점 — 메뉴·화면 통폐합 및 기능 보강 검토

앞서 도출한 7개 시나리오(수면/사무실/독서실/거실/운동 후/유아/반려동물)와 두 가지 신규 요구사항을 반영해 재설계했습니다.

신규 요구사항:
① 모든 작동 모드(PRESET/FIXED/PLAYLIST/SCHEDULE)에서 스케줄·타이머·온습도·불쾌지수·온도변화량·PIR 설정 가능
② 프로파일에서도 스마트 쾌적(Comfort 자동) 설정 가능

1. 현재 메뉴 진단 — 14개 라우트의 문제

# 메뉴 레벨 사용 빈도 진단
1 대시보드 L1 매일 3탭 파편화, 원터치 시나리오 없음
2 자동화 L2 주 1~2회 4탭 과다 (Studio/Playlist/스케줄/타이머)

6 모니터 L2 월 1회 차트/로그와 중복
7 설정 L2 월 1회 네트워크/펌웨어/진단 별도
8 네트워크 L3 초기 1회 설정과 분리
9 windprofile L3 거의 안 씀 Studio와 역할 중복

· Comfort 자동 모드가 대시보드 환경 탭에만 존재
· 프로파일 편집기가 Studio(작곡)와 분리 → 스마트 쾌적 진입 불가

3. 공통 트리거 모델 — 핵심 요구 구현

3.1 문제 정의

현재 ST_A20_AutoOff_t는 프로파일 내부에만 존재:

```cpp
// 현재 (ST_A20_AutoOff_t)
typedef struct {
    struct { bool enabled; uint32_t minutes; } timer;
    struct { bool enabled; char time[6]; } offTime;
    struct { bool enabled; float temp; } offTemp;
} ST_A20_AutoOff_t;
```

· PRESET/FIXED 세션은 AutoOff 설정 불가능
· PIR은 프로파일 내부 motion.pir.enabled 별도
· Comfort 자동은 전역 s_autoComfortEnabled 하나뿐

3.2 신규 ST_A20_TriggerRule_t (모든 모드 공통)

```cpp
typedef struct {
    // ① 시간 트리거
    bool     timerEnabled;      uint32_t timerMinutes;
    bool     offTimeEnabled;    char     offTime[6];
    
    // ② 환경 트리거 (기존 + 확장)
    bool     offTempEnabled;     float    offTemp;
    bool     tempDeltaEnabled;   float    tempDeltaC;      // NEW: 온도 변화량 (°C)
    uint16_t tempDeltaWindowMin;                           // NEW: 변화 감지 윈도우 (분)
    bool     humidityEnabled;    uint8_t  humidityMin;     // NEW: 습도 하한
    uint8_t  humidityMax;                                  // NEW: 습도 상한
    bool     diEnabled;          uint8_t  diMin;           // NEW: 불쾌지수 하한
    uint8_t  diMax;                                        // NEW: 불쾌지수 상한
    
    // ③ 재실 트리거
    bool     pirEnabled;        uint16_t pirHoldSec;
    
    // ④ 스마트 쾌적 (자동 개입)
    bool     smartComfortEnabled;
    uint16_t smartComfortIntervalMin;   // 평가 주기 (기본 5분)
} ST_A20_TriggerRule_t;
```

3.3 규칙 적용 매트릭스 — "모든 모드에서 설정 가능"

작동 모드 규칙 저장 위치 PIR Timer OffTime OffTemp TempDelta 습도 DI Comfort
PRESET 세션 (수동) overrideState.rule (세션 내) ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅
FIXED 세션 (수동) overrideState.rule ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅
PLAYLIST (프로파일) profile.rule (확장) ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅
SCHEDULE schedule.rule (신규) ✅ ✅ ✅ ✅ ✅ ✅ ✅ ✅
Comfort 자동 전역 s_autoComfortConfig (불가) ✅ ✅ ✅ ✅ ✅ ✅ -

핵심: 프로파일/스케줄/세션 모두 동일 스키마 rule: { ... } 사용

3.4 스케줄 규칙 병합 우선순위 (profile 상속 vs 자체 규칙)

```
[기존] Schedule → profileId → profile.autoOff 상속
[신규] Schedule.rule (자체 정의) > profile.rule (상속) > 전역 default
```

스케줄 편집 모달에서:

· "프로파일 규칙 사용" (체크박스 ON, 기본) → profile.rule 상속
· "직접 설정" (체크박스 OFF) → schedule.rule 우선

요청하신 4차원 트리거 관점으로 현재 구현을 대조하고, **Gap → 보완 설계 → 영향 범위** 순서로 정리했습니다.

## Part 1. 사용자 정의 요약표

### ① 시작 Trigger (4종)

| # | Trigger | 사용자 표현 | 신규/기존 |
|:---:|---|---|:---:|
| T1 | Manual 일반모드 | "프리셋 눌러서 시작" | 기존 (MANUAL) |
| T2 | Schedule 요일/시작시간 | "예약된 시간에 자동 시작" | 기존 (SCHEDULE) |
| T3 | Manual 완전 Auto (스마트쾌적) | "AI가 알아서 켜줘" | **신규** |
| T4 | Manual 선택 Auto | "이 프로파일로, 풍량은 알아서" | **신규** |

### ② 운전 Mode (5종)

| # | Mode | 정의 | 신규/기존 |
|:---:|---|---|:---:|
| M1 | 고정 속도 | 일반 선풍기 (PWM %) | 기존 (FIXED) |
| M2 | 플레이리스트 | 사용자 Step 시퀀스 (파라미터 고정) | 기존 (PLAYLIST) |
| M3 | 프리셋 | WindDict 프리셋+스타일 (파라미터 고정) | 기존 (PRESET) |
| M4 | 완전 Auto | 시스템이 프리셋+스타일+강도 모두 결정 | **신규** |
| M5 | 선택 Auto | 사용자가 base 선택, 강도/스타일 자동 | **신규** |

### ③ 운전 중 중단/재실행 Trigger (3종)

| # | Trigger | 조건 | 재개 조건 |
|:---:|---|---|---|
| P1 | PIR | 사람 없음 (`holdSec` 경과) | 재실 감지 |

| # | Trigger | 성격 |
|:---:|---|---|
| S1 | 사용자 중단 | 즉시 완전 종료 |

| S3 | Schedule 종료 | 시간 윈도우 벗어나면 종료 |

## Part 2. 현재 구현 대비 Gap 분석

### 2.1 시작 Trigger Gap

| 항목 | 현재 (`EN_CT10_trigger_t`) | Gap |
|---|---|:---:|
| MANUAL | 1 | ✅ |
| SCHEDULE | 2 | ✅ |
| AUTO_COMFORT | 3 (스위치만, 5분 후 자동) | ⚠️ **T3 사용자 즉시 시작 불가** |
| MANUAL_AUTO_FULL | — | 🔴 **T3 미지원** |
| MANUAL_AUTO_SELECT | — | 🔴 **T4 미지원** |

**핵심 문제**: 현재 `AUTO_COMFORT`는 `POST /comfort/auto`로 스위치만 켜면 **5분 후 자동 기동**만 가능. "지금 즉시 AI 모드로 시작"이 불가능.

### 2.2 운전 Mode Gap

| 항목 | 현재 (`EN_CT10_session_type_t`) | Gap |
|---|---|:---:|
| FIXED | 3 | ✅ |
| PLAYLIST | 1 | ✅ |
| PRESET | 2 | ✅ |
| AUTO_FULL | — | 🔴 **M4 미지원** |
| AUTO_SELECT | — | 🔴 **M5 미지원** |

**핵심 문제**:
- `_session.type`이 3종뿐 → AUTO 계열 표현 불가
- `_session.payload`에도 auto 계열 필드 없음

### 2.3 중단/재실행 Gap

| 항목 | 현재 | Gap |
|---|---|:---:|
| PIR (P1) | ✅ MOTION_BLOCKED + 자동 재개 | ✅ |
| 온도 히스테리시스 (P2) | ❌ OffTemp = **완전 종료**만 | 🔴 **재개 경로 없음** |
| 불쾌지수 히스테리시스 (P3) | ❌ 미지원 | 🔴 **미지원** |

**핵심 문제**:
- `checkAutoOff()`는 `true` 반환 시 **`onAutoOffTriggered()` → `AUTOOFF_STOPPED` (래치)**
- **일시정지 vs 종료가 구분되지 않음** → 온도 낮아지면 무조건 종료 후 ACK 필요
- 히스테리시스 (재개 임계) 없음 → 경계값 flapping 위험

### 2.4 종료 Trigger Gap

| 항목 | 현재 | Gap |
|---|---|:---:|
| 사용자 (S1) | ✅ `stopSession()` | ✅ |
| Timer (S2) | ✅ Timer / RuntimeAutoOff | ✅ |
| Schedule 종료 (S3) | ✅ `findActiveScheduleIndex()==-1` | ✅ |

**판정**: 종료 트리거는 **이미 완전 지원**. 재검토 불필요.

**`MOTION_BLOCKED`는 `ENV_PAUSED`로 일반화 권장** (또는 하위 호환 유지):
- `runCtx.pauseReason` 필드 추가로 어떤 pause인지 구분
- `MOTION_BLOCKED`는 `ENV_PAUSED + pauseReason=MOTION`의 alias

### 3.4 상태 전이 상세

#### 3.4.1 Pause 전이 (P1/P2/P3)

```
[RUNNING 상태] ──pause 조건 만족──► [ENV_PAUSED]
                 (PIR 없음 / tempC < stopBelowC / DI < stopBelowDI)
                 
[ENV_PAUSED] ──resume 조건 만족──► [이전 RUNNING 상태]
              (PIR 감지 / tempC ≥ resumeAboveC / DI ≥ resumeAboveDI)
```

**히스테리시스 강제** (flapping 방지):
- `resumeAboveC = stopBelowC + 0.5°C` (최소)
- `resumeAboveDI = stopBelowDI + 3` (최소)
- 스키마 검증에서 위반 시 리젝트

#### 3.4.2 Stop 전이 (S1/S2/S3 + 기존 OffTemp)

```
[RUNNING] ──stop 조건──► [AUTOOFF_STOPPED]
                          (runCtx.reason = 개별 코드)
                          _autoOffLatched = true
                          
[AUTOOFF_STOPPED] ──ACK (사용자 명시)──► [IDLE]
                    (POST /control/ack 또는 새 세션 시작)
```

#### 3.4.3 우선순위 (결정 매트릭스)

| 우선순위 | 조건 | 결과 |
|:---:|---|---|
| 1 | `overrideState.active` (수동 개입) | OVERRIDE |
| 2 | `_autoOffLatched` | AUTOOFF_STOPPED |
| 3 | Pause 조건 만족 (P1/P2/P3) | ENV_PAUSED |
| 4 | profile mode + profile 선택 | PROFILE_RUN |
| 5 | 스케줄 활성 | SCHEDULE_RUN |
| 6 | (기본) | IDLE |

```cpp
    // ═══════ S3: OffTime (Stop) ═══════
    struct { bool enabled; char time[6]; } offTime;
    
    // ═══════ Stop: 온도 (감기 방지) ═══════
    struct { bool enabled; float belowC; } tempLowStop;
    
    // ═══════ Stop: 온도 (과열 방지) ═══════
    struct { bool enabled; float aboveC; } tempHighStop;
    
    // ═══════ Stop: 온도 변화량 ═══════
    struct { bool enabled; float deltaC; uint16_t windowMin; } tempDeltaStop;
    
    // ═══════ Stop: 습도 범위 이탈 ═══════
    struct { bool enabled; uint8_t min; uint8_t max; } humidityStop;
    
    // ═══════ Pause: 온도 (자동 재개) ═══════
    struct {
        bool  enabled;
        float stopBelowC;
        float resumeAboveC;   // 히스테리시스 강제
    } tempPause;
    
    // ═══════ Pause: 불쾌지수 (자동 재개) ═══════
    struct {
        bool  enabled;
        float stopBelowDI;
        float resumeAboveDI;  // 히스테리시스 강제
    } diPause;
    
    // ═══════ Pause: PIR (자동 재개) ═══════
    struct { bool enabled; uint16_t holdSec; } pirPause;
    
    // ═══════ 스마트 쾌적 (M4/M5용) ═══════
    struct {
        bool     enabled;
        uint16_t intervalMin;   // 기본 5
        uint8_t  level;         // 0=off, 1=warn-only, 2=full
    } smartComfort;
} ST_A20_TriggerRule_t;
```

### 3.7 AUTO_FULL (M4) 상세 동작

```
[세션 시작: MANUAL_AUTO_FULL]
  │
  ├─ 초기 상태: 사용자 아무것도 선택 안 함
  │  → 5분 주기 DI/온도 평가
  │  → 추천 프리셋+스타일 자동 세팅
  │  → PRESET과 동일하게 재생
  │
  ├─ 실행 중 지속 모니터링 (5분 주기)
  │  → 환경 변화 감지 시 프리셋 자동 전환 (부드러운 crossfade)
  │
  ├─ 사용자가 프리셋 수동 선택 시
  │  → AUTO_FULL 자동 해제, MANUAL_PRESET으로 전환 (사용자 의도 우선)
  │
  └─ Pause/Stop은 공통 규칙 (P1/P2/P3/S1/S2/S3) 적용
```

### 3.8 AUTO_SELECT (M5) 상세 동작

```
[세션 시작: MANUAL_AUTO_SELECT + payload {baseType, baseValue}]
  │
  ├─ PRESET base인 경우: presetCode 고정, styleCode+intensity 자동
  │  → DI/온도에 따라 styleCode 선택 (SLEEP/BALANCE/ACTIVE)
  │  → 강도 = Preset.factors × SmartFactor(DI)
  │
  ├─ PLAYLIST base인 경우: 각 step의 styleCode+intensity 자동 오버라이드
  │  → step.presetCode 유지, styleCode만 DI 기반 재선택
  │
  ├─ 5분 주기 재평가
  │  → style/intensity 부드럽게 조정 (급격한 변화 방지)
  │
  └─ Pause/Stop은 공통 규칙 (P1/P2/P3/S1/S2/S3) 적용
```

### 6.1 기존 데이터 하위 호환

**`cfg_userProfile_0203.json` (기존)**:
```json
{
  "autoOff": {
    "timer": { "enabled": true, "minutes": 240 },
    "offTime": { "enabled": true, "time": "05:00" },
    "offTemp": { "enabled": true, "temp": 26.0 }
  }
}
```

**자동 마이그레이션 규칙**:
| 기존 | 신규 |
|---|---|
| `autoOff.timer` | `rule.timer` (그대로) |
| `autoOff.offTime` | `rule.offTime` (그대로) |
| `autoOff.offTemp.temp` | `rule.tempLowStop.belowC` (Stop 성격 유지) |
| (없음) | `rule.tempPause` = disabled (신규 기능 opt-in) |
| (없음) | `rule.diPause` = disabled |
| `motion.pir.enabled` | `rule.pirPause.enabled` (그대로) |

**C++ 로더 로직**:
```cpp
// 마이그레이션: autoOff 필드가 있고 rule이 없으면 자동 변환
if (js["autoOff"].is<JsonObjectConst>() && !js["rule"].is<JsonObjectConst>()) {
    // 기존 autoOff → rule.timer/offTime/tempLowStop으로 매핑
    // 기존 motion.pir → rule.pirPause로 매핑
}
```

**JSON 파일 버전 필드**: `version: "0203"` → `"0204"` (마이그레이션 감지)

### 6.2 API 하위 호환

| 기존 API | 신규 동작 |
|---|---|
| `POST /session/start {type:PRESET, payload}` | `trigger=MANUAL` 유지, 동작 동일 |
